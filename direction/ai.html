Codex CLI 0.171.0：默认打开 TUI workspace，目录加入 GPT-6.2 Sol / Astra，并支持远程 exec

OpenAI 在 GitHub 发布了 Codex CLI 0.171.0（标签 rust-v0.171.0，发布时间 2026-11-20T00:44:47Z）。新功能包括：把 GPT-6.2 Sol 与 Astra 加入模型目录，并以 Sol 作为目录的默认选项；默认启用 TUI workspace，可在主对话旁提供可搜索的文档预览、图片预览和子代理 transcripts；为非 Vim 的提示编辑器增加可配置的撤销/重做快捷键，并可恢复附件和大段粘贴；新增 `codex exec --remote`，可在已有的 app server 上启动或恢复非交互会话；TUI 中新增 `/rc` 与 `/remote`，用于管理本机远程控制并显示设备配对码；在启用 `tui_extensions_statusline` 时，可通过 `/statusline` 选择或编写自定义 MCP 状态行。修复方面，发布说明列出：切换或恢复会话时保留草稿、排队的后续输入和被打断的输入及其原线程；更换工作目录时保留权限配置；避免迟到的完成事件取消较新一轮的审批；在引导进行中的回合时保留聚合 diff 中的先前提交编辑；修复滚动插入杂字符、输入光标跳动，以及用过期终端尺寸重绘；并修复企业 MCP 登录在身份提供方只签发不含 refresh token 的 ID token 时失败的问题。发布说明还提到将源码构建与发布工具链更新到 Rust 1.99.1。完整变更见 rust-v0.170.0...rust-v0.171.0。上述行为以发布说明为准，本机未安装或验证该版本。升级后 TUI workspace 会变为默认布局，而不只是给曾经手动开启的人使用。

    Hugging Face：为特定 agent 框架训练 LoRA harness adapter，提升准确率并减少工具调用

    Lewis Tunstall 于 2026-11-20 在 Hugging Face 博客发布《Introducing harness adapters: adapt your favorite model to your harness to improve performance and cost》。文章的核心做法是：冻结基座模型，在目标 agent 框架（harness）内部用强化学习训练定制 LoRA，使模型适应该框架及其任务分布。作者为 Qwen3.8-27B 分别给 pi、Hermes Agent 和 OpenCode 训练了一个 adapter，训练与 rollout 在 Hugging Face Jobs 上用 TRL 的 `AsyncGRPOTrainer`、OpenEnv 和 Harbor 完成；最终镜像里的框架版本写明为 Pi 1.5.2、OpenCode 2.2.7、Hermes Agent v0.22.6。文首示例称，Qwen3.8-27B 在 pi 框架下的 Terminal-Bench 2.1 分数为 39%、平均每任务约 2.9K token，加上 adapter 后为 55% pass@1、平均约 1.5K token，作者将其主要归因于更少推理、更少工具调用和更高的一次成功率。后文还报告：三个专用 adapter 在各自框架下、两个基准上都超过基座模型。在 SWE-bench Pro（hard 51）上，pi 从 39.2% 升到 64.7%（+25.5 分：新解 15 题、丢失 2 题，p=0.002），Hermes 从 29.4% 升到 43.1%。在两边都能解出的任务上，adapter 在 SWE-bench Pro 上少 56%–72% 的工具调用，在 Terminal-Bench 2.1 上少 53%–70%。三个 LoRA 还被合并成一个可在 pi、Hermes Agent 与 OpenCode 下不变运行的 super-adapter。作者同时做了交叉和域外检查：例如把 pi 的 adapter 放到 OpenCode / Hermes 下评估，以及在 AutomationBench 自带 agent loop（不是这三套框架）上跑 300 个任务，结果显示 adapter 与基座接近，差异被作者视为噪声范围内。adapter、GGUF、RL 任务和 safeagents 插件可通过文中的 Hugging Face collection 浏览。上述分数与效率数字均为文章报告的实验结果，本机未复现训练或评测。

    External sandboxes for coding agents：把代码执行放到智能体之外的沙箱

    Simon Willison 于 2026-11-17 发布的链接博文介绍了他与 Prime Radiant（文中称为 Superpowers 等项目背后的 AI 研究实验室）合作的外部沙箱模式：智能体本身运行在沙箱外，需要执行的代码则送到专用沙箱里运行，以便更安全地试用本地模型，降低误操作或提示注入对宿主机造成破坏的风险。文中列出三个提供相同 localhost API 的沙箱服务实现：external-sandbox-v86（Node.js 服务，用 v86 在 WebAssembly 中跑 Alpine Linux）、external-sandbox-container（Python Web 服务，在 Apple Containers 实例里的 Alpine Linux 中运行沙箱）、external-sandbox-quicksand（同样是 Python Web 服务，使用 Microsoft 的 Quicksand 库，该库把 QEMU 与 Alpine Linux 打进 Python 包）。文章称可以把 Pi、Claude Code 或 Codex 配置成在需要执行代码时向该沙箱发 API。沙箱还提供可选的 HTTP/HTTPS 允许名单代理，以控制智能体代码可以访问的主机，以及凭据替换机制，以便在不把密钥交给智能体的情况下发起需认证的 API 调用，并可用界面在沙箱仍运行时改代理配置。更完整的介绍指向 Prime Radiant 博客上的同题文章。本机未部署或测试这些沙箱服务。

Hugging Face 的 Tarek Ziadé 于 2026-11-18 发文，介绍如何在 Transformers 中只把 MoE 路由选中的专家从 SSD 读入有界缓存，并让缓存对现有 `grouped_mm` 看起来像普通专家库，从而不必为每种模型重写专家矩阵核。实现以 `from_pretrained` 的 `experts_offload` 选项提交为 huggingface/transformers#50717；作者写明该 API 仍在与维护者讨论，量化专家以后也可能改走另一项分层量化方案。针对 Qwen3.8-Flash-Next，文中给出的做法是：专家量化到 3 bit（磁盘约 49 GB，设备上缓存 12 GiB），稠密层用 8 bit（约 5.4 GB），另外约 51 GB 的 n-gram 嵌入表留在磁盘按需读行。作者称加载后约占 18 GiB，6K prompt 峰值 25.4 GiB，在 32 GB 的 Mac 上接近上限。在同一台 M5、相同提示、关闭 thinking / MTP / 推测草稿的设置下，作者报告优化后短解码 13.9 tok/s（Strata 0.1.60 为 14.8，约差 6%），4K prefill 228 tok/s（Strata 220），6K 文档后解码 12.4 tok/s（Strata 13.7）。作者同时写明这个速度对自己使用的编码 agent 仍然太慢，并提醒关闭浏览器等前台占用，否则 macOS 会开始换页。转换脚本与基准细节放在 Space tarekziade/moe-expert-streaming。上述速度、显存与对比数字均为作者自测，本机未转换权重，也未在 Mac 或 GPU 上复现。

Claude Code 于 2026-11-12 发布 2.1.323（发布页时间戳 2026-11-12T22:12:13Z）。主要新功能是实验性、需主动开启的 Code Mode：Claude 编写 JavaScript 来调用其工具；发布说明指向 https://code.claude.com/docs/en/code-mode 了解如何为个人或组织打开或关闭，本次抓取该文档地址返回 404，具体开关步骤以日后可打开的文档为准。插件方面，plugin.json 新增 engines["claude-code"]：超出所声明版本范围的插件不会被安装、更新或加载，安装与更新会挑选符合范围的最新版本。claude plugin validate 增加对插件 TypeScript hooks 模块的类型检查（发现项默认为警告，加 --strict 会失败），并校验 mod 的 engine.create hook 增删改的 $ 名词。此外：受管设置支持 CLAUDE_CODE_AUTO_MODE_MODEL，用于第三方供应商上的 Claude Desktop 会话（需 Desktop 含此版本后生效）；模型需要用量积分但积分关闭或用尽时出现选项菜单（停止、改用用量积分、升级）；claude -p 与 SDK 会话中 hooks 耗时较长时每 30 秒发一次进度心跳，以免宿主把回合判为挂起；Artifact 工具的资源上传支持 .docx。还修了再次 /compact 或在 /context 等命令后误压缩尚未回复的消息、恢复会话把新消息拼到旧的中断消息、大文件编辑后下一轮提示内存尖峰、会话中保存设置覆盖刚改的 settings.json、Edit/Bash 在某些 /proc 或设备文件上内存耗尽、worktree 退出后目录已删导致路径错误等问题。本机未升级到 2.1.323，也未打开 Code Mode。
