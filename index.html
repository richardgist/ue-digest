论坛：UE 5.8.4 编辑器冷启动第 4 帧，Nanite VSM 剔除与异步 Lumen Screen Probe Gather 竞态并 GPU hang（RTX 4070）

作者 @MK28101996 报告：在 UE 5.8.4、D3D12、桌面 Deferred（Lumen、Nanite、VSM、TSR；已装 DLSS 插件但用 -slnodlssg 未加载帧生成）上，用冷启动打开一张 World Partition 地图时，大约每 5 次有 1 次会在第 4 个渲染帧出现 DXGI_ERROR_DEVICE_HUNG。对照硬件为 RTX 4070 12 GB（驱动 621.24，2026-11-07），CPU 为 Ryzen 7 5700X3D，Windows 11 26H2。地图含一块大 Landscape、约 520 个 Actor、Nanite 静态网格（远处网格跨度约 85 km），以及天空大气和体积云。Graphics 队列面包屑停在 Frame 4 的 RenderVirtualShadowMaps(Nanite) → Nanite::DrawGeometry → MainPass → InstanceCulling → NodeAndClusterCull；同一时刻异步计算队列正跑 LumenScreenProbeGather → UpdateWorldRadianceCaches。Nsight Aftermath 写到 MMU fault，发生在 compute shader，故障地址看起来像被符号扩展的 32 位索引。当天稍后把驱动升到 621.40（2026-11-24 发布）后，作者仍带着变通启动，编辑器能干净打开，但还没有在 621.40 上去掉变通再试冷启动。发帖时没有 Epic 答复。这与 11 月 25 日已收录的 NodeAndClusterCull hang 是同一类故障、不同报告：本次明确发生在编辑器冷启动的第 4 帧，异步侧指向 Screen Probe Gather，而不是关卡加载后的前几帧。

值得试的点

  • 若 5.8.4 编辑器冷启动打开 World Partition 地图时，在第 4 帧出现 DXGI_ERROR_DEVICE_HUNG，且面包屑停在 Nanite VSM 的 NodeAndClusterCull、异步队列同时在 LumenScreenProbeGather / UpdateWorldRadianceCaches，可按原文在首次启动就加 -dpcvars=r.Lumen.DiffuseIndirect.AsyncCompute=0，确保第一帧前就关闭 Lumen 漫反射异步计算，再对照 hang 是否消失。作者在改用该参数后连续两次冷启动都干净，但自己也写明次数太少、还不能单独当作充分证明
  • 原文还提到，另有公开报告称 r.RDG.AsyncCompute=0 也能挡住这类 hang。这是启动前关闭异步计算的变通，不是官方合入的修复；5.8.4 仍被列为受影响。不要把它和 11 月 25 日那条“关卡加载后前几帧、先关再开回 AsyncCompute”的报告当成同一帖，但排查时可一并对照

AnyCam4D：用基于光线的光栅化，在原始镜头上训练原生 4D 高斯并支持任意相机模型（论文）

Sascha Kirch 等人的论文 AnyCam4D 于 2026-11-25 挂上 arXiv。作者指出，真实相机不是针孔模型，但多数动态高斯溅射仍按针孔假设处理，先去畸变会损失视场或细节，广角和鱼眼尤其明显；静态高斯溅射已多用基于光线的渲染适应任意相机，但原生 4D 高斯无法直接套用，因为难以从协方差可靠恢复朝向与尺度。AnyCam4D 用基于光线的光栅化，在未经去畸变的原始镜头上训练原生 4D 高斯；作者称这能保留视场和分辨率，每步开销约与标准投影相当。关键做法是对 4D 协方差的平方根做条件化，以数值稳定地得到朝向与尺度。训练后的模型可通过其他相机渲染，并支持滚动快门、景深或色差。作者报告：在合成 170° 鱼眼上，用原始图像训练可使 PSNR 提高 3.0–8.1 dB；在真实镜头上，感知误差低于为各相机改写的标准投影，PSNR 相当，且不必做相机专用推导；当合成相机相对拍摄机位旋转 60–80° 时，相对真值领先 6.2 dB。项目页为 https://sascha-kirch.github.io/anycam4d/ 。以上数字均为作者评测，本机未复核。

Unity 6000.6.11f1：Hierarchy 增加每帧更新时间预算，默认 0.5 ms，大场景下把刷新摊到多帧

Unity 于 2026-11-26 发布 6000.6.11f1（changeset 34837772f4f8）。新功能是编辑器偏好设置 Update Time Budget，用来限制 Hierarchy 窗口每帧用于更新的时间，默认 0.5 ms。改进方面，大场景中 Hierarchy 的更新会摊到多帧完成，而不再在单帧里一次性阻塞（UUM-153593）；图形上，异步上传缓冲区损坏时渲染线程不再冻结，发行版也会记录错误（UUM-150567）。另外，Profiler 的 “App Committed Memory” 计数器在 Android 上改为返回常驻内存与交换内存之和。发行说明还列出多处修复，以及若干已知问题（例如 Android 启动过程中切到后台可能 ANR、高回报率鼠标移动时 Windows 编辑器 Play Mode 帧率明显下降等）。以上摘自官方发行说明，本机未安装该版本验证。

论坛：约 1 平方公里密铺开放世界的 World Partition / HLOD 实装：小物件 PLA 进细网格，大体量先做 2K 代理再参与 HLOD 构建

作者 @XilenceX 分享了开放世界 RPG Asterfel 的 World Partition 与 HLOD 配置，目的是减轻因 World Partition 引起的卡顿和低帧率。地图约 1 平方公里、内容密铺。作者自称这套配置的表现大约是“原版 UE5 默认设置”的两倍，但只是把“几乎不能玩”提升到“勉强能接受”，还不够流畅；发帖是为了征求改进意见，发帖时还没有回复。文字里的做法是：小物件一律打进 Packed Level Actor（PLA），并在高级设置里把这些 PLA 的 Runtime Grid 设为 SmallPropsGrid；大体量物件也放进 PLA，但在构建 HLOD 之前先跑 Python 脚本，把它们变成带 2K 贴图的简单代理网格，再用这些代理去生成建筑外立面、山体等的 HLOD。作者还附了 World Settings、HLOD Layer 和关卡里 PLA 的截图。从截图可以读到：Runtime Hash Class 为 WorldPartitionRuntimeHashSet；主网格 MainGrid 的 Cell Size=10000、Loading Range=20000、原点为 -6400，并勾选 Is 2D，Bounds Method 为 Use Min Content Cell Bounds；其下有一个名为 PersistentLevel 的 HLOD 分区，Cell Size=20000、Loading Range=40000，包含图层 HLOD_Ref_Map_HLODO_Instancing；另一条运行时网格 SmallPropsGrid 的 Cell Size=5000、Loading Range=10000。HLOD 图层资产的 Layer Type 为 Instancing，Parent Layer 为 None，HLOD Actor Class 为 WorldPartitionHLOD，Instance Filtering Type 为 No Filtering。这些数字来自作者截图，不是官方推荐值，也没有独立基准测试支撑“快一倍”的说法。

Qwen Code v0.28.6：托管会话可在等待审批时挂起并在 Harness 崩溃后冷恢复，Send 改为把运行中的 shell 放到后台

QwenLM 于 2026-11-26 发布 Qwen Code v0.28.6。亮点包括：托管会话在等待工具审批、提问或后台任务时可以挂起，Harness 崩溃后可通过冷恢复继续；无头会话和 Ink TUI 默认改走 event-bus kernel，被取消的运行会在 10 秒内结束；新增 general.displayLanguage 设置（off、zh-CN、en），可在 Ink、OpenTUI 和 Web Shell 显示翻译后的回复与思考，原文仍会保存；Send 不再打断正在运行的 shell 命令，而是把它移到后台继续跑，并把命令 id、输出位置和状态交给模型；Web Shell 用幂等键提交提示，对瞬时失败静默重试两次，并用消息级重发提示代替阻塞横幅。破坏性变更是移除了 MessageRewriteMiddleware（原先会额外调用一次模型改写 ACP 回复），回复和思考的改写改为走 Ink、OpenTUI 和 Web Shell 里基于 hook 的路径。该页 Changelog 对比范围是 v0.28.4...v0.28.6。以上摘自官方 Release notes，本机未安装该版本验证。

论坛：UE 5.8 在 r.RayTracing.Nanite.Mode=1 下，关卡加载中途创建本地分屏玩家会在 Nanite::FRayTracingManager::AddVisiblePrimitive 断言崩溃

作者 @SHR3DH3AD 报告：在 UE 5.8、Windows 上开启硬件光线追踪，并把 r.RayTracing.Nanite.Mode 设为 1 后，若关卡中有 Nanite 静态网格，从独立菜单关卡 Open Level 进入该关卡，并在 GameMode 的 BeginPlay 里调用 Create Local Player（Controller Id 1）以便在关卡仍在加载时启用本地双人分屏，编辑器或游戏会在加载过程中或刚加载完时，于后台工作线程触发断言崩溃。断言是 Assertion failed: !AllocationFlags[Index]，文件为 Engine/Source/Runtime/Core/Public/Containers/SparseArray.h 第 100 行。调用栈顶在 Nanite::FRayTracingManager::AddVisiblePrimitive（NaniteRayTracing.cpp:1273），再往下是 RayTracing::GatherRelevantStaticPrimitives，由 UE::Tasks 在工作线程上执行。作者写明：如果等关卡加载完成后再创建第二个本地玩家，崩溃会少得多。预期结果是分屏正常加载并渲染；发帖时还没有 Epic 答复。帖子归类为 Rendering（Graphics / Niagara）错误报告。
