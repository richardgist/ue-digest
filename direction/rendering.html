论坛：Nanite 没有按距离切换材质 LOD——Epic 建议用 HLOD、Disallow Nanite 与可编程距离

提问方沿用传统 Static Mesh 的做法，希望 Nanite 也能按距离换成更简单的材质（近处多层细节法线、远处烘焙贴图），以降低显存和着色成本，并询问 UE 5.8 是否已支持；他们的场景有大量不复用的独特道具。Epic 的 Tim Stullich 答复：目前没有计划支持按距离切换的材质 LOD。Nanite 通常靠 shade binning 降低材质求值成本；引擎虽有 Nanite Override Materials，但不一定覆盖这种「近复杂、远烘焙」需求。对方追问后他补充：团队讨论过给 Nanite 加材质 LOD，主要顾虑是材质变体和 shading bin 数量会变得难管理；目前正在减少变体，已把需求提给开发组评估。8 月 26 日他改口得更明确：按距离做材质 LOD 与 Nanite 的演进方向相反，短期内不太可能加入，因为额外材质 LOD 会制造更多 shading bin，而这正是 Nanite 的主要瓶颈之一。可落地的替代是：若要在 HLOD 上做材质 LOD 链，给网格勾选 Disallow Nanite，运行时退回 Fallback，才能沿用传统材质 LOD；另外可调 WPO Disable Distance 与 Pixel Programmable Disable Distance，让远距实例退回更便宜的光栅——他称这往往比材质 LOD 更影响 Nanite 性能。对于独特道具过多，他建议先复用和实例化。Nanite Material Cache 仍是实验特性、变动频繁，他不建议按项目周期贸然启用。提问方认为 HLOD 不够用，因为 ISM/HISM 只能共用同一套材质。

    论坛：Nanite Voxelize 下加大阴影 LOD Bias 反而更贵——Epic 解释原因并给出 VSM 杠杆

    提问方在 5.7.2 用 Landscape + PCG Nanite 植被 + 单盏方向光测 VSM：Shape Preservation 设为 Voxelize，并关掉 VSM 缓存测最坏情况，阴影深度大约 5.8 ms。他们增大 r.Shadow.NaniteLODBias 后阴影成本不降反升，直到 bias 超过 4 才开始下降；同一场景改用 Preserve Area 或 None 时，加大 bias 则会按预期降成本。Epic 的 Ola.Olsson2 认为这并不意外：体素路径被高度优化成一种 LOD 技术，放大时仍走三角形；无偏差时遇到的是亚像素体素，采样很便宜。体素变大后会变成盒子，需要另一套算法（类似大三角形走硬件光栅），而体素没有这条路径，因此加大 bias 很难省钱。他们内部测试里，bias=0 时实际光栅会下降，但 cluster culling 等上升，所以通常把 bias 留在 1 更划算，也有利于仍走三角形的部分。其他可试的杠杆：若几乎没有大气效果，关掉 r.Shadow.Virtual.MarkCoarsePagesDirectional 往往收益明显（他称这仍是 VSM 的弱点）；确认 r.Shadow.Virtual.UseReceiverMaskDirectional 在 5.7 默认开启；测「无缓存」时应用 r.Shadow.Virtual.Cache.ForceInvalidateDirectional，他并不完全确定只设 r.Shadow.Virtual.Cache=0 效果相同（尤其 HZB）。对 5.7 的体素+VSM，他建议密林优先让缓存生效；5.8 则有实验性 r.Shadow.Virtual.PrefilteredDistant，可把远景几何画得更低分辨率，对动态太阳下的密林帮助很大，但这条路径完全不走缓存，当时仍高度实验。

  2. 图形渲染UE 日报 · 11-0903

    论坛：Nanite 体素化树木能进 Instancing HLOD，但着色可视化无效、换类型会构建失败

    提问方在默认开放世界地图上用 Megatree 做实验：用一组 PCG Volume 在地形上生成树木，树木是 Instanced Skeletal Mesh，走全局植被 Actor 做动画，并启用 Nanite voxelization。目标是借助 World Partition，让远距树木变成 HLOD。给 PCG Volume 指定 HLOD Layer 并构建后，「Show HLOD colorization」里远景地形会变蓝，树木却仍是原色。卸载整张地图后仍能选中各片森林的 HLOD，说明代理确实生成了；但卸载后飞近树木又会开始动画，看起来像已被加载。约 12.5 万实例在其 5080 上也不划算，且加上 HLOD 后没有看到性能收益。提问方随后自行复查（无 Epic 跟帖）：当时 HLOD 层类型是 Instancing，系统只是按格子把 PCG 实例合成更大块，代理是生效的——改了树种却不重建 HLOD 再进游戏，远景仍是旧树。因此他认为 HLOD 着色可视化对 Nanite 体素资产不起作用。把层类型改成 Instancing 以外的任何方式都会构建失败，体素化植被似乎只能走 Instancing HLOD。HLOD 虽然减少了 Nanite primitive 数量，但收益不明显，用更大的 PCG Volume 也能得到类似结果；更复杂的场景里，给植被加 HLOD 或许才更有意义。这是提问方的自查结论，不是 Epic 官方确认，可与「Nanite Foliage 如何进入 Instancing HLOD」那条互相参照。

    Epic 文档：Runtime Virtual Texturing——写入/采样、流送低 mip 与每帧上传预算

    UE 5.8 官方说明如何用 Runtime Virtual Texture（RVT）在运行时由 GPU 按需生成纹素，并把大范围着色结果缓存下来，适合带贴花感材质和样条的地形着色。流程是：在内容浏览器创建 RVT 资产，向关卡放入 Runtime Virtual Texture Volume，让材质写入并采样该资产，再把图元或 Landscape 指派给它。每个 Volume 只绑定一份 RVT 资产；场景组件可以写入多份。材质须使用 Virtual Texture 域或 RVT 相关表达式。资产可选多种 Material Type，并对应不同压缩：仅 Base Color（BC1），Base Color/Normal/Roughness/Specular（BC3+BC3），YCoCg Base Color、Normal、Specular（BC3+BC5+BC1）以及带 Mask、World Height（R16_UNORM）、Displacement（BC4）、Mask4（BC3）等变体。文档建议做法线时写入世界空间，以便多个图元混合。Volume 应用 Transform from Bounds / Set Bounds 套住地形或相关组件，并以 Volume 负 Z 方向做正交投影。写入与采样靠 Runtime Virtual Texture Output / Sample / Sample Parameter；也可用 Runtime Virtual Texture Replace、Virtual Texture Feature Switch，以及 View Property 里的 Virtual Texture Output Level / Derivative / Max Level，按 mip 近似做与相机无关的「距离」着色。适合写入的是 Landscape、Landscape Spline、静态网格、ISM 和做贴花散射的植被实例；骨骼网格、可移动或动画网格不合适，因为 RVT 是着色缓存，不会每帧完整更新，写入对象应为 Static。Draw in Main Pass 可选 Never、From Virtual Texture 或 Always：只写入 RVT 的贴花平面在无虚拟纹理支持时应选 Never；地形则应 Always，以便同时写入并采样。仅写入 RVT 的图元应手动关掉碰撞。图元可调 Virtual Texture LOD Bias、Skip Mips、Min Coverage；Landscape 的 Virtual Texture Num LODs 为 0 时每个组件以单四边形写入，对 GPU 最省，需要高频顶点插值时再提高。Volume 还可设置 Streaming Levels 并 Build，生成 Virtual Texture Builder，把低 mip 交给 Streaming Virtual Texture；编辑器默认仍看运行时 RVT，勾选 Use Streaming Low Mips in Editor 才预览流送数据，Build Debug 会给流送 mip 染色。RVT 设置改动后若未重建，关联 SVT 会失效并在 Map Check 中报警。调试可用 stat virtualtexturing、stat virtualtexturememory，以及 r.VT.Flush、r.VT.MaxUploadsPerFrame（编辑器默认 64、游戏默认 8）、r.VT.RVT.TileCountBias、r.VT.PoolSizeScale 等。限制包括：顶点着色器采样没有 GPU feedback；填充 RVT 的材质不能再采样虚拟纹理；普通流送纹理写入 RVT 可能在未完全流入时留下问题；ISM 即使勾了 Use GPU Lod Selection，RVT 也不走 CPU/GPU 实例剔除与 LOD 选择。

论坛：UE 5.8 移动端 Deferred 开启 Extended GBuffer 后 Subsurface Profile 的 SSS 消失（UE-385656）

提问方在 UE 5.8 发现：项目设置 Engine → Rendering → Mobile 里打开 Extended GBuffer 后，Mobile Deferred Shading 上的 Subsurface Profile 次表面散射会完全消失；关掉该选项后 SSS 立即恢复。移动端复现环境是 Android Vulkan Deferred；用作对照的 Windows 桌面 SM6 预览不受影响。最小复现是：新建 5.8 项目并设 Mobile Shading = Deferred，启用 Extended GBuffer，做一个 Shading Model 为 Subsurface Profile、Opacity=1、指定 Subsurface Profile 资产的材质，赋给带方向光和天空光的球体，再在 Android Vulkan 的 Mobile Preview 里观察。预期是无论 Extended GBuffer 开关，SSS 都应正确；实际开启后表面像 Default Lit 一样平、不透，stat gpu 里能看到 SubsurfaceScattering 通道登记在 Graphics Queue，但没有 Avg/Max/Min 耗时（未被执行），viewmode ShadingModel 下材质全黑，说明 ShadingModelID 没有写入 GBuffer。关掉 Extended GBuffer 后 SSS 与桌面一致，且 SSAO、SSR、TAA 在关闭该选项时仍正常，因此问题被隔离到 5.8 移动端 Deferred 在 Extended GBuffer 布局下没有正确读写 Subsurface Profile 的 GBuffer 数据。提问方确认与 Substrate（开关都复现）、TSR（只用 TAA）以及 r.AllowStaticLighting（已为 False）无关，平台栏同时标了 Android 和 iOS。2026-08-04 Bug-Reporter 登记为 UE-385656 并已分派。

AbacusGS: Gaussian Splatting without Per-Splat Sorting

网页/移动端常见的 3DGS 查看器往往用硬件光栅化画 splat，并在 CPU 上按深度排序，排序会占掉大部分帧时间。AbacusGS 把混合顺序写进场景布局：用八叉树把 splat 分成每盒最多 128 个（文中平均约 31 个），写盘时沿由训练相机得到的轴排序；每帧只对可见盒排序，并用一次点积决定正向或反向读取。它保留 3DGS 的 over 混合算子，用短暂的顺序感知微调转换已有模型，而不必改合成公式。作者在 13 个标准场景上报告：相对同等步数微调的 3DGS，平均损失约 0.13 dB PSNR（微调前两级顺序的平均损失约 1.27 dB）；在用 CPU 排序的 OpenGL 查看器上，帧时间约为逐 splat 排序的 1/4.5。文中还给出约 17 字节/splat 的紧凑格式和采用同一顺序的 CUDA tile renderer，并称代码将开源。以上数字均为论文实验（计时在 RTX 6000 Ada 等平台），本机未复现。

Unreal Fest Tokyo 2026：不改引擎做出动画风角色——《モンギル：STAR DIVE》材质与描边做法

Netmarble Monster 的 Ahn Wonchul 在东京讲《モンギル：STAR DIVE》动画风角色：他在正式上线前不到半年加入，资产已大量完成，因此不改引擎、不改 G-Buffer，只在现有自定义着色器上用材质补表现。头发保留各向异性高光，补上天空光颜色，并用法线与虚拟光源点积做不依赖真实灯光的伪照明，同时合并多余的遮罩/贴图采样。眼睛用相机空间驱动高光位置，瞳孔用 BumpOffset 做出凹陷。眉毛用 CameraOffset 写入 World Position Offset 前移，再叠加半透明第二层眉，避免前发遮住表情或整缕头发变半透明。贴图预算紧时，用 DDX/DDY 从一张单通道图案生成简易法线，并按 RGB 拆出三种法线、A 做遮罩，只用于边界清晰的花纹。描边走后处理拉普拉斯：用 Custom Depth 检轮廓并画在内侧（与 dither 更合）；角色内部描边则把本来没参与着色的 Roughness 写成分件 ID，再对 SceneTexture 的粗糙度做滤波。移动端受处理成本限制，且无法使用来自 G-Buffer 的 Scene Texture，因此只保留物体外周描边。玻璃不用半透明，改用 Scene Capture 立方体贴图模拟透射。演讲还试了 UE 5.8 的 Substrate Toon BSDF，称好上手，但用 Facial SDF 控脸部阴影时找不到 Shadow Attenuation 调节项。

Epic 文档：Landscape 启用 Nanite——双份流送、Skirt 补缝与构建时机

UE 5.8 官方说明如何给 Landscape 开 Nanite：在 Landscape 详情里勾选 Enable Nanite，再用 Build Data / Rebuild Data 或 Build → Build Landscape 生成网格。文档强调编辑器里未重建完成的非 Nanite 地形性能不能代表运行时；视觉上源数据相同，终端用户不应期待外观看起来更好或更差。技术上 Nanite Landscape 是叠在原有 Landscape 数据流送之上的——运行时仍需要非 Nanite 数据给 Runtime Virtual Texture、水体等使用，因此会同时流送两套数据并占用相应内存。HLOD 与 Landscape Proxy 流送行为和未开 Nanite 时相同。Proxy 边界因 Nanite 减面后顶点不对齐，远距可能出现细缝（通常靠 TAA 遮住）；可开 Nanite Skirt，在边缘加一圈顶点并按 Nanite Skirt Depth 下压，让相邻 Proxy 互相交错来堵缝。地形材质写位移即可走 Nanite Tessellation，但数据过期时编辑器里该 Proxy 看不到细分效果（烹饪时仍会构建），过期数据还会拖长 cook。推荐编辑时保持 Landscape.Nanite.LiveRebuildOnModification=0（Experimental，默认 0），以免大幅掉编辑器性能；可用 Landscape.RenderNanite 与 Landscape.Nanite.MultithreadedBuild 辅助。

论坛：Nanite Foliage 怎样进 World Partition HLOD（Epic：默认 Instancing，Mobility 常被打成 Movable）

日文帖询问 Nanite Foliage 是否应纳入 World Partition HLOD。Epic 的 Takashi.Suzuki 答复：Nanite Foliage 一般作为 InstancedSkinnedMeshComponent 放置；在 Instanced 类型的 HLOD 层里会默认被收集并以 Instancing 方式进入 HLOD。若层是 Merge / Simplified，则只有该组件的 HLODBatchingPolicy 为 Instancing 时才会被收集，从而可以手动排除较小的 Nanite Foliage。提问方随后发现 IsHLODRelevant 因 Mobility=Movable 把组件全部排除：详情面板看不到 Mobility，而构造函数链会把父类的 Movable 默认值留下来。Epic 解释该组件主要为 PCG 放置设计、不预期在蓝图里直接改 Mobility；属性并未消失，可在 UCLASS 元数据加 ShowCategory=(Mobility)，或在 ConstructionScript 里 SetMobility。若使用 Instancing 的 HLODType，还需要正确设置 HLOD Batching Policy。

UE 5.8：Landscape 与 World Partition 流送——格子不能混用，改完要重编 HLOD / Nanite / RVT

面向 UE 5.8 的 Landscape × World Partition 操作清单：地形拓扑由 Landscape 负责，单元格驻留和 Streaming Source 由 World Partition 负责，二者不要混为一谈。导入分块高度图前先定拓扑与源瓦片约定，并记录 World Partition Grid Size、Region Size、Flip Y Axis 以及 XY/Z 缩放；导入后核对所有 Landscape Streaming Proxy、组件边界、编辑归属和源码管理文件。Streaming Source / Loading Range 应按最大移动速度和目标设备就绪时间来设。文档特别提醒：不要默认 Landscape 组件、Landscape Streaming Proxy、World Partition 单元格、HLOD 单元格、PCG 网格和导航瓦片是同一套尺寸，每一种都要单独写出大小。地形大改之后，应重建相关 HLOD/远景内容，并重做导航、PCG、植被、RVT 流送低 mip 以及 Nanite 数据。接缝验收覆盖高度/法线、Target Layer 权重、材质与 RVT、Spline/水体形变、碰撞、NavMesh、PCG/草/植被密度，以及 Nanite Proxy 是否过期和 Skirt 行为。运行时标准包括：最快穿越也碰不到缺失地形碰撞、视野里没有卸载空洞或不可接受的 LOD 跳变、来回穿越内存不无限涨、Data Layer 切换不留下地形依赖内容不一致。

GPUOpen（厂商）称：与 Xbox 合作，把 AMD FSR Upscaling 4.1.2 随 2026 年十月 Microsoft GDK 带到 Xbox Series X|S，称这是主机端首次可用的 ML 版 FSR Upscaling；已用分析型 FidelityFX Super Resolution 的开发者可升级。Series X|S 提供 Full INT8 与更小、更便宜的 Lite INT8 两套模型（均可在 X/S 上跑），可用 GDK sample 运行时切换对比画质与开销；文称两模型 upscaler 显存相同（取决于渲染/显示分辨率而非模型），取舍是性能而非内存。集成复用与 PC 相同的 FSR SDK API（已注册开发者从 GDK 取签名二进制），输入仍为 jittered color / depth / motion vectors，质量档与 PC 一致（Native AA–Ultra Performance）。ROG Xbox Ally 系列为 Windows 设备，走标准 FSR SDK 2.4（含 Ryzen AI Z2 Extreme / Z2 A）。玩家侧需各游戏自行集成后才可用。

Unreal Fest Tokyo 2026：MegaLights 时代如何用大量 RectLight 做演出光

木村洋一在 Unreal Fest Tokyo 2026 从灯光艺术家视角谈 MegaLights：正式版后成本大致与灯数量解耦，关键收益是每盏灯都能走正确的 Ray Traced 面积光。街景作例：仅 Directional+Sky 约 13.12ms；加 160 盏 RectLight 并切 RT 约 35.59ms；开 MegaLights 回落到约 16.16ms。建议默认常开，用大面积、柔和的非必然 RectLight（约 2m 级）补远景与人物，比抬 ColorGrading/SkyLight 更保对比；可用贴图 RectLight 代替高风险 Emissive，并与 VolumetricFog 组合。技术细节指向 Epic Japan 的 Scalability / MegaLights 入门幻灯片。

World Partition HLOD 实操：建 Layer、选类型、生成与建筑可视化检查

面向大场景/建筑可视化的 WP×HLOD 步骤文：创建 HLOD Layer（Instancing / Merged Mesh / Simplified Mesh），配置 Always Loaded、Cell Size、Loading Range 与合并/简化参数；Actor 须挂到 Layer 且 Mobility=Static，再 Build > Build HLODs 或 WorldPartitionHLODsBuilder。提醒 masked/opacity 的 alpha 不会进合并贴图；Simplified Mesh 的 Merge Distance 可能糊掉门窗洞口；过大采样间隔会抬内存。建议先对代表性环境组生成，用视口 LOD 颜色与交付相机距验收，勿默认 HLOD 一定降 draw call。

论坛：Nanite Landscape 组件数、Tessellation 与 VisBuffer 空 bin 开销（Epic 答复）

Epic 确认：每个 Landscape component 因独立 weightmap 对应独立材质实例，从而占独立 shading/raster bin；开 Tessellation 后无法走 fixed-function bin，空 ExecuteIndirect 会拖 VisBuffer（低端更明显）。默认世界删到 1 个 section 时 NaniteStats 常见约 42 bins（含 TwoPass）；可试 r.Nanite.Culling.TwoPass 0 便于读数，Tessellation 可试 r.Nanite.DicingRate 3–4。一个 Nanite Landscape component 最多挂 64 mesh sections；更大 component 减少 MIC/bin，但图层更杂、材质更贵。Fortnite 示例约 4 components/proxy、不走 Landscape HLOD。内存上 Nanite 与非 Nanite 两套数据并存；碰撞/导航/Lumen card/DF 仍走标准 Landscape。

Epic 文档：Mobile Rendering Features Reference——路径能力对照表

Epic 文档：Using Preview Platform——编辑器内模拟移动端渲染与 Scalability

Preview Platform 可在编辑器视口切换目标平台/图形 API，重编译材质以模拟该平台渲染器，并加载对应 Device Profile、默认 Scalability 组与平台 CVar，使视口更接近运行时观感；首次切换需等着色器编译，之后可在已编译级别间切换且不必重启编辑器。视口工具栏 Performance and Scalability → Preview Platform 可选 Android GLES 3.1、Android Vulkan、iOS Metal 等；激活后可单独调该平台 Scalability，Default 可恢复平台运行时默认。文档强调仅作预览，最终必须以真机验证。可配合 Project Settings 各平台 Material Quality 与 Update Preview Shaders。
