Unreal Fest Tokyo 2026：NTE 都市开放世界如何在 PC/移动端稳住（WP 预载、FastGeo、LSM 影）

Perfect World Games 的 Shi Jinwei / Zheng Shengwen 在 Unreal Fest Tokyo 2026 讲《NTE》都市开放世界的 PC+移动优化：传送前临时插入 Streaming Source 预载目的地，用状态机分「资源 / 世界 / 玩法」三阶段再交还控制；启用 Fast Geometry Streaming，把静态度几何在 WP 流送数据阶段转成轻量表示以降 Actor 开销，并把绘制与碰撞网格分离。Mass Entity↔Actor 切换按帧限流，Snapdragon 8 Elite Gen 5 上 300 NPC 对比：限流后帧时间 22.456→17.363ms（约 −22.7%），单帧 Actor 化 242→3，超 20ms 帧 70→3。移动端走 Deferred + Depth Prepass，Vulkan 子通道尽量把 GBuffer 留在 tile memory；Device Profile 分级并实测 Vulkan/GLES 例外（例：Pixel 6 因 backbuffer 格式退回 GLES）。阴影：全平台近景 CSM；PC 侧视锥投影收窄更新区，整图更新约 −90%、静止视角 GPU 影约 −20–30%；移动远景用自研 Layer Shadow Map（LSM）按瓦片跨帧更新，称远景影 hitch 降 90% 以上（换日时旧缓存失效可能暂无远景影）。

    论坛：Commandlet 生成 Approximate HLOD 部分组件 Static Mesh 为空（Epic 排查方向）

    提问方用 WorldPartitionBuilderCommandlet -Builder=WorldPartitionHLODsBuilder -SetupHLODs -BuildHLODs 批量生成时，最末 Approximate 层约 130/7k 个 HLOD Actor 出现父级与首个子 Static Mesh 组件未赋值（Instanced 层正常）；编辑器内对该 Actor 点 Build HLOD 则三组件均有网格。Mesh Approximation 调试输出显示近似网格本身已生成，问题更像嵌入式 SM 写回/赋值。Epic 的 Sebastien Lussier 建议先检查 commandlet 保存后的 HLOD Actor 包内是否真有网格：若包内缺失，优先查 SavePackage 路径警告/错误；编辑器内 Build 仍「看起来正常」往往因结果还在内存未落盘。他指出内部 SM 若引用了其他包的 private 对象会导致保存失败，正常应只引用同一 HLOD Actor 包内的 private 贴图与材质实例。

论坛：UE 5.8 iOS Mobile Deferred（Multi-pass）下 Thin Translucent 透射色失效

报告：UE 5.8 将 Mobile Shading Path 设为 Deferred（Multi-pass，5.8 默认）时，Thin Translucent + Translucent + Surface ForwardShading 材质在 iOS/Metal 真机包中完全不应用 Transmittance Color（背景无染色，等效透射为白/关闭），但表面自身高光/反射/基础光照仍正常；同项目编辑器 Mobile Preview（Deferred）与真机 Forward 路径、以及 UE 5.6 Mobile Deferred 均正常。已排除 Lighting Mode、半精度着色器与脏 DDC。提问者怀疑 Metal 上 Multi-pass Deferred 的 dual-source blending 透射输出未正确接线，并关联同版本 Mobile Deferred 上 Subsurface Profile 等着色模型回归讨论。对依赖彩色玻璃/薄透的移动项目，是真机验收清单上的高优先级陷阱。

面向大场景/建筑可视化的 WP×HLOD 步骤文：创建 HLOD Layer（Instancing / Merged Mesh / Simplified Mesh），配置 Always Loaded、Cell Size、Loading Range 与合并/简化参数；Actor 须挂到 Layer 且 Mobility=Static，再 Build > Build HLODs 或 WorldPartitionHLODsBuilder。提醒 masked/opacity 的 alpha 不会进合并贴图；Simplified Mesh 的 Merge Distance 可能糊掉门窗洞口；过大采样间隔会抬内存。建议先对代表性环境组生成，用视口 LOD 颜色与交付相机距验收，勿默认 HLOD 一定降 draw call。

论坛：Nanite Landscape 组件数、Tessellation 与 VisBuffer 空 bin 开销（Epic 答复）

Epic 确认：每个 Landscape component 因独立 weightmap 对应独立材质实例，从而占独立 shading/raster bin；开 Tessellation 后无法走 fixed-function bin，空 ExecuteIndirect 会拖 VisBuffer（低端更明显）。默认世界删到 1 个 section 时 NaniteStats 常见约 42 bins（含 TwoPass）；可试 r.Nanite.Culling.TwoPass 0 便于读数，Tessellation 可试 r.Nanite.DicingRate 3–4。一个 Nanite Landscape component 最多挂 64 mesh sections；更大 component 减少 MIC/bin，但图层更杂、材质更贵。Fortnite 示例约 4 components/proxy、不走 Landscape HLOD。内存上 Nanite 与非 Nanite 两套数据并存；碰撞/导航/Lumen card/DF 仍走标准 Landscape。
