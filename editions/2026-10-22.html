实测：UE5.8 行星场景 VRAM 从 12.5GB 压到 5.3GB，云层 15.5→3.5ms

作者在 3440×1440 / RTX 5070 Ti 上给出可复现测量：进程 VRAM 从 12,480MB 降到 5,256MB（未降纹理画质），地形 chunk 从 2,055→752、三角形 69.4M→25.4M。主要手段包括动态网格改为索引几何、修正低空地平线剔除、把 8K 天空立方体贴图压到可视分辨率、以及为 TSR/Nanite/体积雾/GI atlas/反射捕获池设预算。体积云从约 15.5ms 降到 3.5ms（更小天气图、时间重投影、减少云阴影射线采样）；草地场景 GPU 中位约 22.9→11–12ms，实例遮挡剔除单独贡献约 −5.16ms。文中强调成对 A/B、先读内存 dump 再猜，并提醒尚未在 8GB 卡上诚实测过。

    MegaLights 在 UE 5.8：固定采样的随机直接光，成本近似不随灯数线性涨

    基于 Epic 5.8 文档与发行说明的梳理：MegaLights 是随机直接光路径，对像素重要性采样固定数量光线再降噪，成本大致恒定；5.5 实验→5.7 Beta→5.8 正式（少噪、面向 60fps）。面向当代主机与可光追 PC，推荐硬件光追阴影，不支持移动端/Switch/前代主机与 Forward。只管直接光，间接与反射仍靠 Lumen；方向光默认可关、本地灯可逐灯排除。作者开发构建用 Lumen+VSM、未启用 MegaLights，行星主光走 VSM，小灯用实例材质数据代替真灯。

    官方文档：World Partition HLOD（层类型、构建命令与可视化）

    说明 WP 用 HLOD Layer 把远处未加载格子换成代理网格以减 Draw Call。层类型含 Instancing（最低 LOD 的 ISM，适合植被 impostor）、Merged Mesh、Simplified Mesh；可设 Cell Size、Loading Range、Always Loaded、Parent Layer。Actor 需 Static 且加入 HLOD Layer（Details / Data Layer 默认 / World Settings 默认）。构建走 Build > Build HLODs 或 WorldPartitionHLODsBuilder（-SetupHLODs / -BuildHLODs / -DeleteHLODs）；源未改则不重建。编辑器用 Hierarchical LOD Coloration（近绿远蓝），运行时可用 wp.Runtime.ToggleDrawRuntimeHash2D。Merged/Simplified 均可勾选 Generate Nanite Enabled Mesh。

    PerfGuard：Virtual Shadow Maps 调优——页缓存失效、SMRT 与移动端限制

    把 VSM 性能归结为页缓存：Cached Pages 视图绿=命中、红=每帧重算。常见失效源含 Movable 网格、方向光旋转、骨骼动画、材质 WPO、粒子阴影。建议优先降 r.Shadow.Virtual.SMRT.SamplesPerRayLocal/Directional（AMD 指南约 4–6）、按场景调 MaxPhysicalPages，并用 ShowStats 看池溢出。植被 WPO 是头号杀手：限制 MaxMaterialPositionInvalidationRange、ShadowCacheInvalidationBehavior=Static、WPO Disable Distance、尽量 Nanite 化。平台：需 D3D12/Vulkan；多数移动端非 Nanite VSM 关闭、走 CSM；Apple Metal 会强制关掉 Cache.StaticSeparate。

PerfGuard：Lumen 性能深潜——四分成本、Screen Probe 杠杆与何时关掉

用 stat gpu 把 Lumen 拆成 LumenSceneUpdate、DiffuseIndirectAndAO、Lumen Reflections、ShortRangeAO，强调反射与 GI 分开预算。高 ROI 项含 StochasticInterpolation=1、SpatialFilterNumPasses 3→1、IntegrateDownsampleFactor=2，以及反射侧 MaxRoughnessToTrace / DownsampleFactor。内容侧：关掉不可见网格的 Affect Distance Field Lighting、植被开双面 DF、审计 Movable 灯对 Surface Cache 的失效。明确列出可关场景（主机 60、俯视角、风格化、移动/低端）；完整关停需 DynamicGlobalIlluminationMethod=0 并设 r.Lumen.DiffuseIndirect.Allow 0，同时考虑关闭距离场生成以免空耗。

RLSplat：按高斯预算线性缩放推理成本的前馈 3DGS

论文提出 RLSplat：前馈 3D Gaussian Splatting 在给定高斯数量预算 B 时，不只压缩输出规模，还让推理延迟与峰值显存大致随 B 线性下降。做法是用策略优化学「把预算分到各局部锚点区域」的分配，再经资源线性解码器（层次近邻 + 局部交叉注意力）只生成这 B 个高斯，而不是先稠密预测再剪枝。零样本 ACID 评测写明：各预算下优于 EcoSplat / F⁴Splat；在较低预算时相对 F⁴Splat 约最高 4.1× 更快、约 9.6× 更低峰值显存，且质量更好。正文还称代码在 github.com/mlvlab/RLSplat；本人打开该仓库地址时返回 404，是否已公开未核实。

UE 5.8 渲染性能笔记：用 Medium GI 选 Lumen Lite，并独立压测 GI/反射

实操向 Lumen 选型：高画质 Lumen 给有余量的目标；UE 5.8 的 Lumen Lite 为 Beta，Medium GI（sg.GlobalIlluminationQuality 1）会走 Irradiance Field Final Gather（r.Lumen.FinalGatherMethod 0）换更快、更低质量的 GI。Medium 反射质量会关 Lumen Reflections、光滑面改 SSR，粗糙高光仍可来自 Lumen GI。强调从 BaseScalability/设备档起步，用 profilegpu 确认 Lumen pass 后再分别 A/B GI 与反射档，并注意 async compute 重叠会让单 pass 计时失真。
