Blender 5.3：原生 3D Gaussian Splats、视口 DLSS 4.5 降噪与可选项目系统

Blender Foundation 于 2026-11-10 发布 5.3.0 正式版（官网发布页与新闻稿均写 Initial release / November 10th, 2026）。相对本站 11-10 收录的 Cycles RC 说明，这是已出包的稳定版介绍，并补上 3DGS、EEVEE 与工作流改动。头牌是原生 3D Gaussian Splats：可从 PLY、SPZ 和 glTF 导入为点云，用 Geometry Nodes 处理，并在 Workbench、EEVEE 与 Cycles 中渲染；默认用自发光着色，文档称把 Emission 换成 Diffuse 等硬表面 BSDF 可做「初步」的可重打光，同时写明性能仍在优化，且因多数制作工具用 sRGB、Blender 用线性色彩，低透明度、高辐射区域可能出现不准。视口新增 DLSS 4.5 Ray Reconstruction 降噪器，通过超分并复用先前帧样本；位于渲染属性 Sampling 的 Denoise 面板，需要 NVIDIA 驱动 620 或更新；并写明对运行 Windows 11 的 NVIDIA RTX Spark 提供原生支持（含内存优化）。Cycles 方面 Principled BSDF 增加色散（对应 OpenPBR v1.1.1），Glass BSDF 与 Principled 透射分量支持粗糙度各向异性。EEVEE 新增 Material Lighting 节点（Light Accumulation / Light Info / Light Evaluation / Shadow Raycast 等），并支持全景相机；当前实现尚不支持景深、光线追踪，以及视口里体积的时间重投影。另外还有可选的项目系统（项目级资源库与色彩管理等）、把 Asset Library 作为扩展分享、合成器效果栈，以及视频序列编辑器的 ripple 编辑框架、重写的 Blade 工具和初步 OpenTimelineIO 支持。同期新闻稿还写 Vulkan 现为 Windows（ARM 除外）与 Linux 的默认后端，Workbench 可在 Metal 与 Vulkan 上使用硬件光线追踪阴影；本条链接是功能介绍页，该后端变化以新闻稿为准。本机未安装 5.3.0 验证。

    Epic 文档：Lumen World Cache——运行时路径追踪缓存，可替代网格 Cards 的 Surface Cache

    5.9 新文档介绍 Lumen World Cache：默认关闭，仅在 Lumen 走硬件光追时生效；开启后该视图完全替换 Surface Cache（不再捕获/照明/驻留 mesh cards）。缓存按距相机的稀疏世界空间格子存储（默认约 10 米处每格约 25.6 cm，并按主朝向分条目），每帧从屏幕每 8×8 像素块随机取一点、最多 3 次反弹填入，格子最多平均 16 帧，64 帧未命中则回收。开启方式是在 DefaultEngine.ini 写入 r.Lumen.WorldCache.Supported=1 并重启；还要求 Hardware Ray Tracing Mode 为 Full 或 Simplified Material（Inline 不可用），且 r.Lumen.WorldCache.Allowed 保持开启（默认真，可作分档开关而不重启）。文档列明限制：软件光追仍走 Surface Cache；半透明不入库；暂不支持 Water、光追半透明、植被/次表面透射，以及 Far Field。GPU 耗时可在 stat gpu 的 LumenWorldCache 项查看，默认可走 async compute。

Grit：在导出时把 GDScript 编译成原生 C++ 的实验性 Godot 模块

Grit 是面向 Godot 4.7 的引擎模块，在导出时把项目里的 GDScript（含嵌入场景/资源的内置脚本）编译成 C++，再编进自定义导出模板，使导出后的游戏以本地机器码而不是字节码运行；编辑器里的编写、运行和调试仍走原来的 GDScript VM，无法处理的函数会按函数静默回退到 VM。仓库 README 以 2026-11-09 的置顶说明回应近期关注：项目并未停掉，目前主要缺测试，作者表示若 Godot 4.8 发布会跟进兼容。许可证为 MIT。文档把项目标为「高度实验性」：需要打过补丁的 Godot 4.7.2 与自定义导出模板；已在 Linux x86_64（GCC/Clang）和 Windows x86_64（MSVC）上验证 Godot 自带 GDScript 测试套件全部 1540 个函数可编译、499 条断言在原生执行下通过，macOS、移动端和 Web 未经测试；并写明暂时不要用来出货，且应保留回退到常规 VM 的办法。作者在 AMD Ryzen 9 7950X3D、Linux、GCC 16、发行版导出模板上，用同一二进制对比 VM（GRIT_DISABLE=1）与 Grit：带类型的整数循环 sum_to 为 196.3 ms 对 4.0 ms（约 49.1 倍），Vector2 与数组的 particles 为 31.7 ms 对 7.5 ms（约 4.2 倍），字符串拼接与创建/销毁节点几乎没有收益（约 1.0–1.1 倍）；附带的 Flappy 测试在无头自动驾驶 12 万物理步时，文档写目前原生大约快 2.5 倍。这些是作者在其基准项目上的测量，本机未复现。可选的脚本剥离（strip_scripts）会去掉已编译函数的函数体，剥离后的游戏不能再回退到 VM，且必须与同一次导出编出的模板配对。

在 8 GB 笔记本上自测 UE 5.8 Lumen Lite 与 MegaLights 的 GPU 耗时

作者在 RTX 4070 Laptop 8 GB（驱动 610.62）上，用 UE 5.8.1 编辑器视口（约 2118×1271、TSR、DX12 SM6、硬件光追）搭建 16 m 房间、48 盏可投阴影点光，每条件记录约 400 帧、取三次中位数。同开 MegaLights 时，GI Epic（Lumen 高质量）9.18 ms、GI Medium（Lumen Lite）6.87 ms，约少 25%；GI Epic 下关闭 MegaLights 为 11.69 ms，开启约少 21%。该场景最快组合是 Lumen Lite + MegaLights（6.87 ms），与完全关闭 GI 的 6.91 ms 几乎相同；测完后整卡占用约 2727 MiB / 8188 MiB。文中说明 Lumen Lite 在 5.8 仍为 Beta，需把 Global Illumination 与 Reflections 同时设为 Medium；关闭 MegaLights 时出现 VSM one-pass projection 每像素灯数溢出警告，开启后警告消失。作者强调这是编辑器视口、单场景结果，打包或户外植被场景数字可能不同。

SplatAnything: Gaussian Spacing Normalization for Feed-forward 3DGS across Arbitrary Scenes

这篇 2026-11-05 提交的论文指出，现有前馈 3DGS 通常先由几何基础模型预测深度，再在径向距离归一化（RDNorm，用重建点到参考相机原点的平均径向距离做全局缩放）的坐标系里预测 Gaussian 属性；但相邻 Gaussian 中心间距（Gaussian spacing）仍会随场景尺度和相机配置大幅变化，使相近的局部观察对应不同的尺度监督目标。作者提出 SplatAnything 与 Gaussian Spacing Normalization（GSNorm）：在逐像素预测假设下，局部间距近似为深度除以焦距几何平均，即 d≈D/√(fx fy)，再用所有有效像素的中位数作为场景尺度，把几何、深度和相机平移一并缩放，使该中位数间距为 1。几何由冻结的 WorldMirror 2.0 估计，随后微调 Gaussian Backbone 并用从头训练的 GSHead 预测不透明度、旋转、尺度和球谐系数。为评估跨场景与外推视角，作者建了一套覆盖 ScanNet、NRGBD、DL3DV、Tanks & Temples、Mip-NeRF 360、ETH3D、DTU 的基准，控制输入 4/8/16/32/64 视并强调遮挡感知共视约 0.2–0.6 的外推目标。作者报告在多数设置下优于所列基线，例如无位姿时 ScanNet 上 DISTS/LPIPS 为 0.184/0.207（Mirror2-GS 为 0.193/0.222），DTU 上为 0.229/0.483（Mirror2-GS 为 0.347/0.617）；同一架构消融里 4 视 GSNorm 为 0.198/0.245，对照 RDNorm 的 0.223/0.278。训练为 2 万步、64 张 NVIDIA H20，输入 4–32 视、分辨率 504–1024。文中也写明：方法依赖几何先验，在极稀疏或几何不可靠输入上可能下降，且主要重建输入可见区域。项目页为 https://zju3dv.github.io/SplatAnything/ 。以上均为论文实验与作者结论，本机未复现。
