Unreal Fest Tokyo 2026：MegaLights 时代如何用大量 RectLight 做演出光

木村洋一在 Unreal Fest Tokyo 2026 从灯光艺术家视角谈 MegaLights：正式版后成本大致与灯数量解耦，关键收益是每盏灯都能走正确的 Ray Traced 面积光。街景作例：仅 Directional+Sky 约 13.12ms；加 160 盏 RectLight 并切 RT 约 35.59ms；开 MegaLights 回落到约 16.16ms。建议默认常开，用大面积、柔和的非必然 RectLight（约 2m 级）补远景与人物，比抬 ColorGrading/SkyLight 更保对比；可用贴图 RectLight 代替高风险 Emissive，并与 VolumetricFog 组合。技术细节指向 Epic Japan 的 Scalability / MegaLights 入门幻灯片。

    论坛：Nanite Landscape 组件数、Tessellation 与 VisBuffer 空 bin 开销（Epic 答复）

    Epic 确认：每个 Landscape component 因独立 weightmap 对应独立材质实例，从而占独立 shading/raster bin；开 Tessellation 后无法走 fixed-function bin，空 ExecuteIndirect 会拖 VisBuffer（低端更明显）。默认世界删到 1 个 section 时 NaniteStats 常见约 42 bins（含 TwoPass）；可试 r.Nanite.Culling.TwoPass 0 便于读数，Tessellation 可试 r.Nanite.DicingRate 3–4。一个 Nanite Landscape component 最多挂 64 mesh sections；更大 component 减少 MIC/bin，但图层更杂、材质更贵。Fortnite 示例约 4 components/proxy、不走 Landscape HLOD。内存上 Nanite 与非 Nanite 两套数据并存；碰撞/导航/Lumen card/DF 仍走标准 Landscape。

把「几何已加载」与「可进入」拆开：Nanite 用 StreamingPoolSize 在内存与 IO/解压之间权衡，过小即使静态视口也会 thrash，改前先看 Nanite Streaming Geometry 与 NaniteStats，并单独核验包体/存储。World Partition 格子加载只是一层，就绪门还应覆盖 collision/navigation、资产与 bundle、贴图/Nanite/VT 质量下限、渲染/物理组件注册、首帧可见 PSO、玩法初始化。预加载超前距离按最大接近速度 × 最差就绪延迟 + 余量估算；传送用临时目的地 streaming source，等 WP subsystem 完成后再过完整就绪门，避免为一条路径全局抬 loading range。

UE 5.8：Texture streaming——先诊断再动 PoolSize

把常见渲染症状收成「先证明什么 → 第一次有界实验」对照表：仅高分辨率慢→查像素缩放 GPU pass 并降 Screen Percentage；密林/城市场景慢→隔离图元/overdraw/VSM 失效；植被运动时阴影尖刺→查 VSM 未缓存页并禁远距 WPO/阴影；多灯仍快但噪→MegaLights 采样竞争，控半径或提采样做 A/B；反射占主导→单独对比反射档与 GI；半透明战斗特效拖垮 GPU→减单特效重叠/覆盖；Render Thread 慢而 GPU 有余量→实例化/剔除高提交类别；按地点涨显存→资源快照找新驻留所有者；低档位改了没变化→核对 device profile/组是否生效或需重启，并在打包构建验证；动态分辨率见底→在最低百分比下看主导 GPU pass 或是否实际 CPU 受限。每条要求恢复开关、用正式设置落地，并在同一最坏场景复测。

要求对承重 Actor 显式记录五项：空间生命周期、Data Layer 世界状态、Runtime Grid（通常 None 走默认）、远处表示（指定 HLOD Layer 或故意不加）、依赖类型（硬引用/软引用/子系统/稳定 ID）。解释 Is Spatially Loaded：开启则按流送源距离加载（仍受 Runtime Data Layer 约束）；关闭则不做距离流送，适合真正全局且便宜的 Actor，不能当「引用丢失」的万能药或给远处普通可交互物乱用。硬引用会使空间 Actor 进入同一流送依赖捆，跨远 cell 引用会提前拉驻留；优先用子系统解析、接口+查询、软资产引用、稳定 ID 注册表或消息，而不是为消警告乱改软引用。附校验：Reference Viewer/Size Map、流送生成警告、带 cell 可视化的遍历、反复卸载/重载保留玩法状态、以及服务器/客户端分测。

UE 5.8 World Partition Data Layers：Loaded/Activated、网络权威与流送代价

区分 Data Layer Asset 与世界内 Instance；Editor Data Layer 只管编辑视图，Runtime Data Layer 才参与运行时状态机。运行时三态：Unloaded（不驻留）、Loaded（驻留未激活，作预热）、Activated（驻留且可见/可用）。联网时服务器改权威 Runtime 状态，客户端只观察复制结果，不要让客户端独自激活会改变碰撞/交互/世界真相的层。适用：Boss 场地预热、季节/毁坏变体、按任务权威分相、共享地形上的交替布景；不适用：单个小物件可见性开关、每个任务布尔一层、大范围零散 Actor 多层、仅客户端藏权威 Actor、把持久任务真相存在层状态里。状态迁移建议：服务器尽早请求 Loaded 覆盖最坏加载延迟→需要碰撞/交互时再等就绪→在揭示边界 Activated→玩法真相另存以便读档重建。性能提醒：Actor 大范围分散或多 Runtime 层会碎片化流送依赖。调试命令含 wp.DumpDatalayers、SetDataLayerRuntimeState、ToggleDrawDataLayers 等。
