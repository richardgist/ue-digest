Claude Ship：可在 GitHub 上审 PR、修 CI，并按仓库策略决定是否批准（Team/Enterprise，部分功能为 beta）

Anthropic 于 2026-11-23 发文介绍 Claude Ship（文中写“即日起以 beta 提供”）。它由已正式可用的 Code Review，以及仍处 beta 的 PR Steward 与 Claude Approvals 组成，用于在 GitHub 上把 pull request 走过审阅、修复和批准决定。Code Review 可从多角度审查并发布发现，并提供 Quick / Standard / Deep 三档；PR Steward 处理失败的 CI、合并冲突以及来自 Code Review、其他工具或同事的反馈，但不设计为批准或合并 PR，每次推送后会说明改了什么以及如何撤销，也可用 @claude 指令或 @claude stop。Claude Approvals 读取仓库里的策略文件，在策略允许时自行批准常规改动，或要求更深的人工签署；官方建议多数客户先开 observe-only 模式，再把它纳入分支保护。开发者可在 Claude Code 里用新的 /ship 命令：推送并开 PR、审阅，并跟进反馈与失败检查；/ship 自当日起在 Claude Code 与桌面应用中逐步推出，最终能否合并仍取决于开发者权限和仓库分支规则。管理员可按仓库打开 Code Review 与 PR Steward，配置审阅级别、触发时机和花费上限。适用范围：Claude Team 与 Enterprise，且仓库在 GitHub 上。用量按 token 计费，可能增加组织成本；Claude Approvals 无基础费用，但策略中的分类器按 token 计费，且策略若使用 Claude 的审阅会触发一次计费的 Code Review（observe 模式也一样）。运行 /ship 计入常规 Claude Code 用量。Zero Data Retention、HIPAA 配置或客户管理加密密钥的组织不可用。文中还提到符合条件的 Enterprise 组织可在领取后 30 天内使用至少 10,000 美元 Claude Ship 积分，须在 2027-01-15 前领取，条款适用——这是厂商优惠。另称 Claude Code 团队在把 Claude 的审阅作为更广流程一层时，6 月至 9 月已合并 PR 数量增加一倍以上、被回退比例下降超过 40%；该数字为 Anthropic 自己的团队统计，本机未复核，也未实际使用 Claude Ship。

Lewis Tunstall 于 2026-11-20 在 Hugging Face 博客发布《Introducing harness adapters: adapt your favorite model to your harness to improve performance and cost》。文章的核心做法是：冻结基座模型，在目标 agent 框架（harness）内部用强化学习训练定制 LoRA，使模型适应该框架及其任务分布。作者为 Qwen3.8-27B 分别给 pi、Hermes Agent 和 OpenCode 训练了一个 adapter，训练与 rollout 在 Hugging Face Jobs 上用 TRL 的 `AsyncGRPOTrainer`、OpenEnv 和 Harbor 完成；最终镜像里的框架版本写明为 Pi 1.5.2、OpenCode 2.2.7、Hermes Agent v0.22.6。文首示例称，Qwen3.8-27B 在 pi 框架下的 Terminal-Bench 2.1 分数为 39%、平均每任务约 2.9K token，加上 adapter 后为 55% pass@1、平均约 1.5K token，作者将其主要归因于更少推理、更少工具调用和更高的一次成功率。后文还报告：三个专用 adapter 在各自框架下、两个基准上都超过基座模型。在 SWE-bench Pro（hard 51）上，pi 从 39.2% 升到 64.7%（+25.5 分：新解 15 题、丢失 2 题，p=0.002），Hermes 从 29.4% 升到 43.1%。在两边都能解出的任务上，adapter 在 SWE-bench Pro 上少 56%–72% 的工具调用，在 Terminal-Bench 2.1 上少 53%–70%。三个 LoRA 还被合并成一个可在 pi、Hermes Agent 与 OpenCode 下不变运行的 super-adapter。作者同时做了交叉和域外检查：例如把 pi 的 adapter 放到 OpenCode / Hermes 下评估，以及在 AutomationBench 自带 agent loop（不是这三套框架）上跑 300 个任务，结果显示 adapter 与基座接近，差异被作者视为噪声范围内。adapter、GGUF、RL 任务和 safeagents 插件可通过文中的 Hugging Face collection 浏览。上述分数与效率数字均为文章报告的实验结果，本机未复现训练或评测。

若你仍留在 0.27 稳定线而不是 1.0 Preview，这一版改了 Auto Mode 的授权行为，并补了飞书/企微通知和托管会话里的交互终端，升级前值得先看自己的自动授权习惯会不会被拦住。

值得试

按发行页安装或升级到 v0.27.4 后查看版本。若平时开着 Auto Mode，先确认风险操作会弹出显式授权，不要假定仍会自动放行。需要把会话结果同步到飞书或企微时，按说明配置 webhook。Managed Web Terminal 和本地目录授权仅适用于 Managed Agent 会话。上述功能本机未实测。
