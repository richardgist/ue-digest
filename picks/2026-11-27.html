AnyCam4D：用基于光线的光栅化，在原始镜头上训练原生 4D 高斯并支持任意相机模型（论文）

arXiv发布:2026-11-25
图形渲染前沿

Sascha Kirch 等人的论文 AnyCam4D 于 2026-11-25 挂上 arXiv。作者指出，真实相机不是针孔模型，但多数动态高斯溅射仍按针孔假设处理，先去畸变会损失视场或细节，广角和鱼眼尤其明显；静态高斯溅射已多用基于光线的渲染适应任意相机，但原生 4D 高斯无法直接套用，因为难以从协方差可靠恢复朝向与尺度。AnyCam4D 用基于光线的光栅化，在未经去畸变的原始镜头上训练原生 4D 高斯；作者称这能保留视场和分辨率，每步开销约与标准投影相当。关键做法是对 4D 协方差的平方根做条件化，以数值稳定地得到朝向与尺度。训练后的模型可通过其他相机渲染，并支持滚动快门、景深或色差。作者报告：在合成 170° 鱼眼上，用原始图像训练可使 PSNR 提高 3.0–8.1 dB；在真实镜头上，感知误差低于为各相机改写的标准投影，PSNR 相当，且不必做相机专用推导；当合成相机相对拍摄机位旋转 60–80° 时，相对真值领先 6.2 dB。项目页为 https://sascha-kirch.github.io/anycam4d/ 。以上数字均为作者评测，本机未复核。

为什么有用

若你在用动态 3DGS 处理广角、鱼眼或多相机机位，这篇把“先去畸变再按针孔投影”的损失写清楚了，并给出了直接在原始镜头上做 4D 高斯训练的做法。

值得试

阅读 https://arxiv.org/abs/2611.34223 ，需要代码或演示时再看项目页 https://sascha-kirch.github.io/anycam4d/ 。文中 PSNR 等数字是作者评测，换数据或相机模型不一定能得到同样增益。

Unity 6000.6.11f1：Hierarchy 增加每帧更新时间预算，默认 0.5 ms，大场景下把刷新摊到多帧

Unity发布:2026-11-26
游戏开发工具

Unity 于 2026-11-26 发布 6000.6.11f1（changeset 34837772f4f8）。新功能是编辑器偏好设置 Update Time Budget，用来限制 Hierarchy 窗口每帧用于更新的时间，默认 0.5 ms。改进方面，大场景中 Hierarchy 的更新会摊到多帧完成，而不再在单帧里一次性阻塞（UUM-153593）；图形上，异步上传缓冲区损坏时渲染线程不再冻结，发行版也会记录错误（UUM-150567）。另外，Profiler 的 “App Committed Memory” 计数器在 Android 上改为返回常驻内存与交换内存之和。发行说明还列出多处修复，以及若干已知问题（例如 Android 启动过程中切到后台可能 ANR、高回报率鼠标移动时 Windows 编辑器 Play Mode 帧率明显下降等）。以上摘自官方发行说明，本机未安装该版本验证。

为什么有用

若你的 Unity 大场景会把 Hierarchy 卡死，这次可以直接用每帧时间预算把刷新摊开，不必再等下一次功能版本。

值得试

在 Unity Hub 安装 6000.6.11f1 后，到编辑器偏好设置里查看 Update Time Budget（默认 0.5 ms）。先在工程副本上试；发行说明仍列出若干已知问题。本机未安装该版本。

Qwen Code v0.28.6：托管会话可在等待审批时挂起并在 Harness 崩溃后冷恢复，Send 改为把运行中的 shell 放到后台

GitHub (QwenLM/qwen-code)发布:2026-11-26
AI 工具工具

QwenLM 于 2026-11-26 发布 Qwen Code v0.28.6。亮点包括：托管会话在等待工具审批、提问或后台任务时可以挂起，Harness 崩溃后可通过冷恢复继续；无头会话和 Ink TUI 默认改走 event-bus kernel，被取消的运行会在 10 秒内结束；新增 general.displayLanguage 设置（off、zh-CN、en），可在 Ink、OpenTUI 和 Web Shell 显示翻译后的回复与思考，原文仍会保存；Send 不再打断正在运行的 shell 命令，而是把它移到后台继续跑，并把命令 id、输出位置和状态交给模型；Web Shell 用幂等键提交提示，对瞬时失败静默重试两次，并用消息级重发提示代替阻塞横幅。破坏性变更是移除了 MessageRewriteMiddleware（原先会额外调用一次模型改写 ACP 回复），回复和思考的改写改为走 Ink、OpenTUI 和 Web Shell 里基于 hook 的路径。该页 Changelog 对比范围是 v0.28.4...v0.28.6。以上摘自官方 Release notes，本机未安装该版本验证。

为什么有用

若你在用 Qwen Code 的托管会话或 Web Shell，这次减少了等审批或 Harness 重启时丢会话的情况，也可以在不中断长命令的前提下继续发下一条。

值得试

查看 https://github.com/QwenLM/qwen-code/releases/tag/v0.28.6 后升级到 v0.28.6。注意 MessageRewriteMiddleware 已移除，依赖旧改写路径的配置需要改到 hook。本机未安装该版本。

Hugging Face：用控制实验在一块 RTX PRO 6000 上把 Inkling 2 Mini 单用户解码从 136 提到 190.6 tok/s

Hugging Face Blog发布:2026-11-25
AI 工具效率

Niels Rogge 于 2026-11-25 在 Hugging Face 博客记录了一次推理调优：给编码智能体配上 inference-optimisation skill、hf CLI 和 Hugging Face Jobs，在一块 NVIDIA RTX PRO 6000 96 GB 上对 Inkling 2 Mini 做控制实验。协议是每次只改一个变量，并用“对照 → 候选 → 对照”括号，只有同时优于两次对照且不回退其他指标才保留。作者称，在 46 次有效基准中，单用户解码从 136 提到 190.6 tok/s（+40%），8 用户合计吞吐从约 570 提到 716 tok/s（+26%），使用 vLLM nightly 与 DSpark 推测解码；开启推测前后的 greedy 输出逐字节相同，长上下文针检索在至多 250K token 上 3/3 通过。速度提升主要来自改用 vLLM nightly，以及把 DSpark 设为 7 个 draft 并使用概率采样；作者还写明 --max-model-len 262144 和 --gpu-memory-utilization 0.85 是为了在 96 GB 上带着 drafter 启动。文中给出了完整的 vllm serve 命令，日志和脚本在 NielsRogge/inkling-2-mini-hillclimb。以上数字均为作者在该 GPU 与固定提示组上的测量，本机未复核。

为什么有用

这篇把“一次只改一个变量、用前后对照挡住噪声”写进了可复用的推理调优流程，也给出了在 96 GB 卡上跑 Inkling 2 Mini + DSpark 的具体启动参数。

值得试

阅读 https://huggingface.co/blog/inkling-2-mini-inference-hillclimb ，需要复现时再看仓库 NielsRogge/inkling-2-mini-hillclimb。文中速度是一块 RTX PRO 6000 上的作者测量，换卡、换镜像或换负载不一定能得到同样吞吐。

Gemini API：可在服务端按页、单元格或时间段切片文件，官方称只对实际检查的部分计 token

Google Blog发布:2026-11-23
AI 工具效率

Google DeepMind 于 2026-11-23 宣布，Gemini API 在 Google AI Studio 和 Gemini 平台上线原生文件切片，并可直接上传 Microsoft Office 与 OpenDocument 格式。开发者把 PDF、Office 文档、表格、音频和视频交给 API 后，可指定只要哪些页、工作表单元格、媒体片段或图层；官方称文件可通过 Files API 上传一次并在多轮和工具调用中复用 URI，且只为 Gemini 实际检查的部分计 token。切片适用于所有 Gemini 4 模型，已有的文件大小和页数限制仍然有效。文档和幻灯片可设 start_page / end_page、分辨率和 page_text 或 page_image 图层；表格可设 sheet_index、visible_cells 以及 data / formulas / visuals；视频和音频可设 start_offset / end_offset，视频还可调 fps 与分辨率。未指定处理选项时，文档和幻灯片默认用保留版式的页面图像，表格则包含所有标签页的计算值、公式和表名。文中示例是先以 page_text 廉价通读，再对同一 URI 的单页做高分辨率 page_image 细读。以上为厂商公告，本机未调用该 API 核实计费或切片行为。

为什么有用

若你的智能体要读长 PDF、表格或录像，不必先在本地用 LibreOffice 或 ffmpeg 切文件，也可以先低成本浏览再只对关键页花高分辨率 token。

值得试

阅读 https://blog.google/innovation-and-ai/technology/developers-tools/file-slicing-controls/ ，再按文中示例用 Files API 上传文件并设置 processing / page_options。官方称只对实际检查的部分计 token，具体账单以控制台为准；本机未调用该 API。
