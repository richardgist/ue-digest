官方：UE 5.9 Preview 2 已发布，移动端 Deferred 单 Pass 光照与 Web 移动档画质改进

Unreal Engine（X）发布:2026-11-19适用版本:UE 5.9 Preview 2
图形渲染渲染移动端

官方 @UnrealEngine 于 2026-11-19 22:07（香港时间）宣布 5.9 Preview 2 已推出：仅蓝图项目也可把 Web 作为目标平台，AI 辅助工作流默认开启，并指向同日更新的官方发布说明（页面标注 Last updated 11/19/26）。发布说明中此前未在日报展开的渲染/移动端改动包括：移动端 Deferred 可用 r.Mobile.DeferredLighting.SingleShadingModelPass 在单次光照 Pass 里照亮所有 lit shading model；新增默认关闭的 r.Mobile.DeferredLighting.CameraInsideLightDepthTest，在相机位于本地光源几何内部时对光源背面做深度测试；没有 build data 的 Mobile Reflection Capture 不再渲染成黑色。方向光 Virtual Shadow Maps 增加投影与页管理优化，以及 Stochastic PCSS（接触处更硬、远处更软），并修复阴影投影进行中把 r.ShadowQuality 降到 0 会崩溃的问题。Web 方面，移动档改用引擎默认抗锯齿 TAA（不再用 FXAA），Deferred 档启用 Extended GBuffer，使清漆、贴花法线与材质环境光遮蔽能完整呈现；手机/平板会优先加载更轻的 ASTC 纹理集，各设备只下载所运行档的着色器数据，默认把帧率限制在显示器刷新率以省电散热。Preview 2 还规定：项目未设置帧率上限时改用平台默认上限；未使用的遗留 Reflection Capture 不再随地图构建数据一起 cook/转存；Lyra 的 Web 移动档用纹理与天空光上限把流送控制在预算内。该 Preview 仍是预览构建，官方建议用项目副本测试。

值得试的点

  • 在 5.9 Preview 2 的项目副本上打开 r.Mobile.DeferredLighting.SingleShadingModelPass，对比多 shading model 场景的 Deferred 光照开销与外观
  • 若玩法上相机会进入本地光源体积，再试默认关闭的 r.Mobile.DeferredLighting.CameraInsideLightDepthTest
  • 移动端已构建失败、没有 build data 的 Reflection Capture 若发黑，在 Preview 2 上复测是否已不再渲染成黑色
  • Web 移动档对照 TAA（替代 FXAA）与 Deferred 档 Extended GBuffer（清漆 / 贴花法线 / 材质 AO）；真机确认是否先走 ASTC、只下载当前档着色器，并留意默认按刷新率限帧
  • 方向光 VSM 可对照 Stochastic PCSS 与投影/页管理优化；设置菜单会在运行中把 r.ShadowQuality 降到 0 的项目，也可验证阴影投影在途时的崩溃是否已修

论坛：UE 5.8 体积雾 tricubic 过滤把 h0.z 写错，Quality 2 会采到错误深度（含修复建议）

Epic 论坛发布:2026-11-17适用版本:UE 5.8
图形渲染渲染

作者 @Ruben_designer 报告：将 r.VolumetricFog.Filtering.Quality 设为 2（tricubic）时，HeightFogCommon.ush 的 SampleVolumetricFogFiltered() 会采到错误深度。B 样条准备段在 bicubic 与 tricubic 共用后以 h0.z = VolumeUV.z 结尾，这对只在 XY 过滤、Z 上按原始深度线性采样的 bicubic 是对的；但 tricubic 分支也会用 h0.z / h1.z 与 g0.z 做 lerp，等于在 Z 上把未过滤深度与 B 样条偏移后的 h1.z 混合，过滤是错的。复现步骤：加 Exponential Height Fog（体积雾）和带 volumetric scattering 的聚光灯，设 r.VolumetricFog.Jitter 0 让边缘静止，在锥体边缘对比 Quality 0、1、2。作者观察 Quality 2 看起来与三线性差不多甚至更差（聚光灯边缘的 froxel 台阶仍在），Quality 1 才能正确抹平。建议把 h0.z = VolumeUV.z; 移进 PERMUTATION_VOLUMETRIC_FOG_FILTERING_QUALITY == 1 分支，让 tricubic 保留计算出的 h0.z；并指向 GitHub PR #15392。原文标注影响 UE 5.8、Windows，发帖时没有 Epic 回复。

值得试的点

  • 有体积雾加聚光灯散射时，先设 r.VolumetricFog.Jitter 0，再对比 r.VolumetricFog.Filtering.Quality 0 / 1 / 2 在灯锥边缘的 froxel 台阶
  • 若 Quality 2 并不比 1 更平滑，不要把它当成更高质量档；原文观察它与三线性接近甚至更差
  • 源码工程可按帖中建议把 h0.z = VolumeUV.z; 移入 bicubic（Quality == 1）分支后再对比锥体边缘；原文提到 PR #15392，合入前先在自己工程验证

论坛：从 5.6 升到 5.8 后，Niagara 空纹理绑定会回退到根材质，且完成后再次激活不重建渲染状态

Epic 论坛发布:2026-11-18适用版本:UE 5.8（原文亦列 5.7 / 5.9）
图形渲染渲染

作者 @leopaul3 在项目从 UE 5.6 升到 5.8 后遇到两处 Niagara 渲染回归。其一：renderer 使用覆盖了父材质贴图的材质实例，同时把同一纹理参数的绑定设为 null 时，5.6 会回退到父材质实例上的贴图，5.7+ 因 CL 45127665 改为显式查找根材质的默认贴图；作者建议把查找从 MatDyn->GetMaterial() 改为 MatDyn->Parent，认为改动风险较低。其二：系统已经 Complete 后，在不 Reset 的情况下再次 Activate（例如只在尚未播放时激活），5.6 可以重新显示，5.8+ 因 CL 50513903 在执行状态仍为 Complete 时跳过创建渲染状态；而 UNiagaraComponent::ActivateInternal 会在 SystemInstanceController->Activate 之前调用 CreateRenderState_Concurrent，于是重建被跳过——Niagara Debugger 里能看到模拟在跑，但粒子不绘制。作者暂在 Activate 之后、若已不再是 Complete 且没有 SceneProxy 时补了 MarkRenderStateDirty，并询问这样改是否可取、该不该上游。原文给出最小复现步骤，平台为 Windows，发帖时没有 Epic 回复。

值得试的点

  • 升级后若 Niagara 粒子贴图不对，先检查 renderer 上该纹理参数绑定是否为 null：5.7+ 会回退到根材质默认贴图，而不再用父材质实例的覆盖
  • 若需要 5.6 的回退行为，可按原文把查找改为 MatDyn->Parent，并在自己工程验证副作用
  • 若系统 Complete 后再 Activate 且不 Reset，Debugger 显示在模拟但不绘制：按原文在 Activate 之后、状态已非 Complete 且没有 SceneProxy 时调用 MarkRenderStateDirty，先用“每 tick 激活一次”的最小例子确认，再考虑是否打补丁或等上游
