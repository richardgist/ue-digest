Cross3DGS：用同一套 Vulkan 训练器在工作站到手机上做 3DGS 训练（论文）

arXiv发布:2026-11-17
图形渲染前沿

Hiroyuki Sato 与 Yusuke Takimoto 的论文《Cross3DGS: Unified Vulkan-Based 3D Gaussian Splatting Training from Workstations to Mobile Devices》于 2026-11-17 提交 arXiv（2611.22240），摘要页注明已接收到 WACV 2027 Workshop on Eyes of the Future (EOF)。作者提出一套跨厂商、跨平台的 Vulkan 3DGS 训练器：优化器保持同一套，再按设备限制、工作负载和已观察到的驱动失败排除不能正确运行的执行调度，并按固定优先级在剩余可行调度中选择。作者称，同一核心在他们测量的全部配置上完成了标准质量训练（3 万次更新、一百万高斯），覆盖 NVIDIA、Intel、Arm、Qualcomm、AMD 与 Apple GPU，并包括 Android 设备与一部 iPhone；而现有可移植训练器 VkSplat、Brush 在部分移动 GPU 上无法运行。工作站上 11 个场景的平均结果（均为论文报告）：质量高于 VkSplat 且训练时间无显著差异，Brush 在相近质量下训练时间约为其三倍；作者还称各设备最终质量几乎相同。摘要写有一款移动应用可把手机拍摄在设备上做成可观看模型。以上对比与应用可用性均为论文表述，本机未训练、也未在应用商店核实；摘要页未见官方代码仓库链接。

为什么有用

如果你关心把 3DGS 训练从 CUDA 工作站挪到采集设备或随身手机/笔记本上，这篇把可移植性的难点放在执行调度而不是内核翻译，并给出覆盖手机 GPU 的实验设定；结论以作者实验为准，目前还不能直接下载官方实现。

值得试

阅读 https://arxiv.org/abs/2611.22240 的摘要与 PDF，重点看按设备选择执行调度的两步规则、与 VkSplat / Brush 的对比，以及第 6.5 节对端到端移动应用的描述。摘要页未见官方代码或项目主页。本机未训练或安装该应用。

ContextRenderer：用动态上下文视频生成做互动游戏世界的渲染（论文）

arXiv发布:2026-11-19
游戏开发前沿

Wang 等人的论文《ContextRenderer: Dynamic-Context Video Generation for Interactive Game Worlds》于 2026-11-19 提交 arXiv（2611.25838）。文章把可执行的世界演化与视觉生成分开：游戏引擎或智能体写出的程序维护状态并给出场景表征，再用视频模型把这些表征渲染成观测。作者提出自回归视频扩散框架 ContextRenderer，包含用于块级交互监督的 Dynamic-Context Learning（DCL）、在有限 token 预算内压缩视觉历史的 Recurrent History Compression（RHC），以及连接不同 proxy 表征的 Cross-Representation Flow Alignment（CRFA）。配套数据集 WorldPrism 来自智能体搭建的世界、3A 游戏实机与开源视频，并带有对应渲染和块级标注。作者报告在 GWM-Bench 与 Solar-Bench 上重建与视觉质量有改进，定性结果展示在提示和主体参考变化下可做分钟级互动渲染。项目页为 https://rainzor.github.io/contextrenderer/ 。基准提升与时长均为论文表述，本机未训练或生成。

为什么有用

若你在看“引擎管状态、生成模型当渲染器”的游戏世界模型路线，这篇把持续对局里条件更新与视觉连续性作为核心问题，并给出数据集与评测名称；结论以作者实验为准。

值得试

阅读 https://arxiv.org/abs/2611.25838 与项目页 https://rainzor.github.io/contextrenderer/ ，重点看 DCL / RHC / CRFA 的分工，以及 GWM-Bench、Solar-Bench 上的报告。项目页目前主要是论文介绍，本机未见可直接运行的官方代码说明，也未复现实验。

Inkling 2 Mini：可在笔记本上跑的开源权重循环 Transformer，约 20GB

Thinking Machines Lab发布:2026-11-20
AI 工具工具

Thinking Machines Lab 于 2026-11-20 发布 Inkling 2 Mini（官网博文；Hugging Face 模型卡同样标注 Date of release: November 20, 2026，许可证 Apache 2.0）。这是一个循环 Transformer：中间层对每个 token 跑三遍。官方写它是 Mixture-of-Experts，总参数 264 亿、激活 34 亿，计入循环后每个 token 的权重激活为 54 亿；权重以 NVFP4 为主、最后四层为 MXFP8，总内存占用约 20GB，官方称可在消费级笔记本和桌面 AI 机器上运行。权重开放，可在 Tinker 上做推理与定制；官方列出的开源推理包括 SGLang、vLLM、Ollama、Unsloth、NVIDIA Dynamo、TokenSpeed 和 Llama App，并提到 SkyRL、Miles、NVIDIA AutoModel 等可做强化学习微调。模型卡还写支持文本与图像输入、上下文最长 100 万 token，并建议 32GB 及以上内存的 Apple Silicon，或 32GB 及以上显存的其他 GPU。官方自称在总参数不到 1000 亿的开源权重模型中，DeepSWE v1.1 为 48.2%、Vals Index v2.2 为 46.5%，并领先同档模型——这是厂商评测，本机未复现。文中 MacBook 上离线写出飞行模拟器的演示属官方宣传，本机未运行该模型。

为什么有用

若你想在本地或笔记本上跑一个面向 agent 编程的开源权重模型，这是近几天新发布、体积约 20GB 的选项；先把官方基准当宣传数字，自己用任务验证。

值得试

权重在 https://huggingface.co/thinkingmachines/Inkling-2-Mini 。可按官网列出的 vLLM / SGLang / Ollama 等运行时加载；也可用 Tinker 做推理或微调。模型卡提醒：循环层会使每 token 计算高于激活参数看起来的规模，并建议给输出长度和 agent 轮次设上限、在沙箱里跑 agent 任务。本机未下载或评测。

TokenEconomizer：从仓库历史会话学习，给编码 agent 做黑盒降本的开源插件

Microsoft Research发布:2026-11-16
AI 工具效率

Microsoft Research 于 2026-11-16 发文介绍 TokenEconomizer（UC Berkeley、Microsoft Research 与 Microsoft Security 的开源插件；仓库 https://github.com/microsoft/TokenEconomizer ）。它不改 agent 或底层模型，而是从同一仓库已完成的会话里学习，用三种机制减少后续会话浪费：把反复出现的仓库事实写成 micro-skills、按历史裁掉很少用到的工具、并在失败循环时插入简短改路提示（仍卡住则提醒开发者，插件本身不会中止任务）。官方在 277 个 SWE-Bench 缺陷修复任务、五组 agent–模型组合上报告平均成本下降 18.4%–30.9%，且每个仓库都更便宜、成功率大体稳定；仓库 README 还写 Pass@1 在五组中的四组上升。文中称前期任务可能更贵，但到第六个任务时各仓库累计成本已低于默认；Web-Bench 上成本低 16.0%–21.2%，在每个任务都是新仓库的安全审计上低 6.4%–19.6%。官方写插件不需要额外 API key，学到的内容留在本机（~/.tokeneconomizer），并计入它自己的模型调用成本。目前支持 Claude Code、Codex、GitHub Copilot CLI 与 Pi，对 Cursor、Grok Build 等为实验性支持。以上节省数字均为作者评测，本机未复现。

为什么有用

如果你经常在同一个仓库里跑 Claude Code / Codex 等 agent，这提供一条不改模型、只从历史会话里剪浪费的做法；先把 18%–31% 的降本当论文结果，在自己的仓库里看几个会话再决定是否留下。

值得试

git clone https://github.com/microsoft/TokenEconomizer.git 后，按 plugin/README.md 安装。Claude Code 示例：claude plugin marketplace add /path/to/TokenEconomizer && claude plugin install tokeneconomizer@tokeneconomizer，新开会话后运行 /tokeneconomizer:status，并先做一次 /tokeneconomizer:toolprune refresh-catalog。需要 Python 3.10+。本机未安装该插件。
