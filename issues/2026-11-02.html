Generating a State Object Database for Advanced Shader Delivery（ASDTool）

Epic Games Documentation发布:约 2026-10-21（随 UE 5.8.4 / Microsoft ASD 公告同期文档）适用版本:UE 5.8（文档；工具随 5.8.4）
图形渲染渲染

Epic 官方说明如何用独立命令行 ASDTool 从已 cook 的 Windows D3D12/SM6 构建生成 SODB（.sodb），供商店预编译成按 GPU/驱动的 PSDB，以减轻首次启动着色器编译卡顿。范围仅限 PCD3D_SM6；不支持光追 PSO；需源码编译 ASDTool，并开启 bShareMaterialShaderCode。采集来源：-AllCompute 收齐 SM6 compute shader，-BundleDir 从已有 .upipelinecache 导入 graphics/compute PSO；二者可并用。文档强调 ASD 不替代 PSO precaching / bundled PSO cache，仍建议保留 precaching。提供 generatesodb / compilepsdbs / registerpsdbs 本地验证流程，以及 -ValidatePSOs 排查失败 PSO。

值得试的点

  • 源码构建 ASDTool 后，对 cook 输出跑 generatesodb（-AllCompute + -BundleDir），确认摘要里 graphics PSO 数量 > 0
  • 用 compilepsdbs -LocalAdapter + registerpsdbs 在本机复现商店侧流程，并用 D3D12CacheListener 等核对 PSDB 命中
  • 着色器有变更才重生成 SODB；同时保持 r.PSOPrecaching 与 bundled cache，覆盖 ASD 未命中的路径

UE 5.8 渲染性能参考页：先用 GPU 计时确认 BasePass / 半透明 / 后处理或材质相关 draw 是否显著，再用 Shader Complexity（Alt+8）定位高指令密度区域，怀疑小三角或反复覆盖时检查 Quad Overdraw 等视图，并隔离材质/图元/特效后同帧复测。文中明确 Shader Complexity 主要反映指令数，不可靠定价贴图带宽、发散循环、WPO 或平台调度。杠杆包括：先减全屏/大面积材质覆盖，再减半透明/Masked 层叠与粒子密度，必要时用 Opaque/Masked/抖动/网格替代，收敛 WPO、静态开关排列与材质槽数量——均以平台置换与可见最坏重叠的毫秒证据为准。

值得试的点

  • 同一相机下 ProfileGPU：记下半透明/BasePass 毫秒，再切 Shader Complexity 标出热点材质

  • 给带 WPO 的网格设禁用距离，避免远距无效变形继续吃可编程光栅/阴影失效

图形渲染渲染移动端

区分职责：scalability groups 管玩家可见画质族；device profiles 管平台/设备默认、特性支持、内存桶与覆盖。项目覆盖写在工程 Config，不要改引擎 Base 文件；以 BaseScalability.ini 与平台基线 device profile 为参考后再按测量覆盖。核心组含分辨率、视距、抗锯齿、阴影、GI、反射、后处理、贴图、特效、植被、着色等——一个 sg.* 可联动多枚 CVar。工作流：定义最低/推荐硬件与渲染器能力 → 设 Low/Medium/High/Epic 意图与玩法可读性底线 → 从引擎默认起在各目标设备测量 → 组不够预算时才覆盖子系统 → 标出需重启/重载的设置，并测存档、自动检测与不支持硬件回退。硬规则：低档不得拿掉敌人、危险、导航线索或竞技可见性，只缩放表现而非规则。

  • 改 sg.* 后用控制台核对实际生效 CVar，并在打包构建设备 profile 上复测
  • 需要重启才能切换的特性路径在设置 UI 上明确标注，防止玩家以为「没生效」
