提问方在 UE 5.4.4 下使用 Masked/TwoSidedFoliage、Lumen GI、Virtual Shadow Maps、Nanite，植物叶阴影快速闪烁。答复称这是常见组合问题，多半来自阴影缓存或 TSR 在细 Masked 卡片上的表现，建议先做三项单变量测试再换资产：(1) 复制材质把 Two Sided Foliage 改成 Default Lit，并提高 Opacity Mask Clip Value 约到 0.4–0.5；(2) 断开 WPO 验证；若因风场 WPO 导致 VSM 每帧失效，设 WPO Disable Distance，关掉平行光 Contact Shadow，并确认 r.Nanite.ProgrammableRaster.Shadows=1；(3) 临时关掉 TSR/改 FXAA 区分抗锯齿闪烁。Nanite 设置建议开 Preserve Area，避免叶卡片在 LOD 间掉出被误读成闪烁。

UE 5.8 渲染症状菜谱：从分辨率/VSM/MegaLights 到低档位无效

把常见渲染症状收成「先证明什么 → 第一次有界实验」对照表：仅高分辨率慢→查像素缩放 GPU pass 并降 Screen Percentage；密林/城市场景慢→隔离图元/overdraw/VSM 失效；植被运动时阴影尖刺→查 VSM 未缓存页并禁远距 WPO/阴影；多灯仍快但噪→MegaLights 采样竞争，控半径或提采样做 A/B；反射占主导→单独对比反射档与 GI；半透明战斗特效拖垮 GPU→减单特效重叠/覆盖；Render Thread 慢而 GPU 有余量→实例化/剔除高提交类别；按地点涨显存→资源快照找新驻留所有者；低档位改了没变化→核对 device profile/组是否生效或需重启，并在打包构建验证；动态分辨率见底→在最低百分比下看主导 GPU pass 或是否实际 CPU 受限。每条要求恢复开关、用正式设置落地，并在同一最坏场景复测。

UE 5.8 World Partition：Actor 放置、硬引用与含 HLOD 的生命周期分类

要求对承重 Actor 显式记录五项：空间生命周期、Data Layer 世界状态、Runtime Grid（通常 None 走默认）、远处表示（指定 HLOD Layer 或故意不加）、依赖类型（硬引用/软引用/子系统/稳定 ID）。解释 Is Spatially Loaded：开启则按流送源距离加载（仍受 Runtime Data Layer 约束）；关闭则不做距离流送，适合真正全局且便宜的 Actor，不能当「引用丢失」的万能药或给远处普通可交互物乱用。硬引用会使空间 Actor 进入同一流送依赖捆，跨远 cell 引用会提前拉驻留；优先用子系统解析、接口+查询、软资产引用、稳定 ID 注册表或消息，而不是为消警告乱改软引用。附校验：Reference Viewer/Size Map、流送生成警告、带 cell 可视化的遍历、反复卸载/重载保留玩法状态、以及服务器/客户端分测。

UE 5.8 World Partition Data Layers：Loaded/Activated、网络权威与流送代价

区分 Data Layer Asset 与世界内 Instance；Editor Data Layer 只管编辑视图，Runtime Data Layer 才参与运行时状态机。运行时三态：Unloaded（不驻留）、Loaded（驻留未激活，作预热）、Activated（驻留且可见/可用）。联网时服务器改权威 Runtime 状态，客户端只观察复制结果，不要让客户端独自激活会改变碰撞/交互/世界真相的层。适用：Boss 场地预热、季节/毁坏变体、按任务权威分相、共享地形上的交替布景；不适用：单个小物件可见性开关、每个任务布尔一层、大范围零散 Actor 多层、仅客户端藏权威 Actor、把持久任务真相存在层状态里。状态迁移建议：服务器尽早请求 Loaded 覆盖最坏加载延迟→需要碰撞/交互时再等就绪→在揭示边界 Activated→玩法真相另存以便读档重建。性能提醒：Actor 大范围分散或多 Runtime 层会碎片化流送依赖。调试命令含 wp.DumpDatalayers、SetDataLayerRuntimeState、ToggleDrawDataLayers 等。

Epic 官方说明如何用独立命令行 ASDTool 从已 cook 的 Windows D3D12/SM6 构建生成 SODB（.sodb），供商店预编译成按 GPU/驱动的 PSDB，以减轻首次启动着色器编译卡顿。范围仅限 PCD3D_SM6；不支持光追 PSO；需源码编译 ASDTool，并开启 bShareMaterialShaderCode。采集来源：-AllCompute 收齐 SM6 compute shader，-BundleDir 从已有 .upipelinecache 导入 graphics/compute PSO；二者可并用。文档强调 ASD 不替代 PSO precaching / bundled PSO cache，仍建议保留 precaching。提供 generatesodb / compilepsdbs / registerpsdbs 本地验证流程，以及 -ValidatePSOs 排查失败 PSO。

Agility SDK 1.620.1：Batched Async Commands 的 Fallback Layer

1.620.1 为 Batched Async Commands 提供可选 Fallback：在不支持原生实现的设备上，由运行时用已有操作模拟 batched copy/fill/clear/resolve，原生支持设备仍走驱动快路径。启用后即使命令列表不用这些 API 也会有额外 CPU 记账开销（屏障、根参数、PSO、RT 绑定等）；需 Enhanced Barriers。文中列出与原生的差异（如部分 MSAA/保护资源清屏会失败、bound clear 在 render pass 内的限制），并可用 d3dconfig device force-async-commands-fallback=true 在原生硬件上强制测 fallback。微基准显示多数命令 GPU 开销接近，ClearTextureSubresources 在无法原地清时更贵。

UE 5.8 Scalability 与 Device Profiles：分档工作流与可读性底线

区分职责：scalability groups 管玩家可见画质族；device profiles 管平台/设备默认、特性支持、内存桶与覆盖。项目覆盖写在工程 Config，不要改引擎 Base 文件；以 BaseScalability.ini 与平台基线 device profile 为参考后再按测量覆盖。核心组含分辨率、视距、抗锯齿、阴影、GI、反射、后处理、贴图、特效、植被、着色等——一个 sg.* 可联动多枚 CVar。工作流：定义最低/推荐硬件与渲染器能力 → 设 Low/Medium/High/Epic 意图与玩法可读性底线 → 从引擎默认起在各目标设备测量 → 组不够预算时才覆盖子系统 → 标出需重启/重载的设置，并测存档、自动检测与不支持硬件回退。硬规则：低档不得拿掉敌人、危险、导航线索或竞技可见性，只缩放表现而非规则。
