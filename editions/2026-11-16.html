Neural Render Proxies：用一次与灯光无关的路径采样，对固定机位场景做可微、交互式重打光

ETH Zurich 与 DisneyResearch|Studios 等机构的 Sergio Sancho、Alexander Rath、Marco Manzi、Pascal Chang、Amit H. Bermano、Derek Nowrouzezahrai、Markus Gross 与 Marios Papas 的论文 Neural Render Proxies for Interactive and Differentiable Lighting，于 2026-11-12 提交到 arXiv（2611.17185v1，cs.GR）。页面标注该文属于 2026 年 Eurographics Symposium on Rendering（Computer Graphics Forum 第 45 卷第 4 期，编辑 I. Gkioulekas 与 A. Jarabo）。方法针对灯光环节里几何、材质和相机已固定、但每次微调灯光都要用离线渲染器重跑全图的情况：把渲染拆成一次与灯光无关的路径采样，以及之后按灯光参数计算发光。先从相机按 BSDF 重要性采样（不含 Next Event Estimation）缓存路径数据，再训练一个场景专用的轻量网络，学习从场景中任意位置到像素的光传输；推理时只随分辨率和灯光数量、参数规模变化，而不随场景与外观复杂度增长。作者写该方法可与不可微的生产渲染器配合：制作场景用 Walt Disney Animation Studios 的 CPU 渲染器 Hyperion 采集路径，学术场景则另做采集。摘要给出的交互式重打光帧率为约 30–60 Hz，并接近路径追踪参考；网络可微，因而可用图像空间编辑或生成式目标，对灯光参数做基于梯度的反求。实现基于 PyTorch 与 tiny-cuda-nn。作者在一块 RTX 5090（32 GB 显存）上报告：标准配置（680×680、512 spp、8 层×256 神经元）训练 10 万次迭代约 1 小时；Kitchen 场景（885×500）上，256/8 网络推理 9.13 ms、模型 7.4 MB，512/8 为 31.21 ms、13.3 MB。用与灯光无关的 64 spp 路径数据训练时，色调映射空间的平均 PSNR 仍比最多 1024 张图的基于图像基线高 2.8 dB。限制包括：机位与材质需固定；训练后不能再改物体间的非物理衰减或灯光独占（分层 NRP 只能近似后者）；遮挡腔体可能欠采样；路径数据需预载进显存。上述帧率、耗时、显存和 PSNR 均来自论文，本机未训练或复现。

    论坛：UE 5.8 Vulkan 硬件光线追踪下 bindless 描述符延迟写入导致 GPU hang（含补丁）

    LifeBandit7575 报告：UE 5.8 的 Vulkan RHI 在默认开启的 bindless（VK_EXT_descriptor_buffer）下，FVulkanShaderResourceView / FVulkanUnorderedAccessView 会在构造函数里分配 bindless 槽位，但描述符要等 RHI 线程的 EnqueueLambda 才写入；若命令列表先提交，GPU 会读到该槽位的前一个所有者（硬件光线追踪时常见为加速结构或 3D 纹理），顶点着色器取用后就会 GPU hang。发帖人在 Linux、Intel Arc A750、Mesa ANV 26.2.6 / 26.3.0 上，用约 300 个每帧重建顶点缓冲 SRV 的 UMaterialBillboardComponent（半透明加法材质），在 -game 中打开 r.RayTracing.Enable 1 并配合 r.RayTracing.Shadows 1 或 r.Lumen.HardwareRayTracing 1 后复现：启用 RT 后约 6–74 秒出现 hang（中位数约 13 秒），一晚超过 40 次。补丁是在构造函数里也对 buffer view（不含加速结构）调用 UpdateView；按发帖人验证，11/11 次通过（8 次 RT 阴影、2 次 Lumen HWRT、1 次关闭 RT）且未见回归。该帖尚未提供空白工程复现，也还没有 Epic 官方确认。

Last Week in Unreal：ue6-main 取消编辑器进程内 cook，项目级 cook 必须改走 cook commandlet

SpeedrunCI 于 2026-11-09 发布 Last Week in Unreal，汇总 2026-11-02 至 11-08 对 EpicGames/UnrealEngine 源码分支的提交。作者把该周最可能打断现有流程的变化放在 ue6-main：提交 84cd4dab 的说明是“Cooker: Remove support for cooking in the editor process（UUnrealEdEngine::CookServer，以及 ECookMode::CookOnTheFlyFromTheEditor / CookByTheBookFromTheEditor）；all project cooks must now run through the cook commandlet”。提交还写，这是接续 5.7 里把编辑器中的 CookByTheBook 弃用之后的收尾，并“deletes (without deprecation)”原先可通过 CookerSettings.bEnableCookOnTheFlyFromTheEditor 使用的编辑器内 CookOnTheFly。文中整理的仍然可用或受影响的行为包括：单个包仍可在编辑器里通过 UE::Cook::Internal::CookAsset 烹饪，但对某些类可能与项目级 cook 不一致；已保存的 Launcher 配置若使用了编辑器内 cook 模式会被重映射，并给出警告，改为在单独的 cook 进程里做 By the Book 或 On the Fly；Launch On 仍可用，但会启动单独的 cook 进程；Launcher 配置上的 OnIsCookFinished()、OnCookCanceled() 委托被删除，cooker 设置里的 bEnableBuildDDCInBackground 也被去掉。因此，依赖编辑器进程内 cook 或上述委托的插件和工具将无法编译，也没有弃用过渡期。同一周 CookIncrementalVersion 被改了三次（b7d89bd1、d6ecb330、2441c767），提交说明分别是主资产扫描规则、Shader 变化和重复主资产 ID“not picked up”，每次都会让下一轮增量 cook 失效全部包；另外 6ea64332 修了 PreSave 期间创建的对象丢失 cook 依赖的问题，复现是“cook 一个 Niagara 系统，改它的 renderer MIC 的父材质，再做增量 cook：该系统不会被重新 cook”。这是对公开源码提交的解读，不是已发布引擎版本的发行说明；文中统计该周 ue6-main 有 1,476 个提交。文章同时也介绍了当时刚公开、尚未打标签的 5.9 分支，并写 Preview 将在“下周”到来——5.9 Preview 现已发布，相关官方说明此前已另文收录，此处不重复展开。本机未同步这些提交或实际 cook。

Anthropic：自托管 Claude Managed Agents 进入私有预览，可在自有环境运行 harness、沙箱和会话历史

Anthropic 于 2026-11-12 在 Claude 官网发文，宣布 Self-hosted Claude Managed Agents 进入私有预览（private beta）。Managed Agents 是一套用于构建和部署自主 agent 的可组合 API，提供 agent harness、沙箱、凭据处理和会话历史。此前托管版由 Anthropic 在 Claude Platform 上运行基础设施，随后又提供了只把沙箱放在客户环境的选项。自托管模式下，harness、沙箱、凭据和会话历史都在客户自己的云或本地环境中运行：由客户运维 Managed Agents 服务器、数据库，以及执行 shell 与文件工具的 worker。发往模型的请求可由客户选择路径，文中列出 Anthropic 直连、云厂商（Amazon Bedrock、Google 的 Agent Platform 或 Microsoft Foundry），或客户自己的网关。开发者仍使用与托管版相同的核心 API。会话历史存在客户自己的数据库里；若组织已与 Anthropic 签订零数据保留（ZDR），文中写它对发往 Claude 的请求按与其他 Messages API 调用相同的方式适用。架构说明包括：harness（调用 Claude）与沙箱（跑 agent 代码）分离，循环、会话历史和保险库密钥留在沙箱外；对 MCP 工具和受支持的 API 调用，由沙箱外的代理附加凭据，自托管时也可把凭据放进客户自己的密钥管理；可为每个环境设置允许的主机列表；每一步工具调用可经 OpenTelemetry 导出。获取途径是联系 Anthropic 客户团队申请访问，或先阅读文档。私有预览的具体资格、配额和收费，本文未给出可独立核对的公开细则。本机未申请或部署该服务。

Codex CLI 0.169.0：终端可开多个侧栏对话，codex exec 在未信任目录不再因 workspace-write 自动启用项目配置和 MCP

OpenAI Codex 于 2026-11-13 发布 Rust 版 0.169.0（GitHub 标签 rust-v0.169.0）。发行说明列出的新功能包括：可选的终端工作区支持多个 side-chat 标签页，可用键盘或鼠标切换，本地已保存的侧栏对话在重启 Codex 后也能重新打开；可在 agent command center 里按名称、提示预览或工作目录搜索更早的任务；全屏 transcript 可打开 Collapse turn details，把已完成活动折到各条提示下面，同时保留可见答复，工具输出仍可搜索；可在终端里添加或编辑自定义模型提供方，若启用了 custom gateway onboarding，还能在登录过程中创建提供方，并在 SSH 或没有本地浏览器时对支持的网关使用 device code；在终端报告编辑器里按 Ctrl+S，即使禁用了上传，也可以把诊断 ZIP 存到本地；在 macOS 和 Linux 上，若启用了可选的 Cloud 连接，可从终端发送图片、选择模型和推理力度，以及归档或恢复 Cloud 对话。行为变化方面：即使加了 --sandbox workspace-write，codex exec 在未信任目录里仍会保持项目配置和 MCP 服务器为关闭；若要明确保存项目信任，需对 codex exec 或 codex review 使用 --trust。其他修复包括：Yes, clear context and implement 会把完整已批准计划交给新会话，若交接失败则保持当前会话打开；修正了 Windows 沙箱对带引号的 cmd.exe 路径，以及工作目录的父目录不可读时的 PowerShell 会话；macOS 粘贴图片会保留预定方向，并在可用时使用原生 PNG 或 JPEG 剪贴板数据；终端不再一直等待共享 app server 未汇报的 MCP 服务器；被中断的回合会干净结束，延迟的中止或文件审批取消不再打断后续回合。说明还写更新了捆绑的 SQLite 到 3.54，以及插件市场升级可复用磁盘上已有的 Git 对象。本机未安装或运行该版本。

Unity 6000.6.9f1：可为纯编辑器 UI Toolkit 用途剥离模块，并加入官方 Steamworks API 包 1.0.0

Unity 于 2026-11-12 发布 6000.6.9f1（Supported 通道，changeset 8c45277fb9c5）。改进项包括：Memory Profiler 对 Asset Database 原生内存的归属改为记在具名的 AssetDatabase 根下，而不再作为未归类内存；Licensing Client 更新到 v1.19.0，官方称启动更快——这是厂商说法，本机未测量；在运行时统计关闭时跳过 JIT 阶段计时，以降低 JIT 编译开销；新增脚本定义符号 DISABLE_UGUI_UITK_SUPPORT，用于排除 uGUI 与 UI Toolkit 的集成，从而在 UI Toolkit 只用于编辑器时，让 Player 构建可以剥离 UI Toolkit 模块。API 方面，内置 JetBrains.Annotations 增加了 SourceTemplateAttribute.Target 和 SourceTemplateTargetExpression 枚举，源模板可以使用 Target = SourceTemplateTargetExpression.Outer。UI Toolkit 的 Constant Physical Size 面板在解析缩放时，会把 Game 视图的 Low Resolution Aspect Ratios 设置计算进去。修复里较直接相关的有：DirectX 12 下每次窗口重绘会泄漏描述符内存，长时间开着编辑器可能崩溃；异步命令列表上错误的资源状态跟踪、split-threaded native graphics jobs 的 render pass input attachment 校验错误，以及原生渲染插件或异步计算仍在使用资源时发生的竞态；部分 OpenGL ES 设备在关闭 2D Renderer 的 Depth/Stencil Buffer 时精灵和 UI 不绘制；2D 项目 Player 构建时间过长，原因是 Sprite Lit、Sprite Custom Lit 和 VFX Graph 着色器里不需要的 Rendering Layer Mask 变体。包变更中新增 com.unity.steamworks-api@1.0.0；Memory Profiler 从 1.1.12 升到 1.2.0。发行说明还列出若干已知问题，例如开启 Run In Background 和 Predictive Back Support 时，Android 从后台返回后返回手势会关闭应用，以及烘焙集之间切换活动场景可能出现 IndexOutOfRangeException 甚至编辑器崩溃。本机未安装该版本。

CORTAO：开源的基于圆形遮挡体与屏幕空间光线追踪的实时 SSAO，可作为引擎原有 SSAO 阶段的替换

Fenris Creations（EVE Online / EVE Frontier）于 2026-11-12 宣布开源 Circular Occluder Ray-Traced Ambient Occlusion（CORTAO），作者是高级渲染工程师 Daniel Isheden。参考实现仓库 theagentd/CORTAO 的 README 版本记录写 1.0.0 初始发布为 2026-11-05，随后在 11-13 到 11-15 发布了 1.0.1–1.0.3 的修复；仓库采用 MIT 许可证。技术说明把 CORTAO 定义为基于屏幕空间光线追踪的物理实时 SSAO：从深度缓冲采样，把像素邻域近似成圆形遮挡体，再对这套代理几何求交，并用预计算查找表追踪每像素最多 32 条光线，同时可计算 bent normals。作者用它对照 GTAO（Jimenez 等，2016），认为水平线方法在倾斜、不正对相机的表面上会偏斜，难以收敛到暴力光线追踪参考；这些准确性、稳定性以及“以更少样本达到更高质量”的说法来自仓库 README 和公司稿，本机未复现。仓库给出的作者测试结论包括：简单场景中，CORTAO 用不到一半的 GPU 时间达到与 GTAO 相当的精度，或在相同 GPU 时间预算下平均平方误差最多低约 4 倍；复杂场景中，在更低样本数下平均平方误差明显更低，并在提高样本数后收敛到比 GTAO 更低的误差。仓库还写：着色器提供 HLSL 与 GLSL；已测试可在 DirectX 11（需 Shader Model 6.7 的变通）、DirectX 12、OpenGL 4.3+ 和 Vulkan 1.0+ 上直接使用；HLSL 完整路径的最低要求是 Shader Model 6.7。实现分 prepass、main pass 和可选的空间滤波 pass，用于给后续时间滤波做准备；仓库目前不自带时间滤波，需要引擎侧另行接入。面向 Carbon 引擎、针对大深度范围太空场景的精简实现另在 carbonengine/CORTAO。公司稿称该技术已在开发中的 EVE Frontier 中测试，并设计为替换引擎现有的屏幕空间环境光遮蔽阶段。本机未编译或跑分。

FastWild-GS：用紧凑的逐图外观适配，在数分钟内做野外照片集的 3D Gaussian Splatting

Chung-Ang University 的 Donghun Ryu、Seokhyun Kim 与 Minhyeok Lee 的论文 FastWild-GS 于 2026-11-10 提交到 arXiv（2611.13808v1）。论文针对互联网照片集中曝光、光照和过路人等瞬态物体不一致的 in-the-wild 设定：同一套高斯颜色无法解释所有照片，而近期同类方法多报告每场景数小时优化。FastWild-GS 用 128 维 Photo Appearance Token（PAT）描述每张照片，再加上作用在渲染图上的每通道 scale 与 offset（共 6 个参数）；一个小 MLP（PAT Decoder）根据该 token 和每个高斯的特征预测颜色，用来替换球谐颜色。稠密化与剪枝打分用的渲染图也会套上同一套逐图变换，避免把曝光或色彩差异当成重建误差。对留出照片，场景固定，只在图像左半边拟合该照片的外观参数，右半边用于评测。作者报告的结果（文中写在一块 RTX 5090 上测量，本机未复现）：在 PhotoTourism 上每场景训练 8.8 分钟，在所比较方法中 LPIPS 最低，比 LPIPS 次优的 AsymGS 快 23 倍；在 NeRF-OSR 上每场景 9.7 分钟，平均 PSNR、SSIM 和 LPIPS 在所比较方法中最好。摘要还写加速版 3DGS 训练虽能到分钟级，但通常假设采集外观一致。本机未训练或核对表格中的具体指标。

Unity Hub 4.0.0：重写为原生应用，命令行改走 Unity CLI，并改进 Git / SSH 支持

Unity 于 2026-11-13 发布 Unity Hub 4.0.0 正式版。官方发行说明写明：Hub 已重写为原生应用，保留原有常用功能，并称启动更快、下载体积约为原来的四分之一——这是厂商说法，本机未测量。更新会替换已安装的 Unity Hub 3。原先 Hub 的命令行模式（--headless）改由 Unity CLI 取代，说明里举例把旧命令对应到 unity install、unity editors 等；若仍要使用 Hub CLI 命令，官方建议安装 Hub 3 的最后一版 3.22.6。此版本把捆绑的 Unity CLI 更新到 1.0.0。新增 Settings > Security & Privacy 中的 “Send crash reports” 开关，默认开启、无需重启，也覆盖捆绑的 Unity CLI。Projects / Templates / Installs 页可用 Cmd+F（Windows / Linux 为 Ctrl+F）跳到搜索框。Linux 除 AppImage、.deb 和 .rpm 外，新增 Flatpak 发行。使用 High Definition Render Pipeline（HDRP）的项目和模板会在所有 Editor 版本上显示弃用警告；新建项目流程里，HDRP 模板会排到最后且不会被默认选中。源代码管理方面：Hub 改用操作系统凭据管理器或 Git Credential Manager 登录 GitHub / GitLab，若没有凭据助手，可在上述设置里安装；现支持 SSH 远程，并在连接失败时说明原因；可为每个组织和每个项目使用不同的 Git 账号；能识别你在终端、IDE 或浏览器里完成的登录；克隆仓库会显示真实进度，Cancel 会停止下载，若已安装 Git LFS，LFS 文件会以真实文件到达。Installs 页可为 Editor 复制路径；在 Hub 外用 unity uninstall 等移除的 Editor 或模块，会在数秒内从该页消失；在 Hub 外变更的许可证也会更新列表。2017.2 到 2018.4 的 Editor 不再从 Hub 获取账号信息，会显示为已退出登录，但项目仍可从 Hub 打开。若 Editor 或其他应用请求打开不在项目列表中的文件夹，Hub 会先询问。说明还写改进了 Windows 上 Hub 更新、模块安装以及从 Hub 3 升级的安全性；通过共享 Hub 链接切换分支时，非 GitHub / GitLab HTTPS 仓库需直接在 Git 里切换。本机未安装该版本。
