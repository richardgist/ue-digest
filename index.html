Epic：UE6（含 Early Access）将不含 Blueprints 与 Actor 玩法框架，改用 Verse 与 Scene Graph

Epic Games 开发执行副总裁 Marcus Wassmer 于 2026-11-20 在 Unreal Engine 官网发文《An update on Blueprints and the path to UE6》（页面显示 November 20, 2026；官方 RSS 标注 published 为 2026-11-20 00:00:00 GMT）。文章写明：UE6（包括 UE6 Early Access）将不包含 Blueprints 与 Actor Gameplay Framework，玩法将在 Verse 和新的 Scene Graph 框架上构建。作者回顾，今年 6 月曾表示 Blueprints 与 Actor 会在 UE6 Early Access 和 6.0 中并存，以便 UE5 项目在 Scene Graph 成熟时逐步升级；此次改口的理由是“近期 AI 能力的进展”。文中写到，Epic 预期 AI 将大幅帮助把 UE5 项目转到 UE6，“哪怕还不能让这一过程完全自动”，并称这样可以按时（或更早）交付 UE6，同时满足其设计目标：新的数据模型、Verse 优先的架构、模块化，以及 AI 可操作性。上述“大幅帮助 / 完全自动 / 按时或更早交付”均为官方预期，并非已完成的迁移结果。关于成本，文章引用 Epoch AI 的“任务成本同比下降 13 倍”并认为趋势会持续甚至加速，从而在 UE 6.0 面世时转换成本会较为有限；该倍数与成本判断均来自文中引用和推测，本栏未核对 Epoch AI 原文。Fortnite 方面，作者称大约两周前用 AI 尝试把 Battle Royale 的全部 Blueprint 转成 Verse：该工作原先预计要数年，但现在已有一个可运行的 Fortnite 原型，在移植超过 20,000 个 Blueprint 后约有 300 万行 Verse 代码；团队仍在迭代，以验证性能、内存占用和架构。这是 Epic 自己的实验陈述，本栏未见到独立复现。文章明确：是否继续把项目留在 UE5 由开发者自己决定，不必等到 UE6 才能使用更多 AI 工具。Epic 已开始把为 UE6 做的 AI 工具带回 UE5，首先出现在 UE 5.9 MegaJam Preview，并列了四项：扩大的编辑器 Python 脚本访问、MCP 改进（把首选模型接到编辑器并直接在项目里工作）、把 Web 作为目标平台、以及 Unreal Canvas（生成资产，并把编辑器内容、引用和反馈并排、保持可更新和可控）。文中还称 UE 5.9 的相当一部分（包括大部分 Web 平台工作）是用 AI agent 做的，并表示在开发 UE6 期间会继续针对 UE5 做有针对性的功能、修复和支持。5.9 预览的渲染与动画更新见文内链到的发行说明；本栏未安装或验证 5.9 Preview。

    AGSR：用收缩投影协方差的多孔径渲染，给预训练 3DGS 做推理时超分（论文）

    Ayman Alkhateeb、Hadi Amirpour、Christian Timmerer（Alpen-Adria-Universität Klagenfurt）的论文于 2026-11-19 提交 arXiv（编号 2611.25934）。作者认为 3D Gaussian Splatting 的光栅化会通过每个图元的投影协方差衰减细尺度结构，并在推理时收缩这些投影协方差，以缓解有限高斯足迹带来的等效带宽限制，从而得到多孔径渲染。据此提出 AGSR（Aperture-Guided Super-Resolution）：在推理阶段逐步融合多孔径渲染，用不确定性引导的特征聚合，以及透射率、深度等几何条件；它作为插件增强已训练好的 3DGS 模型，底层高斯表示保持冻结。实验在 Mip-NeRF 360 上进行，并对训练图像按 tf∈{2,4,8} 下采样得到不同质量的 3DGS，再评估 2× 与 4× 超分。论文报告：在 2×、tf=8 时，AGSR 相对双三次上采样将 PSNR 提高 1.69 dB、SSIM 提高 0.039，相对直接以目标分辨率光栅化的 Native 3DGS 提高 4.34 dB PSNR（表 II：AGSR 25.49 / 0.764 / 0.349，Bicubic 23.80 / 0.725 / 0.358，Native 21.15 / 0.631 / 0.437）。在 4×、tf=8 时，AGSR 的 SSIM 为 0.766、LPIPS 为 0.360。作者也写明：在低退化 tf=2、2× 时，微调后的 SAFMN 在 SSIM（0.830 vs 0.827）和 LPIPS（0.281 vs 0.287）上略优于 AGSR。复杂度方面，网络约 21K–139K 参数；表 I 在 NVIDIA RTX A6000、batch size 1、目标 Full HD（含 3DGS 光栅化与网络推理）上测得：2× 在 3 个融合阶段时 FP32/FP16 为 22/27 FPS，4× 因输入分辨率更低，3 阶段为 64/76 FPS。这些指标均为论文实验数据，本机未复现。arXiv 摘要页未见 Comments 字段，也未见官方代码仓库或项目主页。

    论坛：开启 Nanite Tessellation 后，硬件光追阴影对不齐置换后的表面（社区解释原因）

    作者 @HN1214 报告：在 UE 5.6 / 5.8 上使用 Lumen 与硬件光线追踪时，打开 Nanite Tessellation 后能看到网格上的置换，但光线追踪阴影对不齐置换后的表面。这个问题在侧光特写镜头里尤其明显，对影视镜头很关键。他询问更新的引擎版本是否已修复，若仍在开发则目标版本是什么。次日 @glitchered 给出社区技术解释（并非 Epic 官方答复）：Nanite 置换是实时变换的可视几何，而光线追踪依赖放进加速结构（BVH）里、预先变换好的静态或“动态”几何；Nanite 细节太多，难以即时重建 BVH，因此会使用更低分辨率的代理 BVH，这份代理不会为虚拟置换后的几何计算正确阴影，所以对不齐。答复认为这需要较长时间才能解决，帖中没有给出已验证的变通，也没有官方修复或目标版本。

Codex CLI 0.171.0：默认打开 TUI workspace，目录加入 GPT-6.2 Sol / Astra，并支持远程 exec

OpenAI 在 GitHub 发布了 Codex CLI 0.171.0（标签 rust-v0.171.0，发布时间 2026-11-20T00:44:47Z）。新功能包括：把 GPT-6.2 Sol 与 Astra 加入模型目录，并以 Sol 作为目录的默认选项；默认启用 TUI workspace，可在主对话旁提供可搜索的文档预览、图片预览和子代理 transcripts；为非 Vim 的提示编辑器增加可配置的撤销/重做快捷键，并可恢复附件和大段粘贴；新增 `codex exec --remote`，可在已有的 app server 上启动或恢复非交互会话；TUI 中新增 `/rc` 与 `/remote`，用于管理本机远程控制并显示设备配对码；在启用 `tui_extensions_statusline` 时，可通过 `/statusline` 选择或编写自定义 MCP 状态行。修复方面，发布说明列出：切换或恢复会话时保留草稿、排队的后续输入和被打断的输入及其原线程；更换工作目录时保留权限配置；避免迟到的完成事件取消较新一轮的审批；在引导进行中的回合时保留聚合 diff 中的先前提交编辑；修复滚动插入杂字符、输入光标跳动，以及用过期终端尺寸重绘；并修复企业 MCP 登录在身份提供方只签发不含 refresh token 的 ID token 时失败的问题。发布说明还提到将源码构建与发布工具链更新到 Rust 1.99.1。完整变更见 rust-v0.170.0...rust-v0.171.0。上述行为以发布说明为准，本机未安装或验证该版本。升级后 TUI workspace 会变为默认布局，而不只是给曾经手动开启的人使用。

Hugging Face：为特定 agent 框架训练 LoRA harness adapter，提升准确率并减少工具调用

Lewis Tunstall 于 2026-11-20 在 Hugging Face 博客发布《Introducing harness adapters: adapt your favorite model to your harness to improve performance and cost》。文章的核心做法是：冻结基座模型，在目标 agent 框架（harness）内部用强化学习训练定制 LoRA，使模型适应该框架及其任务分布。作者为 Qwen3.8-27B 分别给 pi、Hermes Agent 和 OpenCode 训练了一个 adapter，训练与 rollout 在 Hugging Face Jobs 上用 TRL 的 `AsyncGRPOTrainer`、OpenEnv 和 Harbor 完成；最终镜像里的框架版本写明为 Pi 1.5.2、OpenCode 2.2.7、Hermes Agent v0.22.6。文首示例称，Qwen3.8-27B 在 pi 框架下的 Terminal-Bench 2.1 分数为 39%、平均每任务约 2.9K token，加上 adapter 后为 55% pass@1、平均约 1.5K token，作者将其主要归因于更少推理、更少工具调用和更高的一次成功率。后文还报告：三个专用 adapter 在各自框架下、两个基准上都超过基座模型。在 SWE-bench Pro（hard 51）上，pi 从 39.2% 升到 64.7%（+25.5 分：新解 15 题、丢失 2 题，p=0.002），Hermes 从 29.4% 升到 43.1%。在两边都能解出的任务上，adapter 在 SWE-bench Pro 上少 56%–72% 的工具调用，在 Terminal-Bench 2.1 上少 53%–70%。三个 LoRA 还被合并成一个可在 pi、Hermes Agent 与 OpenCode 下不变运行的 super-adapter。作者同时做了交叉和域外检查：例如把 pi 的 adapter 放到 OpenCode / Hermes 下评估，以及在 AutomationBench 自带 agent loop（不是这三套框架）上跑 300 个任务，结果显示 adapter 与基座接近，差异被作者视为噪声范围内。adapter、GGUF、RL 任务和 safeagents 插件可通过文中的 Hugging Face collection 浏览。上述分数与效率数字均为文章报告的实验结果，本机未复现训练或评测。

VideoRNG：用生成式视频模型做出可重打光的神经高斯资产（论文）

Bowen Xue、Saeed Hadadan、Fabrice Rousselle、Ravi Ramamoorthi、Zahra Montazeri、Miloš Hašan 的论文于 2026-11-19 提交 arXiv（编号 2611.25338，学科 cs.CV、cs.GR；作者单位包括 NVIDIA、University of Manchester、UC San Diego）。作者认为网格加紧凑 PBR 材质难以表达细几何或复杂光传输带来的外观，而现有高斯溅射生成方法通常把固定光照烘焙进外观。VideoRNG 是一个两阶段方法：先把预训练视频扩散骨干微调成视频生成器，在已知位姿、相机和光照下生成结构化 RGBA 转台序列；再用从预训练视频扩散骨干初始化的前馈重建模型，把选定转台帧的 video-VAE 潜变量直接映射到带学习神经外观特征的数百万各向异性高斯。共享方向解码器和随机高斯光线追踪器把该表示（文中称为 rtRNG）变成新视角和新光照下的辐射。为在学习几何时保留高频外观，作者引入 depth-anchored appearance training，并用前景 token 选择和代价感知的分布式采样来降低百万级高斯重建的开销。论文摘要称该方法可由文本提示或单张图像生成完整、可重打光的 3D 资产，并展示毛皮、羽毛、蛛网等可交互渲染、重打光并放入场景的例子。图 1 说明中，作者报告在 NVIDIA RTX A6000 上、每资产解码器隐层宽度 64、1280×720、1 spp 时每帧约 50 ms；该耗时为作者实验数据，本机未复现。arXiv 摘要页没有 Comments 字段，也未见官方代码仓库或项目主页。

论坛：UE 5.8/5.9 摄像机切镜帧上，TSR 未写入的 mip 1 会让 Tonemap 采到过期画面（含修复建议）

作者 @Michael.Edwards 报告：在开启 TSR、运动模糊且 r.MotionBlur.HalfResInput=1（默认）时，摄像机切镜的那一帧画面边缘会出现一帧旧画面残影；把抗锯齿改成非 TSR，或设 r.MotionBlurQuality=0，残影会消失。根因是 5.8 起 TSR 会为运动模糊预过滤分配半分辨率 mip 1，但写入与分配是分开的：PassInputs.bGenerateOutputMip1 决定分配，还要加上 PassConfig.MotionBlurValidInCurrentFrame 才写入。切镜帧上 View.bCameraCut 或 View.bPrevTransformsReset 会使 MotionBlurValidInCurrentFrame 为假，于是 mip 1 仍占用池化纹理里的旧内容（常常是另一台摄像机的画面），输出 SRV 却覆盖两个 mip。切镜帧会跳过运动模糊，Tonemap 直接采样 TSR 输出；色差等会放大 UV 的导数 LOD，在屏幕边缘把过期的 mip 1 混进来。作者用 RenderDoc 确认切镜帧上 TSR.History.Color 的 mip 1 是旧帧，下一帧 mip 1 被重新写入后画面恢复。建议在未写入 mip 1 时把输出 SRV 限制为 mip 0，或在已分配时始终写入 mip 1，或让 Tonemap 用 SampleLevel(..., 0)。原文询问是否已在后续改动中修复、能否进 5.8.x 热修或 5.9；发帖时没有 Epic 回复。平台为 Windows。

Unity 6000.6.10f1：Forward+ / Deferred+ 不再处理远平面外的光与探针，并修复多处灯光裁剪

Unity 官方发布说明写明 6000.6.10f1 于 2026-11-19 发布，changeset 为 40e81493c67d。改进方面：URP 的 Forward+ 与 Deferred+ 渲染路径不再处理只在远平面之外、或位于正交相机近平面之前的那部分灯光与反射探针。变更方面：FreeType 更新到 2.15.0，为 macOS 上镜像的 Apple Color Emoji 字形提供支持，并略微改变 Hinted Smooth 与 OS Default 字体渲染模式的文本外观；Clamped 模式下的 Content Size Fitter 在 Horizontal / Vertical Layout Group 关闭 Control Child Size 时，会保持大于内容的尺寸，而不再把组收缩到子物体大小（UUM-159240）。修复中与渲染和安全相关的包括：Graphics.RenderSpriteInstanced 在 MaterialPropertyBlock 里设置 _MainTex 时不再画 Sprite 自身纹理（UUM-158701）；Android 将 Bouncy Castle 从 1.70 升到 1.86，Keystore Manager 新建密钥改为 4096-bit RSA 与 SHA256withRSA（已有密钥不变），OpenJDK 从 17.0.18+8 升到 17.0.21+9 以应对被泄露的 eMudhra 中间证书，并把 NDK API level 提高到 26；DirectX 12 为大纹理在单帧多次更新导致的崩溃提供修复，并在为 Android 目标烘焙 Entities Graphics 光照贴图时增加 CopyTexture 校验；修复 macOS 上 Unity Compute light baker 可能错误烘焙探针遮挡，以及遮挡剔除在极多 occludee 场景中的崩溃；修复 Forward+ / Deferred+ 下聚光灯边缘块状缺口、靠近近平面或屏幕边缘时点光/聚光灯缺失、以及相机后方聚光灯顶部被裁掉等问题；还修复 Unity Transport WebSocket 的栈损坏与无效握手后的越界访问（UUM-160664），以及 FreeType 畸形可变字体越界读取漏洞 CVE-2026-23865（UUM-140975）。发布说明同时列出已知问题，例如在 Baking Sets 之间切换活动场景时的 IndexOutOfRangeException 与编辑器崩溃（UUM-161251），以及若干 Mecanim / Prefab / Search 崩溃。本机未安装或回归测试该版本。

论坛：UE 5.8 部分 Masked 材质会忽略 Opacity Mask（bCanMaskedBeAssumedOpaque 被置真）

作者 @lyaflora 在空白项目中复现：复制引擎自带的 Niagara 默认精灵材质 DefaultSpriteMaterial（Engine/Niagara/DefaultAssets），把 Blend Mode 改为 Masked，并把 Opacity Mask 设为 0 后，预览网格仍完全可见，像是 Opacity Mask 为 1。作者发现出问题的材质里 bCanMaskedBeAssumedOpaque 为真，生成的 HLSL 里 PixelMaterialInputs.OpacityMask 在多处被写成 1.0f。按另一帖提供的 C++ 修复函数跑完后，该标志会变为假、HLSL 也暂时正确，但预览外观仍不变；一旦再改材质并 Apply，标志又会被重置为真，HLSL 再次写错。给该故障材质做实例、并在实例上把 Blend Mode 设为 Masked，实例侧可以正常工作，父材质仍然是坏的。作者试过关闭 Substrate、改 GBuffer Format 等项目设置，都没有解决问题。原文指向一篇关于 5.8.1 旧材质忽略 Opacity Mask 与 AO 的相关帖，发帖时没有 Epic 回复。平台为 Windows。

Anthropic 在 GitHub 发布了 Claude Code v2.1.330（发布时间 2026-11-20T22:32:56Z）。新功能包括：支持登录 Anthropic Enterprise Admin Console 管理的组织，在 `claude auth login` 之后会应用该组织设置并使用其云供应商或网关；新增内置 mod easel，可在被要求时以及在 MCP 指标结果下画图，面向 Pro、Max，以及在可用时的 Team 与 Enterprise，仅 macOS 与 Linux，可在 `/config` 关闭自动出图；可用环境变量 `CLAUDE_CODE_FULL_SIGN_IN_LINK=1` 打印完整登录链接；自托管 runner 新增 `--start-dir` / `SELF_HOSTED_RUNNER_START_DIR`，让 Claude 在仓库的某个子目录开始工作，同时仍按原方式加载设置和 hooks；`claude plugin install --json` 增加 `commandPrinted` 与 `commandFailed` 字段；自托管 runner 的 `/metrics` 增加从工单下发到注册成功、以及到首次会话交接的耗时指标。修复方面，发布说明列出：超长对话压缩后可能卡住数分钟、WebFetch 在部分页面卡住数分钟或返回空结果、`ExitWorktree` 与退出对话框可能删掉其他正在使用的 worktree、多个进程同时保存导致用户设置丢失、`--continue` / `--resume` 在最后一条消息时间戳缺失或无效时打开空会话或失败，以及 MCP 工具输入 schema 被 API 拒绝时出现 “JSON schema is invalid”、会话文件膨胀数兆字节等。还修复 Linux/WSL 上休眠两分钟以上后第一条提示空等约三分钟、Linux 上含大型忽略目录的慢仓库在 Bash 后不再显示文件 diff、Windows 上 Git Bash 启动慢导致后续 Bash 变慢，以及 VS Code 中 `/fork`、`/loop` 与选择范围等多处问题。上述行为以发布说明为准，本机未安装或验证该版本。

论坛：UE 5.9 同时开启 LumenPT、MegaLights 与 World Cache 会在全局着色器编译阶段失败

作者 @John70176162 报告：在 UE 5.9 的 DefaultEngine.ini 里启用 LumenPT，并同时打开 MegaLights 与 World Cache 后重启工程，启动画面阶段就会因全局着色器编译失败而崩溃。致命错误来自 ShaderCompilerEditor.cpp，平台为 PCD3D_SM6，共 6 个错误。帖中贴出的报错包括：MegaLightsShading.ush 中 UnpackSubstrateHeaderIn 与 SubstrateDeferredLighting 没有匹配的函数重载；LumenPTInitialSampling.usf 中 FMegaLightsMaterial 没有名为 GBuffer 的成员（FLumenPTInitialSamplingRGS、FLumenPTVisualizeHardwareRayTracingRGS 等 permutation 都会受影响）。调试信息被写到项目 Saved/ShaderDebugInfo 下对应全局着色器目录。发帖时没有给出已验证的变通，也没有 Epic 回复。平台为 Windows。该组合仍属 5.9 预览期能力，建议先在项目副本上验证。
