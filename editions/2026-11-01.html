  1. 图形渲染UE 日报02

    ue5-main：LumenWorldCache——运行时自动表面缓存，可替代预烘焙 Mesh Cards

    社区分享的 ue5-main 变更说明描述 LumenWorldCache：用 GBuffer 路径追踪（默认约 1/64 spp）在稀疏体素单元里缓存命中，作为可自动覆盖全场景的表面缓存，意图替代依赖预烘焙 Mesh Cards 的 LumenSurfaceCache。说明要求开启 Ray Tracing 与 hit-lighting（完整/材质光追模式）；宣称不挑几何类型（含骨骼、Spline、WPO）、无需 cook 卡片、几乎无 CPU 实例更新，并给出 FortGPUTestBed 上室内约 +0.35ms、室外约 −0.4ms、内存约小 10× 的对比。开关示例包括 r.Lumen.WorldCache.Support 与 r.Lumen.WorldCache.Allowed；同时列出水面/前层半透明反射、透射、Ambient Lighting Volume、Far Field 等尚未支持项。公开 GitHub 提交链接对未登录用户 404，细节以帖内截图为准，且仅适用于跟踪主线而非现网 5.8。

  3. 图形渲染UE 日报04

    论坛实操：Lumen 间接光Δ=0——空 Distance Field 图集与 Linux/Vulkan 能力门

    提问方在 Linux/Vulkan 无头编辑器上用 SceneCapture 测得开关 Lumen GI 的亮度差精确为 0，同时 Surface Cache 仍在更新。答复指出：5.4 Linux 上 Vulkan 光追不是受支持的 Lumen 路径（即使扩展枚举成功也会报 disabled on current platform）；Surface Cache 更新≠软件追踪所依赖的 Mesh/Global Distance Field 已建好。若 DF 图集为空，屏迹在无真实深度/历史的离屏捕获上也会打空。给出不靠 Static Mesh 编辑器 GUI、在非 -nullrhi 下用 StaticMeshEditorSubsystem 脏化 LOD0 构建设置以强制重建 DF 的 Python 片段，并提醒 DefaultEngine.ini 应写 bGenerateMeshDistanceFields=True；另指出 r.GlobalDistanceField.Debug.ShowStats 在 5.4 Vulkan 上会触发已知断言，且 Lumen Scene 视口模式无法进 SceneCapture。

图形渲染UE 日报06

UE 5.8 Nanite：Owner No See + Cast Hidden Shadow 在本机视角不投阴影（含源码定位与变通）

报告：Nanite 开启时，Owner No See + Cast Hidden Shadow 的静态网格在拥有者第一人称视角下完全不投阴影（VSM 开、RT 阴影关）；第三方视角正常，关闭 Nanite（r.Nanite 0 或 Disallow Nanite）后本机阴影恢复。作者对照源码指出 NaniteInstanceCulling.usf 阴影通道虽放行 Cast Hidden Shadow，但随后按 NaniteOwnershipVisibility 的 HiddenPrimitives 无条件剔除本机 OwnerNoSee，且无阴影通道例外；非 Nanite 的 IsShadowCast 则会在 Cast Hidden Shadow 时跳过 owner 测试。建议的临时做法：本机在 Owner No See 期间对组件 SetForceDisableNanite(true)，走非 Nanite 阴影路径。典型用例是隐藏车身外壳但仍要在驾驶舱看到车影。

图形渲染UE 日报08

UE 5.8：分辨率、TSR 与 Dynamic Resolution 的量测与边界

把内部分辨率、TSR 重建与 Dynamic Resolution 拆开量：TSR 同时有输入分辨率与输出分辨率成本，降低 screen percentage 未必同比降低 TSR 通道本身。建议在目标输出分辨率上抓 GPU，用相同内容对比主屏百分比，经 sg.AntiAliasingQuality 调档，并用 Temporal Upscaler 可视化与 TemporalSuperResolution 事件查速度/拒绝/半透明/曝光问题；避免把例行输入百分比压到 50% 以下。Dynamic Resolution 侧列出 Min/MaxScreenPercentage、FrameTimeBudget、HistorySize 等 CVar，强调它只能响应既往 GPU 负载、无法挽救 CPU 瓶颈，并用 stat unitgraph / stat raw 核对原始 GPU 时间与所选百分比。

UE 5.8 World Partition：Level Instance / Packed Level / OFPA 选型与 HLOD 核验清单

区分 Level Instance（可含玩法 Actor、就地编辑并传播到所有实例）、Packed Level Blueprint（偏静态网格视觉组装，任意组件可能打包不全）与 OFPA 工作流。Embedded 模式（OFPA Level Instance 默认）在运行时丢弃包装器、把外部 Actor 并入父级 WP 网格；无法嵌入时退回 Level Streaming 模式并按单元流送子关卡，高密度会有额外开销。文中明确实例内 Actor 默认可继承 Level Instance 的 Data Layer，并要求在每个放置副本上核验运行时状态与 HLOD 行为；创建清单含轴点、传播测试、Embedded vs Streaming、碰撞/导航/引用以及 HLOD。提醒拆开 Level Instance 不可通过该操作撤销，破坏性重组前先提交。

Splatting the Gaussians into Blender

Blender 5.3 引入原生 3D Gaussian Splat：可导入 .PLY / .SPZ，也可从 USD 加载；在编辑器里以点云形态表示，Geometry Nodes 提供 Pointcloud Type，属性含 Position、三维 Scaling、四元数 Rotation，以及拆成 radiance:base / radiance:sh 的球谐辐射。Workbench / EEVEE 用光栅化投影为 2D billboard（EEVEE 初版走 dithered 透明，噪声需提高采样；Workbench 需 Flat 光照预览）；Cycles 对每条射线求与 splat 的最大不透明度交点并用随机接受做不透明，以兼容二次射线与 GI，并注明与 EEVEE 在透视/训练假设上会有细微差异。文中给出重光照、法线估计的早期做法与当前限制（EEVEE overdraw、编辑工具仍偏点云、重光照仍早期），并列出后续性能与工具改进计划。

Epic Office Hours：UE 5.8 MegaLights 入门（生产就绪、设置与调优）
