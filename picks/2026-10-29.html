AMD FSR SDK 2.4：ML 超分覆盖 RX 6000 / 部分 Ryzen APU，并补齐 Vulkan

AMD GPUOpen发布:2026-10-28
图形渲染工具

AMD 于 2026-10-28 发布 FSR “Redstone” SDK 2.4。ML 超分 FSR Upscaling 4.1.2 在既有 RX 9000（FP8）与 RX 7000（INT8）之外，把完整 INT8 模型扩到 RX 6000（RDNA 2）离散卡，以及 Ryzen AI Max 300/400（Strix Halo / Gorgon Halo）；另提供体积不到一半的轻量 INT8 模型给更受限的 Ryzen AI 9 300/400、Z2 Extreme、Z2 A 等 APU，模型按硬件自动选择。本版首次让 Upscaling 与 Frame Generation 在 Vulkan 上与 DirectX 12 功能对等（Ray Regeneration / Radiance Caching 仍仅 DX12）。Frame Generation (Swapchain) 4.0.0 在 RX 9000 + Adrenalin 26.10.1 等条件下可走 Driver-Assisted Frame Pacing；Ray Regeneration 1.2.1 增加独立 AO / specular occlusion 降噪。原文注明当前 UE 插件仍是 Upscaling 4.1.1 / FG 4.0.1，稍后才会跟到 4.1.2 / 4.0.2。厂商演示帧率与画质对比未在本机复现。

为什么有用

做跨端/掌机/AMD 机型兼容时，一次集成就能把 ML 超分铺到更老的 Radeon 和一批 APU，Vulkan 路径也不再落后。

值得试

从 GPUOpen / GitHub 拉 FSR SDK 2.4；Vulkan 标题需自行集成本版 DLL（驱动不会像 DX12 那样自动升级旧 FidelityFX 3.1）。UE 项目可先看现有 FSR 插件，并留意 OverrideSwapChainDX12 与 Frame Pacing 条件。

Godot：可在 XREAL AURA 上原生开发与发布空间应用

Godot Engine发布:2026-10-28
游戏开发工具

Godot 官方博文（2026-10-28）写明：XREAL AURA（Android XR 上的光波导透视眼镜）发售时，Godot 进入首发阵容。可在设备上下载编辑器与配套应用，在多窗口空间工作区里原生开发、导出并发布空间游戏/应用；编辑器亦可从 Google Play 安装（包名 org.godotengine.editor.v4）。新能力包括 OpenXR Spatial Containers（系统管理的空间内容容器）。Godot Foundation 正与 Blender Studio、W4 Games 合作，把 DOGWALK 移植到 AURA 的 Spatial Containers，计划年内发布——该移植进度属官方计划表述，尚未提供可玩构建。

为什么有用

若你跟 XR / 空间计算，这是较少见的「编辑器就在眼镜上跑」路径，也方便把既有 Godot 3D 项目迁到 Spatial Containers。

值得试

有 AURA 设备时从 Play 装 Godot 编辑器；桌面侧跟进 OpenXR Spatial Containers 文档，评估现有 3D 场景能否锚到桌面空间容器。

Epic 确认用 AI（含 Claude / Codex）写 Unreal 代码：烹饪非确定性等老问题被压住

Game Developer发布:2026-10-28
游戏开发前沿

Game Developer（2026-10-28）转述 Epic 开发执行副总裁 Marcus Wassmer 对 This Week in Video Games 的回应：Epic「确实在用 AI 开发 Unreal Engine 的代码与功能」；当前开发几乎都在 Fortnite / UEFN / UE6 相关分支，5.9「有可能」但是针对特定系统的相对小更新，且会包含 AI 参与的改动。Wassmer 称 Claude、Codex 等工具帮助几乎消除了他们对抗约十年的 non-deterministic cooking bugs，并用于自动盯 Fortnite PC 稳定性（驱动/硬件组合告警）。他说工程师不再写大部分代码，但仍控制架构与范围；并表示更担心「推进太慢」的风险。以上均为 Epic 管理层表述与媒体转述，未附独立复现数据。

为什么有用

直接关系到 UE6 / UEFN 路线和引擎侧 AI 工作流会怎样渗透到日常开发与稳定性预期。

值得试

对照自己项目的 cook 非确定性与补丁体积问题，看看是否已有社区/Epic 侧 AI 辅助排查实践；跟进 UEFN 与 UE6 公开说明里对 AI 工具链的更新。

GitHub (anthropics/claude-code)发布:2026-10-27
AI 工具效率

CHANGELOG / Release 标签 v2.1.312（约 2026-10-27）主要增量：Claude apps gateway 新增 oidc.user_id_claim（可用 Entra oid 等替代 sub）；全屏模式下可点击排队消息下的 “to send now” 立即发送。修复包括：VS Code 登录后托管设置/组织策略未在会话内刷新；Write 在只看到大 CLAUDE.md/规则/@ 文件开头时可能整文件覆盖——现会要求读全或就地编辑；Bash cd 到仓库更深层后找不到按目录 / paths: 的 skills；无效命令名导致全部命令加载失败（claude -p 无输出）；PDF Read 与会话清理竞态等。另有 hooks 并发上限（每会话最多 24，超时等待最多 12）、未识别自定义模型名默认短系统提示、用量文案改为 “5-hour limit” 等。以上摘自官方 changelog，未在本机逐项复测。
