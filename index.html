PerfGuard：World Partition 与流送——单元网格、HLOD 构建成本与专用服务器陷阱

把 WP 建模成按 Actor（OFPA）流送而非整子关卡：运行时网格的 Cell Size 与 Loading Range 决定内存与弹入风险；硬引用会跨格子触发 Grid Promotion，静默放大加载集，应用软引用控制。HLOD 层含 Instancing / MergedMesh / SimplifiedMesh 与 5.7+ Custom HLOD Actor；WorldPartitionHLODsBuilder 需 -AllowCommandletRendering 才能烘焙材质，大地图烘焙易 OOM，宜进 CI。Data Layer 负责叙事/难度/服务器专用内容。专用服务器默认整图常驻：需显式开 wp.Runtime.EnableServerStreaming 与 EnableServerStreamingOut；服务器通常可 wp.Runtime.HLOD.ForceDisable=1。调试用 ToggleDrawRuntimeHash2D/3D、DumpStreamingGenerationLog，Insights Loading Time 抓阻塞加载。

PerfGuard：Nanite 性能深潜——簇剔除、软/硬光栅与 Masked/WPO 成本

把 Nanite 当成独立光栅器而非“自动 LOD”：128 三角形簇经 DAG + 双遍 HZB 剔除后写入 VisBuffer，再走 NaniteRaster / BasePass / Shading。软件光栅负责约亚像素三角形（默认约 32 像素边长以下），硬件光栅吃大三角形；可用 r.Nanite.MinPixelsPerEdgeHW 与 MaxPixelsPerEdge 调交叉点。Masked、WPO、PDO、双面与顶点动画会把簇踢进可编程光栅箱，固定开销高；缓解包括改成不透明几何、设 WPO Disable Distance、限制 VSM 材质位置失效范围、ShadowCacheInvalidationBehavior=Static。还覆盖与 VSM 的耦合、5.6 Ray Tracing Proxy、流送池与 NaniteVisualize 调试清单。

Unity MethodReload：跳过 Domain Reload，设备上也能改方法体

Unity 发布实验包说明：MethodReload 在 com.unity.pipeline@0.7.0-exp.1（需 Unity 6.0+）。给方法打 [MethodReload]，启动 Watcher 后进入 Play Mode 或连接 Development Player，保存后只改方法体，由解释器注入，无需完整 Domain Reload。限制：只改已标记的方法体，不能改字段/类型布局；解释器是 C# 子集（无 await/try-catch/LINQ 查询语法等）；设备上只能调用玩家已暴露的 API（IL2CPP 剥离会影响）。官方对比：Asset Store 热重载在 Editor/Mono 更成熟，但 IL2CPP 设备侧这是文中强调的差异点。Release 构建中标记方法无序言、无解释器开销。文中标注流程可能随实验包变化。

官方文档：移动端 Mesh Auto-Instancing（GPU Scene，含 Mali 纹理路径）

移动端可开启网格自动实例化以合并 Draw Call：在 DefaultEngine.ini 设 r.Mobile.SupportGPUScene=1，并用 r.Mobile.UseGPUSceneTexture=1 把 GPU Scene 数据存进纹理而非 buffer，从而让仅支持约 64KB buffer 的 Mali 也能用。开启会触发移动端着色器重编。文档强调主要利好偏 CPU 瓶颈的项目；GPU 瓶颈收益可能不明显；若极吃内存可关 UseGPUSceneTexture 改回 buffer（但 Mali 会失去该特性）。要求结合真机 profiling 判断是否值得上线，并提醒除通用 Mesh Drawing 限制外还有移动端特有约束。
