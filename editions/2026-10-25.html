Arm：Opacity Micromap 降低植被光追阴影成本（Mali G2 + Moku，最高约 +31% FPS）

Arm 用 UE 样例 Moku 在 Mali G2 上评估 Opacity Micromap：把 alpha 遮罩植被的不透明度烘焙进加速结构，减少光追过程中的 any-hit/材质求值。七组参考机位 Off→On FPS 约 +5.9%～+31%（Ref2 最高）；Streamline 匹配负载下非不透明三角命中近乎归零、RTU active 约 −66.8%，内存带宽变化很小。文中说明 MegaLights 在 SM5 RQ 路径上缺材质求值会导致植被影缺失，并给出 EvaluateMaterialMode 0/1/2 与细分预览流程；强调需改引擎，非开箱即用。

    UE 5.8：MegaLights + GI Medium 下骨骼网格丢阴影（社区可复现修复）

    帖主指出 5.8 在 Global Illumination Medium 预设中关闭了骨骼网格的 Ray Tracing Geometry 与 Mesh Card 表示；开启 MegaLights 后角色不投影（推测默认阴影路径被替换后无可用回退）。会话内临时修复：控制台设 r.RayTracing.Geometry.SkeletalMeshes 1 与 r.MeshCardRepresentation.SkeletalMesh 1。永久修复：改 Engine/Config/BaseScalability.ini 的 [GlobalIlluminationQuality@1] 将上述两项从 0 改为 1。作者提醒这两项被关掉多半为省性能，重开会抬 CPU/GPU 成本。

PerfGuard：World Partition 与流送——单元网格、HLOD 构建成本与专用服务器陷阱

把 WP 建模成按 Actor（OFPA）流送而非整子关卡：运行时网格的 Cell Size 与 Loading Range 决定内存与弹入风险；硬引用会跨格子触发 Grid Promotion，静默放大加载集，应用软引用控制。HLOD 层含 Instancing / MergedMesh / SimplifiedMesh 与 5.7+ Custom HLOD Actor；WorldPartitionHLODsBuilder 需 -AllowCommandletRendering 才能烘焙材质，大地图烘焙易 OOM，宜进 CI。Data Layer 负责叙事/难度/服务器专用内容。专用服务器默认整图常驻：需显式开 wp.Runtime.EnableServerStreaming 与 EnableServerStreamingOut；服务器通常可 wp.Runtime.HLOD.ForceDisable=1。调试用 ToggleDrawRuntimeHash2D/3D、DumpStreamingGenerationLog，Insights Loading Time 抓阻塞加载。

PerfGuard：移动端性能深潜——Forward/Deferred 路径、分档预算与真机 profiling

移动端三条路径：Mobile Forward（默认、带宽友好）、Mobile Deferred（需 Vulkan/Metal + MobileHDR）、高端机桌面渲染器（约 3× 成本）。瓷砖 GPU 带宽敏感，MobileHDR 把 tile buffer 提到浮点代价大。Draw Call 参考 Epic 每视图 <700，文中给低/中/旗舰约 250/450/700 与三角形量级。r.Mobile.SupportGPUScene 只读，必须写进 DefaultEngine.ini。标准移动路径无 Lumen/Nanite/非 Nanite VSM，实用光照是方向光+CSM、角色动态点光、烘焙/DFAO。强调按 Adreno/Mali/Apple 做 Device Profile 继承、纹理池约设备可用显存 30–40%，以及 Snapdragon Profiler / Arm Performance Studio / Xcode Metal Capture 真机抓帧；并提示 UE 5.6 Mali Vulkan 描述符崩溃需钉版本或 GLES 回退。

UE 5.8.4 默认改用 UIScene：iOS 前后台回调可能静默失效

Indie Tooling 根据 Epic 5.8.4 热修说明：iOS/iPadOS/tvOS 客户端默认改用 Apple UIScene 生命周期。一旦采用 scene，UIKit 不再调用旧 app delegate 的 become/resign active、进后台/回前台等方法，即使代码仍实现它们——暂停、静音、存档、广告/归因 SDK 刷新若挂在自定义 delegate 或第三方插件上，可能不崩溃只是不跑。文中建议分支升级、全仓搜旧回调名、向插件厂商确认、真机测来电/锁屏/控制中心。另复述热修里 VS2026 .slnx、新 Apple 机型 profile、Lumen SceneCapture 等项。官方帖是否提供切回旧行为的项目设置，文中称未写明。

2026 年用 UE5 做手游还现实吗？路径选择、可扩展档与商店约束

结论：UE5 适合视觉要求高的中重度、已有 UE 经验或要跨 PC/主机同代码的团队；普通手机走专用移动渲染路径，Lumen/Nanite 面向更高端而非典型机型。建议按市场数据定低/中/高档并做 Scalability，从原型起就在最低档真机测（热节流模拟器看不出）。包体用 Android Play Asset Delivery / iOS On-Demand Resources。文中提醒 Google Play 对新应用/更新要求 target Android 16（API 36），Epic 对 5.7 曾建议 target SDK 35，发版前需核对当前引擎工具链。变现侧 UE 官方 SDK 少于 Unity；清单强调先定最低机、不依赖 Nanite/Lumen 做主路径、提前规划分包。
