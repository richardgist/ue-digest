官方：UE 5.9 Preview 2 已发布，移动端 Deferred 单 Pass 光照与 Web 移动档画质改进

官方 @UnrealEngine 于 2026-11-19 22:07（香港时间）宣布 5.9 Preview 2 已推出：仅蓝图项目也可把 Web 作为目标平台，AI 辅助工作流默认开启，并指向同日更新的官方发布说明（页面标注 Last updated 11/19/26）。发布说明中此前未在日报展开的渲染/移动端改动包括：移动端 Deferred 可用 r.Mobile.DeferredLighting.SingleShadingModelPass 在单次光照 Pass 里照亮所有 lit shading model；新增默认关闭的 r.Mobile.DeferredLighting.CameraInsideLightDepthTest，在相机位于本地光源几何内部时对光源背面做深度测试；没有 build data 的 Mobile Reflection Capture 不再渲染成黑色。方向光 Virtual Shadow Maps 增加投影与页管理优化，以及 Stochastic PCSS（接触处更硬、远处更软），并修复阴影投影进行中把 r.ShadowQuality 降到 0 会崩溃的问题。Web 方面，移动档改用引擎默认抗锯齿 TAA（不再用 FXAA），Deferred 档启用 Extended GBuffer，使清漆、贴花法线与材质环境光遮蔽能完整呈现；手机/平板会优先加载更轻的 ASTC 纹理集，各设备只下载所运行档的着色器数据，默认把帧率限制在显示器刷新率以省电散热。Preview 2 还规定：项目未设置帧率上限时改用平台默认上限；未使用的遗留 Reflection Capture 不再随地图构建数据一起 cook/转存；Lyra 的 Web 移动档用纹理与天空光上限把流送控制在预算内。该 Preview 仍是预览构建，官方建议用项目副本测试。

    论坛：UE 5.8 体积雾 tricubic 过滤把 h0.z 写错，Quality 2 会采到错误深度（含修复建议）

    作者 @Ruben_designer 报告：将 r.VolumetricFog.Filtering.Quality 设为 2（tricubic）时，HeightFogCommon.ush 的 SampleVolumetricFogFiltered() 会采到错误深度。B 样条准备段在 bicubic 与 tricubic 共用后以 h0.z = VolumeUV.z 结尾，这对只在 XY 过滤、Z 上按原始深度线性采样的 bicubic 是对的；但 tricubic 分支也会用 h0.z / h1.z 与 g0.z 做 lerp，等于在 Z 上把未过滤深度与 B 样条偏移后的 h1.z 混合，过滤是错的。复现步骤：加 Exponential Height Fog（体积雾）和带 volumetric scattering 的聚光灯，设 r.VolumetricFog.Jitter 0 让边缘静止，在锥体边缘对比 Quality 0、1、2。作者观察 Quality 2 看起来与三线性差不多甚至更差（聚光灯边缘的 froxel 台阶仍在），Quality 1 才能正确抹平。建议把 h0.z = VolumeUV.z; 移进 PERMUTATION_VOLUMETRIC_FOG_FILTERING_QUALITY == 1 分支，让 tricubic 保留计算出的 h0.z；并指向 GitHub PR #15392。原文标注影响 UE 5.8、Windows，发帖时没有 Epic 回复。

论坛：UE 5.8.4 macOS 异步删除 RDG 图时，Nanite Materials 更新器会写入下一帧 FSceneCullingBuilder 并触发断言（含已验证变通）

DOOM-GS：面向大规模动态高斯溅射的核外训练框架，并发布 DynamicMatrixCity 数据集（论文）

Doğa Yılmaz、Jialin Zhu、Binglun Wang、He Wang 的论文于 2026-11-17 提交 arXiv（编号 2611.22805），并出现在 2026-11-18 的 cs.GR 新稿列表。作者认为既有核外（out-of-core）高斯溅射训练主要针对静态场景，而动态高斯会随时间移动且只在有限时段有效，会破坏按静态空间局部性分块和“单视图可见图元总能放入 GPU”的假设。文中提出 DOOM-GS，自称是首个专门面向大规模动态高斯溅射的核外优化方法：用时空分块与重叠感知的相机调度管理缓存与传输，并把原先只用于推理的 Gaussian Point Splatting 改成可学习渲染，使单视图关联图元超出 GPU 显存时仍能训练。因缺少合适公开基准，作者基于 MatrixCity 的 Small City 地图加入程序化行人与车辆，发布 DynamicMatrixCity，含 Corner（80 m×80 m）、Block（260 m×150 m）、District（1,870 m×1,500 m）三个尺度，每台相机 120 帧、30 fps、1920×1080。在与改成动态表示的 TideGS（Dynamic TideGS）对比中，双方均优化 2,000 万高斯、1,800 个块的 GPU 预算（约合 740 万常驻高斯）：作者报告持有相机上平均 PSNR 在 Corner / Block / District 分别为 24.93 / 23.19 / 19.35，对比基线 15.60 / 9.28 / 10.19，训练时间分别为 15.9 / 37.2 / 228.5 小时，对比 29.5 / 54.2 / 317.4 小时，峰值显存在 District 从 20.5 GB 降到 12.6 GB。与按帧训练的静态核外方法相比，作者用一个 250 万高斯的动态模型覆盖整段 120 帧，而基线是 120 个模型共 3 亿高斯，并称相对最稳定基线把 flicker 在 Corner / Block 分别降到约 1/7.1 和 1/6.3。上述“首个”、质量与耗时数字均为作者在自建合成数据上的实验结论，本机未训练、未复现；摘要与 HTML 全文未见官方代码仓库。

One Code per Material：用 256 维码表示实测 BTF，并可在共享解码器上采样新材质（论文）

剑桥大学 Fazilet Gokbudak、Canberk Baykal、Chenliang Zhou、Rafal Mantiuk、Cengiz Oztireli 的论文于 2026-11-17 出现在 arXiv cs.GR 当日列表（编号 2611.20948）。作者指出，实测双向纹理函数（BTF）能记录视差、自阴影和互反射等解析 SVBRDF 难以表达的外观，但单次测量体量极大，而且每种新材质都要重新采集；已有神经 BTF 多用每纹素潜在图，而不是把材质放进可采样的共享空间。文中给出两个工作点：按材质的坐标网络，在匹配体量下相对 Xia 等人最近的神经 BTF 提高 3.2 dB PSNR，并称在所有指标上优于既有基线；紧凑模型用一个 256 维码条件化共享解码器来表示整份材质，作者称其 PSNR（+1.2 dB）和颜色精度超过 Rainer 等人的每纹素潜在图，但每个材质只需 256 个数而非数百万个数，且解码器为所有材质共用。由于每个材质是该码空间中的一个点，作者再在 84 种材质并经 colourways 与色相旋转扩充的数据上训练类别条件 flow，用于采样新材质，并由同一解码器渲染、重打光为完整 BTF。上述对比数字与生成效果均为作者实验结论，本机未训练、未复现，也未在摘要可见部分找到官方代码仓库。

Pose-based Neural Clothing：面向动画角色、可实时交互摆姿势的神经服装（SCA 2026 论文）

DisneyResearch|Studios、ETH Zürich 与 Pixar Animation Studios 的论文《Pose-based Neural Clothing for Animated Characters》于 2026-11-13 提交 arXiv（cs.GR），注释写明已被 ACM SIGGRAPH / Eurographics Symposium on Computer Animation（SCA 2026）接收，并将发表于 Computer Graphics Forum。针对传统服装模拟速度慢、调参费时，以及现有神经服装方法多在写实人体（如 SMPL）数据上表现较好、在动画角色数据上对未见姿势泛化较差的问题，作者设计网络与训练策略，以便在实时条件下更好地泛化到未见姿势，支持交互式摆姿势。设定是面向制作流程：为单件服装、在准静态条件下训练。方法先训练变分自编码器（VAE）得到平滑且有表达力的隐空间，再逐步把 VAE 编码器从重建过渡到由姿势驱动的预测；预测同时以低维姿势参数和角色体表位移为条件。此外提出一种局部梯度直方图损失，用于减轻重建损失造成的过度平滑。论文称在制作级资产和公开数据集上，该方法能实时生成清晰真实的褶皱、平滑的大尺度垂坠，并保持时间连贯。文中测量：在 Jen’s Shirt 数据上推理速度为 212.2 FPS，实验在 NVIDIA GeForce RTX 4070Ti 上进行；还与 Maya 2025.2、Unreal Engine 5.6 以及若干已有神经方法做了误差与观感对比，并报告用户研究中 96.3% 的投票更偏向该方法。这些速度、误差和用户研究数字均来自论文，本机未复现训练或推理。碰撞处理在推理时于变形之后进行，作者称只做小幅修正。准静态假设对非常松弛、动态很大的服装仍可能吃力，文中也提到在 VTO 等数据上各方法都可能出现过平滑或高频伪影。

DIRT：用深度补全与双频段混合做无需训练的实时新视角合成（论文）

Friedrich-Alexander-Universität Erlangen-Nürnberg 的论文《DIRT: Depth-completed Image-based Rendering using Two-band Blending for Live Novel-view Synthesis》于 2026-11-13 提交 arXiv（cs.CV，交叉列出 cs.GR）。针对多数新视角合成方法需要按场景优化、难以用于拍摄过程中的实时（live / ad-hoc）合成，作者提出一种传统图像绘制路线：输入是带位姿的深度传感器观测和图像，不使用神经网络，也不做场景优化或训练。流程是：把主动传感器得到的稀疏点几何投影到目标视角的屏幕空间，在该深度缓冲上做层次化深度补全；再把若干带位姿的图像投影到该代理几何上并处理遮挡；最后用考虑频率的双频段混合，并以近似距离变换作为混合权重。因此在捕获与新视角绘制之间不必等待按场景训练，也不依赖网络对未见场景的泛化。作者在手持 RGB-D、车载 LiDAR、热成像以及低光照等设置上做了验证。实验在同一台机器上进行（Intel i9-12900、NVIDIA A5000 24 GB、64 GB 内存），主要延迟指标定义为最后一路输入传感器数据到达至合成测试视角之间的 capture-to-image 间隔，质量指标为 PSNR 与基于 AlexNet 的 LPIPS。论文称在实时重建场景上优于所比较的先前方法，在常规离线新视角基准上保持有竞争力的结果；例如 Table 3 在 LiveNVS 数据集、使用已采集的立体深度时，作者方法报告 LPIPS 0.1987、每张图 8.51 ms，对照 nvblox TSDF 融合为 0.2438 / 74.39 ms。这些数字和“优于先前方法”的判断均来自论文实验，本机未复现。该方法依赖带位姿的深度观测，不是无位姿纯 RGB 方案。

Bermano、Derek Nowrouzezahrai、Markus Gross 与 Marios Papas 的论文 Neural Render Proxies for Interactive and Differentiable Lighting，于 2026-11-12 提交到 arXiv（2611.17185v1，cs.GR）。页面标注该文属于 2026 年 Eurographics Symposium on Rendering（Computer Graphics Forum 第 45 卷第 4 期，编辑 I. Gkioulekas 与 A. Jarabo）。方法针对灯光环节里几何、材质和相机已固定、但每次微调灯光都要用离线渲染器重跑全图的情况：把渲染拆成一次与灯光无关的路径采样，以及之后按灯光参数计算发光。先从相机按 BSDF 重要性采样（不含 Next Event Estimation）缓存路径数据，再训练一个场景专用的轻量网络，学习从场景中任意位置到像素的光传输；推理时只随分辨率和灯光数量、参数规模变化，而不随场景与外观复杂度增长。作者写该方法可与不可微的生产渲染器配合：制作场景用 Walt Disney Animation Studios 的 CPU 渲染器 Hyperion 采集路径，学术场景则另做采集。摘要给出的交互式重打光帧率为约 30–60 Hz，并接近路径追踪参考；网络可微，因而可用图像空间编辑或生成式目标，对灯光参数做基于梯度的反求。实现基于 PyTorch 与 tiny-cuda-nn。作者在一块 RTX 5090（32 GB 显存）上报告：标准配置（680×680、512 spp、8 层×256 神经元）训练 10 万次迭代约 1 小时；Kitchen 场景（885×500）上，256/8 网络推理 9.13 ms、模型 7.4 MB，512/8 为 31.21 ms、13.3 MB。用与灯光无关的 64 spp 路径数据训练时，色调映射空间的平均 PSNR 仍比最多 1024 张图的基于图像基线高 2.8 dB。限制包括：机位与材质需固定；训练后不能再改物体间的非物理衰减或灯光独占（分层 NRP 只能近似后者）；遮挡腔体可能欠采样；路径数据需预载进显存。上述帧率、耗时、显存和 PSNR 均来自论文，本机未训练或复现。

CORTAO：开源的基于圆形遮挡体与屏幕空间光线追踪的实时 SSAO，可作为引擎原有 SSAO 阶段的替换

Fenris Creations（EVE Online / EVE Frontier）于 2026-11-12 宣布开源 Circular Occluder Ray-Traced Ambient Occlusion（CORTAO），作者是高级渲染工程师 Daniel Isheden。参考实现仓库 theagentd/CORTAO 的 README 版本记录写 1.0.0 初始发布为 2026-11-05，随后在 11-13 到 11-15 发布了 1.0.1–1.0.3 的修复；仓库采用 MIT 许可证。技术说明把 CORTAO 定义为基于屏幕空间光线追踪的物理实时 SSAO：从深度缓冲采样，把像素邻域近似成圆形遮挡体，再对这套代理几何求交，并用预计算查找表追踪每像素最多 32 条光线，同时可计算 bent normals。作者用它对照 GTAO（Jimenez 等，2016），认为水平线方法在倾斜、不正对相机的表面上会偏斜，难以收敛到暴力光线追踪参考；这些准确性、稳定性以及“以更少样本达到更高质量”的说法来自仓库 README 和公司稿，本机未复现。仓库给出的作者测试结论包括：简单场景中，CORTAO 用不到一半的 GPU 时间达到与 GTAO 相当的精度，或在相同 GPU 时间预算下平均平方误差最多低约 4 倍；复杂场景中，在更低样本数下平均平方误差明显更低，并在提高样本数后收敛到比 GTAO 更低的误差。仓库还写：着色器提供 HLSL 与 GLSL；已测试可在 DirectX 11（需 Shader Model 6.7 的变通）、DirectX 12、OpenGL 4.3+ 和 Vulkan 1.0+ 上直接使用；HLSL 完整路径的最低要求是 Shader Model 6.7。实现分 prepass、main pass 和可选的空间滤波 pass，用于给后续时间滤波做准备；仓库目前不自带时间滤波，需要引擎侧另行接入。面向 Carbon 引擎、针对大深度范围太空场景的精简实现另在 carbonengine/CORTAO。公司稿称该技术已在开发中的 EVE Frontier 中测试，并设计为替换引擎现有的屏幕空间环境光遮蔽阶段。本机未编译或跑分。

MatrixSplat：把高维特征 3DGS 渲染映射到 GPU Tensor Core 的矩阵并行框架（论文）

5.9 新文档介绍 Lumen World Cache：默认关闭，仅在 Lumen 走硬件光追时生效；开启后该视图完全替换 Surface Cache（不再捕获/照明/驻留 mesh cards）。缓存按距相机的稀疏世界空间格子存储（默认约 10 米处每格约 25.6 cm，并按主朝向分条目），每帧从屏幕每 8×8 像素块随机取一点、最多 3 次反弹填入，格子最多平均 16 帧，64 帧未命中则回收。开启方式是在 DefaultEngine.ini 写入 r.Lumen.WorldCache.Supported=1 并重启；还要求 Hardware Ray Tracing Mode 为 Full 或 Simplified Material（Inline 不可用），且 r.Lumen.WorldCache.Allowed 保持开启（默认真，可作分档开关而不重启）。文档列明限制：软件光追仍走 Surface Cache；半透明不入库；暂不支持 Water、光追半透明、植被/次表面透射，以及 Far Field。GPU 耗时可在 stat gpu 的 LumenWorldCache 项查看，默认可走 async compute。

Auto SR Officially Launches on ROG XBOX Ally X and X20, Expands to Copilot+ PCs powered by AMD Ryzen

Microsoft DirectX 博客于 2026-11-10 宣布 Automatic Super Resolution（Auto SR）在 ROG XBOX Ally X 与 ROG XBOX Ally X20 上结束预览、正式推出，并扩展到部分搭载 AMD Ryzen 的 Windows Copilot+ PC。文中列出四项能力：手持/未扩展坞、用电池时也可在内置屏使用（预览期仅限扩展坞）；游戏以 1080p 运行时也可启用（预览期需先降低分辨率，扩展到更高分辨率电视/显示器时可升到 1440p）；可与 Auto HDR 同时使用（以前二者只能二选一）；以及新的 Performance Mode，把此前约 60–75 FPS 的上限提到最高 120 FPS。文中明确：手持模式、AMD Ryzen Copilot+ PC 扩展和 1080p 支持即日起可用；Performance Mode 与 Auto HDR 兼容会随 Windows 更新推出，到达各设备的时间可能不同。1080p 手持内置屏下，文中也写性能可能不如其他配置，但在较老游戏上仍可能看到画质改善。厂商配了 Rocket League 在 Ally X、720p、游戏内高画质下的截图：Quality Mode 约 70 FPS，Performance Mode 约 115 FPS——这是 Microsoft 自己的测量，本机未复现。启用步骤：更新 Game Bar 与最新 Windows 11，从 Microsoft Store 下载或更新 Auto Super Resolution 包，打开 Game Bar（Win + G）到 Widgets > Display > Graphics，在 Quality 与 Performance 之间切换。

UE 5.9 Preview 发布说明：Nanite 剔除改进、AVBOIT 半透明排序与阴影调试视图

官方 5.9 Preview 发布说明（Rendering & Lighting 节）补充了除 World Cache 以外的渲染改动：Nanite 剔除会把实例分成简单与复杂两类（蒙皮、样条变形、WPO 等分开处理），并可在单步中测试网格细节层级的多层；场景自动受益、无需改资源，收益随场景规模增大。AVBOIT（文中亦写作 ABVOIT）按正确混合重叠半透明（玻璃、烟、粒子），不依赖绘制顺序，同时适用于 Nanite 与非 Nanite 半透明，可处理彩色玻璃，并跳过完全不透明烟雾后方的像素；半透明材质需只输出自身颜色。阴影调试新增 Virtual Shadow Map Overview 并排视图、CSM 级联着色与深度分块视图、Far Shadow 高亮，并支持远影按独立频率更新、按组件在蓝图/代码中开关远影投射。
