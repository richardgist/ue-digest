Rider 2026.3：Lua / Verse 插件、Godot 场景联调，以及 Unity CoreCLR 与 UE 调试改进

JetBrains 于 2026-11-11 发文介绍 Rider 2026.3 面向游戏开发的更新：更紧密对接 Godot Editor、改进 Unreal Engine 与自定义 C++ 引擎调试、新增对 Unity CoreCLR Player 的调试支持，并推出仍处 Beta 的 Lua 与 Verse 插件。Lua 插件由 JetBrains 维护，支持 Lua 5.1–5.4、LuaJIT 与 Luau，提供补全、文档、参数信息、inlay hints、35 项以上带 quick-fix 的检查、导航 / Find Usages / 调用层次与 require 路径解析，以及 Rename、Extract Function、Inline、Change Signature 等重构和可配置格式化；并识别已有的 EmmyLua、LuaLS、LDoc 注释和 Luau 类型注解。Verse 插件用 Rider 自有语言引擎，不依赖外部 language server，提供高亮、错误检测、补全、导航、Find Usages 与 Quick Documentation，这些能力也可经 Rider 的 MCP server 提供给 AI agent；UE6 项目可打开 .sln 或 .uproject 在同一项目里处理 C++ 与 Verse，也可打开生成的 .code-workspace 做更轻的 Verse 工作区。文中写明跨语言（C++↔Verse）导航尚未支持，两个插件均需在 JetBrains Marketplace 安装 Beta。内置命令行参数预设取代 EzArgs 插件：可整理为预设并从主工具栏选用，独立于运行配置，可在 Debug/Release 间复用，并支持从已有命令行导入、经版本控制或 XML 在项目间共享。Godot 方面，安装并启用 Godot Asset Store 中的 JetBrains Rider Integration 插件后（连接服务随 Rider 提供），可在 C# 或 GDScript 下调试当前场景；C# 场景经 Godot Editor 启动且 Rider 调试器从第一帧挂上，可用编辑器内嵌游戏窗口暂停或调速。命中断点后可查看 autoload、活动场景与节点层次并检查节点属性，无需额外设置即可出现场景树；GDScript 还增加悬停查看变量、Add to Watches，以及 Immediate 窗口的表达式补全，大数组/字典可分页浏览。Unity 方面，可附加并调试 Unity 6.7 的 CoreCLR 桌面 Player；文中同时写明 CoreCLR Player 仍是实验性技术预览，6.7 编辑器（含 Play 模式）仍使用 Mono，并对 Unity 7 Alpha 的 CoreCLR 编辑器提供早期支持，Unity for Agents 则预告将在 2026.3.1 介绍。C++/UE 侧新增 Natvis 热重载：可在调试会话中编辑并重载已加载的 .natvis，无需重启游戏；还写了对 UE 的 TMap/TSet 检查更可靠、表达式求值与 visualizer 元素支持有所扩展，以及 UE 项目调试器启动更快——后几项是厂商对体验的说明，本机未对比。Windows 上对 MSVC（含 UE 项目）改用原生步进实现，并称 Step Into/Over/Instruction 更快、更一致，同时修复了停在错误位置或留下内部断点的问题。数据断点可在编辑器里对变量右键设置，或在 Breakpoints 对话框用变量名/内存地址添加，并支持条件、日志和读/写触发；AI agent 也可通过 Rider MCP server 设置数据断点。另有基于 LLDB 21 的实验性调试器（Windows/macOS/Linux 可选），以及同步 Visual Studio 逻辑结构的实验性 .vcxproj.filters 支持。本机未安装 2026.3 验证上述功能。

    Unity：6.7 将弃用烘焙遮挡剔除，并说明 GPU / 小网格剔除的现状与后续方向

    Unity 图形团队工作人员 ElaineK 于 2026-11-09（UTC 09:41）在官方论坛发帖，说明剔除工作的现状与后续方向，并写明当前重点是先改进已上线能力、再加新功能。烘焙遮挡剔除（基于 Umbra 中间件）将在 Unity 6.7 弃用：团队表示这是较旧技术，无法再更新或带到新平台，且与 GPU-driven 路径配合不佳——经 GPU Resident Drawer 绘制的物体可被烘焙数据隐藏，但不能作为遮挡物去隐藏其他物体，检测也更低效；烘焙之后新创建的物体同样不能遮挡其他物体。新项目不再显示烘焙遮挡剔除 UI，已启用 Umbra 的项目会在 Occlusion Culling 窗口看到弃用提示（原文写作 depreciation）；既有项目在 6.7 生命周期内仍可继续使用，文档也会加上弃用说明。GPU 遮挡剔除仍在开发中：适用于经 GPU Resident Drawer 渲染的内容，在极密实例化场景表现很好，但在高度独特内容上可见性检测的开销可能大于收益，因此除非场景实例非常密集，一般建议先关掉；团队也在改进 GPU Resident Drawer，让 GPU 遮挡剔除能覆盖更多内容。小网格剔除已在 Unity 6.6 通过 GPU Resident Drawer 提供：可设屏幕尺寸阈值，过小的物体不再提交渲染，阴影投射物也可按 cascade 设各自阈值。文中还列出仍在调研或规划、尚未作为已交付功能保证的方向：更多 GPU-driven 剔除、扩大移动端 GPU 兼容、面向移动端架构而非从桌面移植的遮挡剔除、阴影灯在无相关变化时跳过冗余剔除、分屏/小地图/瞄准镜/镜像等多摄像机以及 XR 中几乎完全重叠的视图共享剔除工作，以及让剔除可脚本化（按相机控制，或插入自定义遮挡/预计算可见性等逻辑）。这些是团队计划与向开发者征询，不是已经发布的能力。本机未在 Unity 6.6/6.7 中实测上述选项。

    War Thunder Eagle’s Shadow 新渲染（其二）：局部色调映射、天空遮挡与粗糙金属 BRDF

    Gaijin 于 2026-11-11 发布 Eagle’s Shadow 新渲染系列第二篇开发日志，介绍光照、阴影与金属反射方面的改动，并配有新旧对比图。此前全屏只用一个曝光值；现在的局部色调映射会把画面各区域亮度与整帧比较，较暗区域轻轻提亮、较亮区域稍压，并加一点局部对比以免发平。每个区域的调整被限制在上下各一档（one stop），且区域亮度会跨帧跟踪并跟随相机和移动物体，避免转头或车辆穿过亮区时曝光跳动。文中写局部色调映射可用于所有抗锯齿模式；Max 与 Movie 画质预设默认开启，其他预设需在图形设置的 Render 栏手动打开。天空遮挡方面，环境光遮蔽此前假定周围光照均匀、未考虑开阔天空下大部分光来自上半球；现在会区分物体是否在建筑内：室外天空遮挡最强，室内稍软，使房间顶部更暗、窗口附近更亮。显示曲线在把 HDR 结果转到屏幕颜色时做了调整：最深阴影和偏低中间调被抬高以保留细节，偏高中间调对比稍增，纯白保持纯白；适用于所有画质预设和所有平台的标准动态范围输出，HDR 输出不变。金属与反射方面，团队称原 BRDF 未计入粗糙表面在锐角下的多次反弹，粗糙金属和刮痕漆面会因此损失最多一半的反射光，现已补回，坦克装甲或飞机蒙皮等粗糙金属在低角度会更亮；还修复了阳光阴影里表面反射偏暗的问题，使低角度的地面/道路反射天空和墙壁而不是自身，并让潮湿与积雪表面的反射按文中所说正确工作。文中称显示曲线调整和反射修复「几乎不占用系统资源 / 没有性能开销」，这是开发商自己的说明，本机未实测。相对本站 11-10 收录的同一更新 DLSS 5 访谈，这篇写的是色调映射与材质反射，不是超分。

Blender 5.3：原生 3D Gaussian Splats、视口 DLSS 4.5 降噪与可选项目系统

Blender Foundation 于 2026-11-10 发布 5.3.0 正式版（官网发布页与新闻稿均写 Initial release / November 10th, 2026）。相对本站 11-10 收录的 Cycles RC 说明，这是已出包的稳定版介绍，并补上 3DGS、EEVEE 与工作流改动。头牌是原生 3D Gaussian Splats：可从 PLY、SPZ 和 glTF 导入为点云，用 Geometry Nodes 处理，并在 Workbench、EEVEE 与 Cycles 中渲染；默认用自发光着色，文档称把 Emission 换成 Diffuse 等硬表面 BSDF 可做「初步」的可重打光，同时写明性能仍在优化，且因多数制作工具用 sRGB、Blender 用线性色彩，低透明度、高辐射区域可能出现不准。视口新增 DLSS 4.5 Ray Reconstruction 降噪器，通过超分并复用先前帧样本；位于渲染属性 Sampling 的 Denoise 面板，需要 NVIDIA 驱动 620 或更新；并写明对运行 Windows 11 的 NVIDIA RTX Spark 提供原生支持（含内存优化）。Cycles 方面 Principled BSDF 增加色散（对应 OpenPBR v1.1.1），Glass BSDF 与 Principled 透射分量支持粗糙度各向异性。EEVEE 新增 Material Lighting 节点（Light Accumulation / Light Info / Light Evaluation / Shadow Raycast 等），并支持全景相机；当前实现尚不支持景深、光线追踪，以及视口里体积的时间重投影。另外还有可选的项目系统（项目级资源库与色彩管理等）、把 Asset Library 作为扩展分享、合成器效果栈，以及视频序列编辑器的 ripple 编辑框架、重写的 Blade 工具和初步 OpenTimelineIO 支持。同期新闻稿还写 Vulkan 现为 Windows（ARM 除外）与 Linux 的默认后端，Workbench 可在 Metal 与 Vulkan 上使用硬件光线追踪阴影；本条链接是功能介绍页，该后端变化以新闻稿为准。本机未安装 5.3.0 验证。

Epic 文档：Lumen World Cache——运行时路径追踪缓存，可替代网格 Cards 的 Surface Cache

5.9 新文档介绍 Lumen World Cache：默认关闭，仅在 Lumen 走硬件光追时生效；开启后该视图完全替换 Surface Cache（不再捕获/照明/驻留 mesh cards）。缓存按距相机的稀疏世界空间格子存储（默认约 10 米处每格约 25.6 cm，并按主朝向分条目），每帧从屏幕每 8×8 像素块随机取一点、最多 3 次反弹填入，格子最多平均 16 帧，64 帧未命中则回收。开启方式是在 DefaultEngine.ini 写入 r.Lumen.WorldCache.Supported=1 并重启；还要求 Hardware Ray Tracing Mode 为 Full 或 Simplified Material（Inline 不可用），且 r.Lumen.WorldCache.Allowed 保持开启（默认真，可作分档开关而不重启）。文档列明限制：软件光追仍走 Surface Cache；半透明不入库；暂不支持 Water、光追半透明、植被/次表面透射，以及 Far Field。GPU 耗时可在 stat gpu 的 LumenWorldCache 项查看，默认可走 async compute。

Grit：在导出时把 GDScript 编译成原生 C++ 的实验性 Godot 模块

Grit 是面向 Godot 4.7 的引擎模块，在导出时把项目里的 GDScript（含嵌入场景/资源的内置脚本）编译成 C++，再编进自定义导出模板，使导出后的游戏以本地机器码而不是字节码运行；编辑器里的编写、运行和调试仍走原来的 GDScript VM，无法处理的函数会按函数静默回退到 VM。仓库 README 以 2026-11-09 的置顶说明回应近期关注：项目并未停掉，目前主要缺测试，作者表示若 Godot 4.8 发布会跟进兼容。许可证为 MIT。文档把项目标为「高度实验性」：需要打过补丁的 Godot 4.7.2 与自定义导出模板；已在 Linux x86_64（GCC/Clang）和 Windows x86_64（MSVC）上验证 Godot 自带 GDScript 测试套件全部 1540 个函数可编译、499 条断言在原生执行下通过，macOS、移动端和 Web 未经测试；并写明暂时不要用来出货，且应保留回退到常规 VM 的办法。作者在 AMD Ryzen 9 7950X3D、Linux、GCC 16、发行版导出模板上，用同一二进制对比 VM（GRIT_DISABLE=1）与 Grit：带类型的整数循环 sum_to 为 196.3 ms 对 4.0 ms（约 49.1 倍），Vector2 与数组的 particles 为 31.7 ms 对 7.5 ms（约 4.2 倍），字符串拼接与创建/销毁节点几乎没有收益（约 1.0–1.1 倍）；附带的 Flappy 测试在无头自动驾驶 12 万物理步时，文档写目前原生大约快 2.5 倍。这些是作者在其基准项目上的测量，本机未复现。可选的脚本剥离（strip_scripts）会去掉已编译函数的函数体，剥离后的游戏不能再回退到 VM，且必须与同一次导出编出的模板配对。

在 8 GB 笔记本上自测 UE 5.8 Lumen Lite 与 MegaLights 的 GPU 耗时

作者在 RTX 4070 Laptop 8 GB（驱动 610.62）上，用 UE 5.8.1 编辑器视口（约 2118×1271、TSR、DX12 SM6、硬件光追）搭建 16 m 房间、48 盏可投阴影点光，每条件记录约 400 帧、取三次中位数。同开 MegaLights 时，GI Epic（Lumen 高质量）9.18 ms、GI Medium（Lumen Lite）6.87 ms，约少 25%；GI Epic 下关闭 MegaLights 为 11.69 ms，开启约少 21%。该场景最快组合是 Lumen Lite + MegaLights（6.87 ms），与完全关闭 GI 的 6.91 ms 几乎相同；测完后整卡占用约 2727 MiB / 8188 MiB。文中说明 Lumen Lite 在 5.8 仍为 Beta，需把 Global Illumination 与 Reflections 同时设为 Medium；关闭 MegaLights 时出现 VSM one-pass projection 每像素灯数溢出警告，开启后警告消失。作者强调这是编辑器视口、单场景结果，打包或户外植被场景数字可能不同。
