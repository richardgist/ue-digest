VideoRNG：用生成式视频模型做出可重打光的神经高斯资产（论文）

Bowen Xue、Saeed Hadadan、Fabrice Rousselle、Ravi Ramamoorthi、Zahra Montazeri、Miloš Hašan 的论文于 2026-11-19 提交 arXiv（编号 2611.25338，学科 cs.CV、cs.GR；作者单位包括 NVIDIA、University of Manchester、UC San Diego）。作者认为网格加紧凑 PBR 材质难以表达细几何或复杂光传输带来的外观，而现有高斯溅射生成方法通常把固定光照烘焙进外观。VideoRNG 是一个两阶段方法：先把预训练视频扩散骨干微调成视频生成器，在已知位姿、相机和光照下生成结构化 RGBA 转台序列；再用从预训练视频扩散骨干初始化的前馈重建模型，把选定转台帧的 video-VAE 潜变量直接映射到带学习神经外观特征的数百万各向异性高斯。共享方向解码器和随机高斯光线追踪器把该表示（文中称为 rtRNG）变成新视角和新光照下的辐射。为在学习几何时保留高频外观，作者引入 depth-anchored appearance training，并用前景 token 选择和代价感知的分布式采样来降低百万级高斯重建的开销。论文摘要称该方法可由文本提示或单张图像生成完整、可重打光的 3D 资产，并展示毛皮、羽毛、蛛网等可交互渲染、重打光并放入场景的例子。图 1 说明中，作者报告在 NVIDIA RTX A6000 上、每资产解码器隐层宽度 64、1280×720、1 spp 时每帧约 50 ms；该耗时为作者实验数据，本机未复现。arXiv 摘要页没有 Comments 字段，也未见官方代码仓库或项目主页。

    论坛：UE 5.8/5.9 摄像机切镜帧上，TSR 未写入的 mip 1 会让 Tonemap 采到过期画面（含修复建议）

    作者 @Michael.Edwards 报告：在开启 TSR、运动模糊且 r.MotionBlur.HalfResInput=1（默认）时，摄像机切镜的那一帧画面边缘会出现一帧旧画面残影；把抗锯齿改成非 TSR，或设 r.MotionBlurQuality=0，残影会消失。根因是 5.8 起 TSR 会为运动模糊预过滤分配半分辨率 mip 1，但写入与分配是分开的：PassInputs.bGenerateOutputMip1 决定分配，还要加上 PassConfig.MotionBlurValidInCurrentFrame 才写入。切镜帧上 View.bCameraCut 或 View.bPrevTransformsReset 会使 MotionBlurValidInCurrentFrame 为假，于是 mip 1 仍占用池化纹理里的旧内容（常常是另一台摄像机的画面），输出 SRV 却覆盖两个 mip。切镜帧会跳过运动模糊，Tonemap 直接采样 TSR 输出；色差等会放大 UV 的导数 LOD，在屏幕边缘把过期的 mip 1 混进来。作者用 RenderDoc 确认切镜帧上 TSR.History.Color 的 mip 1 是旧帧，下一帧 mip 1 被重新写入后画面恢复。建议在未写入 mip 1 时把输出 SRV 限制为 mip 0，或在已分配时始终写入 mip 1，或让 Tonemap 用 SampleLevel(..., 0)。原文询问是否已在后续改动中修复、能否进 5.8.x 热修或 5.9；发帖时没有 Epic 回复。平台为 Windows。

    论坛：UE 5.8 部分 Masked 材质会忽略 Opacity Mask（bCanMaskedBeAssumedOpaque 被置真）

    作者 @lyaflora 在空白项目中复现：复制引擎自带的 Niagara 默认精灵材质 DefaultSpriteMaterial（Engine/Niagara/DefaultAssets），把 Blend Mode 改为 Masked，并把 Opacity Mask 设为 0 后，预览网格仍完全可见，像是 Opacity Mask 为 1。作者发现出问题的材质里 bCanMaskedBeAssumedOpaque 为真，生成的 HLSL 里 PixelMaterialInputs.OpacityMask 在多处被写成 1.0f。按另一帖提供的 C++ 修复函数跑完后，该标志会变为假、HLSL 也暂时正确，但预览外观仍不变；一旦再改材质并 Apply，标志又会被重置为真，HLSL 再次写错。给该故障材质做实例、并在实例上把 Blend Mode 设为 Masked，实例侧可以正常工作，父材质仍然是坏的。作者试过关闭 Substrate、改 GBuffer Format 等项目设置，都没有解决问题。原文指向一篇关于 5.8.1 旧材质忽略 Opacity Mask 与 AO 的相关帖，发帖时没有 Epic 回复。平台为 Windows。

External sandboxes for coding agents：把代码执行放到智能体之外的沙箱

Simon Willison 于 2026-11-17 发布的链接博文介绍了他与 Prime Radiant（文中称为 Superpowers 等项目背后的 AI 研究实验室）合作的外部沙箱模式：智能体本身运行在沙箱外，需要执行的代码则送到专用沙箱里运行，以便更安全地试用本地模型，降低误操作或提示注入对宿主机造成破坏的风险。文中列出三个提供相同 localhost API 的沙箱服务实现：external-sandbox-v86（Node.js 服务，用 v86 在 WebAssembly 中跑 Alpine Linux）、external-sandbox-container（Python Web 服务，在 Apple Containers 实例里的 Alpine Linux 中运行沙箱）、external-sandbox-quicksand（同样是 Python Web 服务，使用 Microsoft 的 Quicksand 库，该库把 QEMU 与 Alpine Linux 打进 Python 包）。文章称可以把 Pi、Claude Code 或 Codex 配置成在需要执行代码时向该沙箱发 API。沙箱还提供可选的 HTTP/HTTPS 允许名单代理，以控制智能体代码可以访问的主机，以及凭据替换机制，以便在不把密钥交给智能体的情况下发起需认证的 API 调用，并可用界面在沙箱仍运行时改代理配置。更完整的介绍指向 Prime Radiant 博客上的同题文章。本机未部署或测试这些沙箱服务。

Unite Tokyo 2026：Unity 7 将让每个 GameObject 同时成为 Entity，并展示 Surface Cache GI、神经纹理压缩与 UGK

Unity 产品高级副总裁 Adam Smith 于 2026-11-17 发文，回顾 Unite Tokyo 2026 主题演讲，核心是 Unity 7“为想法的速度而建”。性能方面提出 ECS for All：每个 GameObject 同时成为 Entity，以便引擎系统迁到 ECS 后现有项目也能受益；文中称 5,000 艘飞船的演示里，GameObject 版随数量增加而变慢，ECS 版则保持稳定帧率，且 Unity 7.0 将允许在 Inspector 中查看和编辑 Entity 数据。图形方面用新样例场景 Atrio 展示 URP 的 Surface Cache GI（无需 lightmap 或烘焙的动态全局光照），文中称以全分辨率、60 fps 运行，并写明该样例即日起可在 Unity Asset Store 获取。Unity Neural 被描述为一组用于更快渲染、更低显存的 AI 工具：作者称 Neural Texture Compression 把 Atrio 的纹理内存减少了近 30%，将作为实验特性进入 Unity 6.7 LTS，并计划在 Unity 7 正式发布；新的图形后端 Unity Graphics Kernel（UGK）基于 DirectX 12、Vulkan 和 Metal，文中称在开启光追的 Atrio 上把 GPU 性能提升了 62% 以上。文中还提到 Unity 6.7 LTS 将带来可定制的 2D 图形、Physics Core 2D 创作组件和新的 2D 分析器，Bunny Blitz 物理解谜样例同样已上架 Asset Store。工具侧，Unity CLI 1.0 已正式可用；Unity Pipeline API 处于测试、正在开放报名，计划 2027 年正式发布；新的 Asset Library 插件可在编辑器内搜索 Asset Store 与已购资源并放入场景，还能把 Built-in 管线资源适配到 URP，同一搜索也可从 CLI 供 agent 使用。演讲还宣布 Synty Studios 加入 Unity，以及每年资助 10 支临近发行的独立团队、各 5 万美元且不抽成、不追回的 Unity Fellowship。飞船演示帧率、Atrio 的 60 fps、纹理内存“近 30%”和 UGK“62% 以上”均为 Unity 现场演示或博文中的厂商数据，本机未运行这些样例或测量。

官方：UE 5.9 Preview 2 已发布，移动端 Deferred 单 Pass 光照与 Web 移动档画质改进

官方 @UnrealEngine 于 2026-11-19 22:07（香港时间）宣布 5.9 Preview 2 已推出：仅蓝图项目也可把 Web 作为目标平台，AI 辅助工作流默认开启，并指向同日更新的官方发布说明（页面标注 Last updated 11/19/26）。发布说明中此前未在日报展开的渲染/移动端改动包括：移动端 Deferred 可用 r.Mobile.DeferredLighting.SingleShadingModelPass 在单次光照 Pass 里照亮所有 lit shading model；新增默认关闭的 r.Mobile.DeferredLighting.CameraInsideLightDepthTest，在相机位于本地光源几何内部时对光源背面做深度测试；没有 build data 的 Mobile Reflection Capture 不再渲染成黑色。方向光 Virtual Shadow Maps 增加投影与页管理优化，以及 Stochastic PCSS（接触处更硬、远处更软），并修复阴影投影进行中把 r.ShadowQuality 降到 0 会崩溃的问题。Web 方面，移动档改用引擎默认抗锯齿 TAA（不再用 FXAA），Deferred 档启用 Extended GBuffer，使清漆、贴花法线与材质环境光遮蔽能完整呈现；手机/平板会优先加载更轻的 ASTC 纹理集，各设备只下载所运行档的着色器数据，默认把帧率限制在显示器刷新率以省电散热。Preview 2 还规定：项目未设置帧率上限时改用平台默认上限；未使用的遗留 Reflection Capture 不再随地图构建数据一起 cook/转存；Lyra 的 Web 移动档用纹理与天空光上限把流送控制在预算内。该 Preview 仍是预览构建，官方建议用项目副本测试。

UE 5.8.4 加入 ASD Tool：可从已 cook 的 Windows 包生成 Advanced Shader Delivery 所需的 SODB

Xbox 团队产品经理 Clint Woon 于 2026-11-18 发文称，自 Unreal Engine 5.8.4 热修复起，引擎提供 Advanced Shader Delivery（ASD）支持，并附上 Epic 新发布的指南。ASD 的背景是：Direct3D 12 游戏首次启动时，驱动会在创建 Pipeline State Object（PSO）时编译着色器，可能导致较长的首次加载和卡顿；ASD 把这项工作移出游戏，按 GPU 与驱动预先编译，并由商店随游戏分发结果。5.8.4 中的 ASD Tool（ASDTool）可从已 cook 的 Windows 包生成 ASD 所需的 State Object Database（SODB），它是独立命令行程序，不需要编辑器或正在运行的游戏。SODB 需提交到 Microsoft Store；文中转述 Epic 的说明：Epic Games Store 支持计划在 2027 年初提供。覆盖范围是 Windows D3D12 Shader Model 6 构建（PCD3D_SM6），光线追踪 PSO 不受支持。ASD 并不取代 PSO precaching 和随包 PSO 缓存，Epic 建议两者都保留。使用条件包括：必须从源码编译引擎（该工具没有预编译二进制），并且已为 Windows D3D12 SM6 构建准备好 PSO 缓存。本机未编译引擎，也未运行 ASDTool。

论坛：UE 5.8 体积雾 tricubic 过滤把 h0.z 写错，Quality 2 会采到错误深度（含修复建议）

作者 @Ruben_designer 报告：将 r.VolumetricFog.Filtering.Quality 设为 2（tricubic）时，HeightFogCommon.ush 的 SampleVolumetricFogFiltered() 会采到错误深度。B 样条准备段在 bicubic 与 tricubic 共用后以 h0.z = VolumeUV.z 结尾，这对只在 XY 过滤、Z 上按原始深度线性采样的 bicubic 是对的；但 tricubic 分支也会用 h0.z / h1.z 与 g0.z 做 lerp，等于在 Z 上把未过滤深度与 B 样条偏移后的 h1.z 混合，过滤是错的。复现步骤：加 Exponential Height Fog（体积雾）和带 volumetric scattering 的聚光灯，设 r.VolumetricFog.Jitter 0 让边缘静止，在锥体边缘对比 Quality 0、1、2。作者观察 Quality 2 看起来与三线性差不多甚至更差（聚光灯边缘的 froxel 台阶仍在），Quality 1 才能正确抹平。建议把 h0.z = VolumeUV.z; 移进 PERMUTATION_VOLUMETRIC_FOG_FILTERING_QUALITY == 1 分支，让 tricubic 保留计算出的 h0.z；并指向 GitHub PR #15392。原文标注影响 UE 5.8、Windows，发帖时没有 Epic 回复。

Codex CLI 0.170.0：TUI 增加实时语音通话的 WebRTC 协商，并修复 Windows 沙箱与 Cloud 重连

openai/codex 于 2026-11-18 发布稳定版 0.170.0（标签 rust-v0.170.0，发布时间 03:40 UTC，即北京时间 11:40）。发行说明列出的新功能包括：为 TUI 中的实时语音通话加入 WebRTC 协商（#61172）；OpenTelemetry HTTP exporter 会自动刷新认证头（#61028）；以及实验性支持在不同环境中使用同名 MCP 服务器（#60905）。修复方面，过大的 WebSocket 请求会立即回退到 HTTP、不再做不必要的重试；MCP OAuth 在取消、登录和登出时的凭证竞态已修复；Cloud 会话的自动重连有改进，并且客户端重连时会保留正在进行的恢复回合；Windows 上修复了文件替换、沙箱权限保留和运行时注册恢复，并修正权限更新或子线程丢失已有沙箱限制的问题；另外去掉了重复的文件搜索结果，并修复含空白查询的线程搜索片段。文档更新了沙箱权限配置与文件系统规则说明。完整对照范围是 rust-v0.169.0...rust-v0.170.0。本机未安装或升级到 0.170.0，也未验证语音通话与 Windows 沙箱修复。
