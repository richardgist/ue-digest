打包后 Lumen 失效：常见原因与排查步骤

Bugnet Blog发布:2026-10-07适用版本:原文未标注（适用于启用 Lumen 的 UE5 项目）
图形渲染渲染

文章归纳打包后 Lumen 常“消失”的五类原因：可伸缩性低于 High、Post Process Volume 未加载、项目未设为默认 Lumen、跑在 DX11 等不同 RHI、以及仅存在于编辑器的配置；并给出 Development 包内用 console 逐项核对的流程。

值得试的点

  • Development 包里先跑 scalability，再查 sg.GlobalIlluminationQuality / sg.ReflectionQuality（需 2=High 或 3=Epic）以及 r.DynamicGlobalIlluminationMethod / r.ReflectionMethod（1=Lumen）
  • 若靠 Post Process Volume 开 Lumen，在 World Partition 下取消 Is Spatially Loaded 或放进 always-loaded Data Layer；更稳妥是在 Project Settings / DefaultEngine.ini 设全局方法并生成 Mesh Distance Fields
  • 把编辑器控制台里临时敲过的 CVar 迁入 DefaultEngine.ini 或 Device Profile，避免只在编辑器生效

Nanite 与 Lumen 把显存打满时怎么拆因

VFXRendering发布:2026-10-07适用版本:原文未标注
图形渲染渲染

文中区分 Nanite（几何流式池）与 Lumen（加速结构与光照缓存，高分辨率分块还会每 tile 加开销）的显存占用机制，给出按症状对照表，并强调在交付分辨率、最重帧上用 stat 测量后再改设置。

值得试的点

  • 在交付分辨率下用 stat RHI / stat streaming / Nanite streaming 统计看峰值；临时关一次 Lumen 对比差值，判断是谁占大头
  • 草稿用较低 Lumen 质量、远处换成代理网格、按距离降纹理上限；有余量再调 r.Streaming.PoolSize，卡满时不要盲目加大池
  • 纹理先糊再崩多半是流式池不够：先查 streaming 统计，再决定加池还是砍远景纹理
