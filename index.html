SplatAnything: Gaussian Spacing Normalization for Feed-forward 3DGS across Arbitrary Scenes

这篇 2026-11-05 提交的论文指出，现有前馈 3DGS 通常先由几何基础模型预测深度，再在径向距离归一化（RDNorm，用重建点到参考相机原点的平均径向距离做全局缩放）的坐标系里预测 Gaussian 属性；但相邻 Gaussian 中心间距（Gaussian spacing）仍会随场景尺度和相机配置大幅变化，使相近的局部观察对应不同的尺度监督目标。作者提出 SplatAnything 与 Gaussian Spacing Normalization（GSNorm）：在逐像素预测假设下，局部间距近似为深度除以焦距几何平均，即 d≈D/√(fx fy)，再用所有有效像素的中位数作为场景尺度，把几何、深度和相机平移一并缩放，使该中位数间距为 1。几何由冻结的 WorldMirror 2.0 估计，随后微调 Gaussian Backbone 并用从头训练的 GSHead 预测不透明度、旋转、尺度和球谐系数。为评估跨场景与外推视角，作者建了一套覆盖 ScanNet、NRGBD、DL3DV、Tanks & Temples、Mip-NeRF 360、ETH3D、DTU 的基准，控制输入 4/8/16/32/64 视并强调遮挡感知共视约 0.2–0.6 的外推目标。作者报告在多数设置下优于所列基线，例如无位姿时 ScanNet 上 DISTS/LPIPS 为 0.184/0.207（Mirror2-GS 为 0.193/0.222），DTU 上为 0.229/0.483（Mirror2-GS 为 0.347/0.617）；同一架构消融里 4 视 GSNorm 为 0.198/0.245，对照 RDNorm 的 0.223/0.278。训练为 2 万步、64 张 NVIDIA H20，输入 4–32 视、分辨率 504–1024。文中也写明：方法依赖几何先验，在极稀疏或几何不可靠输入上可能下降，且主要重建输入可见区域。项目页为 https://zju3dv.github.io/SplatAnything/ 。以上均为论文实验与作者结论，本机未复现。

为什么有用

做前馈 3DGS 时如果尺度在小物体上出洞、大场景上过平滑，这篇把问题从「几何归一化」改写成「先对齐 Gaussian 间距再预测尺度」，并给出跨数据集和外推视角的对照。

值得试

How Gaijin Tuned DLSS 5 for War Thunder

NVIDIA 于 2026-11-03 刊登对 Gaijin Entertainment 美术总监 Kirill Stupin 的访谈，介绍 War Thunder 如何把 DLSS 5（3D-Guided Neural Rendering）接入自研 Dagor Engine。文中说：11 月中旬的 Eagle's Shadow 大更会上线该功能；游戏此前已有 DLSS 4.5 Multi Frame Generation、Super Resolution、Ray Reconstruction、DLAA，以及 Reflex、光线追踪和路径追踪全局光照。NVIDIA 写 DLSS 5 作为图形管线的最后阶段运行，以引擎已渲染的帧和运动向量为基础增加光照与材质细节——这是厂商对功能的描述。Gaijin 团队说真正的难点不在文档（他们估计 NVIDIA 文档覆盖了约 95%），而在色彩空间：DLSS 5 在 sRGB 中工作，Dagor 与多数现代引擎一样在线性 HDR 中渲染；既要在 bloom、运动模糊、色差等后处理和 UI 之前评估 DLSS 5，又要喂给它带有玩家最终观感的 sRGB 图像。他们的做法是让色彩管理管线可逆，先做出「半最终」观感的 sRGB 图给 DLSS 5，再把 DLSS 5 造成的变化映射回线性 HDR；并在代表性场景上对照参考外观，调整模型和强度。访谈中的「高光/阴影更好、出现过去做不到的微对比度」「有组员一度以为换了渲染引擎」等是对方美术团队的主观评价，并非独立测评。给其他开发者的建议是：花时间按自己的美术方向去调。这是厂商访谈，本机未验证其画质或性能说法。

  • 先按内容行为拆多个 HLOD Layer，再调 Cell Size / Loading Range，避免一张万能层

Gaussians Can Subtract: Neural Dissolve Fields for Hybrid Scene Rendering

现有 Mesh–Gaussian 混合重建多半是加法：网格负责大块规则表面，Gaussian 残差去补网格做不到的部分；但同一块网格内容可能在某个视角一致、换个视角就不一致（残余几何误差、遮挡错位、纹理投影伪影或视角相关外观）。这篇 2026-11-04 提交的论文把冲突改写成多视角不一致，提出 Gaussolve：用标量球谐 Gaussian 参数化的 Neural Dissolve Field，学习在何处、从哪些视线方向溶解网格，再让残差 RGB Gaussian 填回露出的区域；融合用连续透射率，而不是按深度做硬可见性切换。网格几何来自 RealityCapture，纹理是把训练图像直接投影到网格上（默认均匀减面到约 10 万三角），测试视角不参与重建和贴图。作者在 RTX 5000 Ada 上报告：ML-Hypersim-AI 上接 3DGS 主干的 Ours 为 PSNR 35.35 / SSIM 0.962 / LPIPS 0.108，相对 3DGS 的 34.39 / 0.959 / 0.155，Gaussian 数量减少约 30%；Deep Blending 上为 28.75 / 0.876 / 0.228，相对 28.50 / 0.877 / 0.272，数量减少约 47%。效率表（Deep Blending 平均）里，同一 3DGS 主干的并行混合渲染约 174 FPS、存储约 0.336G，对照 3DGS 约 99 FPS、0.655G；换成 Reduced 3DGS 主干约 241 FPS、0.219G，但仍慢于单独的 Reduced 3DGS（文中归因于额外的网格与 dissolve 开销）。与 MeshGS、Hybrid Mesh-Gaussian 的 Deep Blending 对照直接引用了对方论文数字。项目页为 https://ooosn.github.io/gaussians-can-subtract/ 。以上均为论文实验，本机未复现。

论坛：Nanite 没有按距离切换材质 LOD——Epic 建议用 HLOD、Disallow Nanite 与可编程距离

提问方沿用传统 Static Mesh 的做法，希望 Nanite 也能按距离换成更简单的材质（近处多层细节法线、远处烘焙贴图），以降低显存和着色成本，并询问 UE 5.8 是否已支持；他们的场景有大量不复用的独特道具。Epic 的 Tim Stullich 答复：目前没有计划支持按距离切换的材质 LOD。Nanite 通常靠 shade binning 降低材质求值成本；引擎虽有 Nanite Override Materials，但不一定覆盖这种「近复杂、远烘焙」需求。对方追问后他补充：团队讨论过给 Nanite 加材质 LOD，主要顾虑是材质变体和 shading bin 数量会变得难管理；目前正在减少变体，已把需求提给开发组评估。8 月 26 日他改口得更明确：按距离做材质 LOD 与 Nanite 的演进方向相反，短期内不太可能加入，因为额外材质 LOD 会制造更多 shading bin，而这正是 Nanite 的主要瓶颈之一。可落地的替代是：若要在 HLOD 上做材质 LOD 链，给网格勾选 Disallow Nanite，运行时退回 Fallback，才能沿用传统材质 LOD；另外可调 WPO Disable Distance 与 Pixel Programmable Disable Distance，让远距实例退回更便宜的光栅——他称这往往比材质 LOD 更影响 Nanite 性能。对于独特道具过多，他建议先复用和实例化。Nanite Material Cache 仍是实验特性、变动频繁，他不建议按项目周期贸然启用。提问方认为 HLOD 不够用，因为 ISM/HISM 只能共用同一套材质。
