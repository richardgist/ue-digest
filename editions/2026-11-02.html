    Generating a State Object Database for Advanced Shader Delivery（ASDTool）

    Epic 官方说明如何用独立命令行 ASDTool 从已 cook 的 Windows D3D12/SM6 构建生成 SODB（.sodb），供商店预编译成按 GPU/驱动的 PSDB，以减轻首次启动着色器编译卡顿。范围仅限 PCD3D_SM6；不支持光追 PSO；需源码编译 ASDTool，并开启 bShareMaterialShaderCode。采集来源：-AllCompute 收齐 SM6 compute shader，-BundleDir 从已有 .upipelinecache 导入 graphics/compute PSO；二者可并用。文档强调 ASD 不替代 PSO precaching / bundled PSO cache，仍建议保留 precaching。提供 generatesodb / compilepsdbs / registerpsdbs 本地验证流程，以及 -ValidatePSOs 排查失败 PSO。

    Agility SDK 1.620.1：Batched Async Commands 的 Fallback Layer

    1.620.1 为 Batched Async Commands 提供可选 Fallback：在不支持原生实现的设备上，由运行时用已有操作模拟 batched copy/fill/clear/resolve，原生支持设备仍走驱动快路径。启用后即使命令列表不用这些 API 也会有额外 CPU 记账开销（屏障、根参数、PSO、RT 绑定等）；需 Enhanced Barriers。文中列出与原生的差异（如部分 MSAA/保护资源清屏会失败、bound clear 在 render pass 内的限制），并可用 d3dconfig device force-async-commands-fallback=true 在原生硬件上强制测 fallback。微基准显示多数命令 GPU 开销接近，ClearTextureSubresources 在无法原地清时更贵。

UE 5.8 Scalability 与 Device Profiles：分档工作流与可读性底线

区分职责：scalability groups 管玩家可见画质族；device profiles 管平台/设备默认、特性支持、内存桶与覆盖。项目覆盖写在工程 Config，不要改引擎 Base 文件；以 BaseScalability.ini 与平台基线 device profile 为参考后再按测量覆盖。核心组含分辨率、视距、抗锯齿、阴影、GI、反射、后处理、贴图、特效、植被、着色等——一个 sg.* 可联动多枚 CVar。工作流：定义最低/推荐硬件与渲染器能力 → 设 Low/Medium/High/Epic 意图与玩法可读性底线 → 从引擎默认起在各目标设备测量 → 组不够预算时才覆盖子系统 → 标出需重启/重载的设置，并测存档、自动检测与不支持硬件回退。硬规则：低档不得拿掉敌人、危险、导航线索或竞技可见性，只缩放表现而非规则。
