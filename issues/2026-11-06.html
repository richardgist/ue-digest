Unreal Fest Tokyo 2026：MegaLights 时代如何用大量 RectLight 做演出光

ゲームメーカーズ（Unreal Fest Tokyo 2026 演讲报道）发布:2026-11-06适用版本:UE 5.8
图形渲染渲染

木村洋一在 Unreal Fest Tokyo 2026 从灯光艺术家视角谈 MegaLights：正式版后成本大致与灯数量解耦，关键收益是每盏灯都能走正确的 Ray Traced 面积光。街景作例：仅 Directional+Sky 约 13.12ms；加 160 盏 RectLight 并切 RT 约 35.59ms；开 MegaLights 回落到约 16.16ms。建议默认常开，用大面积、柔和的非必然 RectLight（约 2m 级）补远景与人物，比抬 ColorGrading/SkyLight 更保对比；可用贴图 RectLight 代替高风险 Emissive，并与 VolumetricFog 组合。技术细节指向 Epic Japan 的 Scalability / MegaLights 入门幻灯片。

值得试的点

  • 在目标相机位 A/B：关 MegaLights 的少灯路径 vs 开 MegaLights + 数十盏大 RectLight，对比 GPU 与阴影质量
  • 非必然补光用大 Source 的 RectLight（或加大 SourceRadius 的 Point/Spot），避免小硬光源暴露假光方向
  • Emissive 仅作可见发光体：关 Affect Dynamic Indirect Lighting，Specular 交给 Emissive、漫反射交给同位贴图 RectLight；可用 r.MegaLights.Debug 1 看采样

World Partition HLOD 实操：建 Layer、选类型、生成与建筑可视化检查

3dsınıfı发布:2026-11-05适用版本:原文未标注（基于 Epic World Partition / HLOD 文档整理）
图形渲染HLOD

面向大场景/建筑可视化的 WP×HLOD 步骤文：创建 HLOD Layer（Instancing / Merged Mesh / Simplified Mesh），配置 Always Loaded、Cell Size、Loading Range 与合并/简化参数；Actor 须挂到 Layer 且 Mobility=Static，再 Build > Build HLODs 或 WorldPartitionHLODsBuilder。提醒 masked/opacity 的 alpha 不会进合并贴图；Simplified Mesh 的 Merge Distance 可能糊掉门窗洞口；过大采样间隔会抬内存。建议先对代表性环境组生成，用视口 LOD 颜色与交付相机距验收，勿默认 HLOD 一定降 draw call。

值得试的点

  • 按内容分 Layer：重复植被试 Instancing，建筑簇试 Merged/Simplified；先小范围生成再全图
  • 生成前核对 Actor 已分配 HLOD Layer 且 Mobility=Static；Always Loaded 开启时 Cell/Loading Range 不可用
  • 验收：远距门窗是否被 Merge Distance 封死、masked 材质 alpha、实际交付机位的可读性；用 View Mode LOD 颜色辅助

论坛：Nanite Landscape 组件数、Tessellation 与 VisBuffer 空 bin 开销（Epic 答复）

Epic Developer Community Forums（Petrockets / Alex Peterson）发布:2026-08-20（提问）；2026-09-01～09-02（Epic 详解）适用版本:UE 5.8（答复提及 5.8 experimental bindless bundle 模拟）
图形渲染渲染HLOD

Epic 确认：每个 Landscape component 因独立 weightmap 对应独立材质实例，从而占独立 shading/raster bin；开 Tessellation 后无法走 fixed-function bin，空 ExecuteIndirect 会拖 VisBuffer（低端更明显）。默认世界删到 1 个 section 时 NaniteStats 常见约 42 bins（含 TwoPass）；可试 r.Nanite.Culling.TwoPass 0 便于读数，Tessellation 可试 r.Nanite.DicingRate 3–4。一个 Nanite Landscape component 最多挂 64 mesh sections；更大 component 减少 MIC/bin，但图层更杂、材质更贵。Fortnite 示例约 4 components/proxy、不走 Landscape HLOD。内存上 Nanite 与非 Nanite 两套数据并存；碰撞/导航/Lumen card/DF 仍走标准 Landscape。

值得试的点

  • 用 NaniteStats + PIX/Insights 数 Landscape 相关空 bin；开 Tessellation 前先设 DicingRate 并量 VisBuffer
  • 在预算内加大 component 分辨率（上限约 511×511）以减少 MIC/bin；对照 RVT 摊销材质层成本
  • Streaming Proxy 粒度：权衡并发编辑、驻留（碰撞/nav/grass）与 HLOD；可试 grass.GrassMap.UseRuntimeGeneration 1 降草图驻留

Epic 文档：Mobile Rendering Features Reference——路径能力对照表

Epic Games Documentation发布:约 2026-06（UE 5.8 文档；此前未收录；官方 X 2026-11-02 再次指向）适用版本:UE 5.8
图形渲染移动端渲染

UE 5.8 移动端渲染特性矩阵：按 Mobile Forward（ES3.2/Metal/Vulkan/Switch）、Mobile Deferred（Metal/Vulkan/Switch）、以及关 HDR 的 HMD Mobile XR Forward，逐项标 Yes/No/有前提。明确 Nanite、Hardware RT、VSM、软件/硬件 Lumen、TSR、Volumetric Clouds 等在表列移动路径为 No；HLOD、传统 LOD、Texture/VT Streaming、MSAA（Forward）、TAA、部分 Volumetric Fog 等可用。Feature Level 对应 Android ES3.2、Android Vulkan、iOS Metal 2.0，并指向各平台 Material Quality 设置。适合在选型阶段先查表再定艺术方向与 Device Profile。

值得试的点

  • 立项时用本表锁定目标路径（Forward vs Deferred）与不可用的次世代特性，避免后期返工
  • 需要 MSAA（如部分 XR）优先 Forward；动态灯更多再评估 Deferred 与平台扩展前提
  • 对照 Project Settings 的 Android/iOS Material Quality，与真机包体验证，不以桌面默认为准

Epic 文档：Using Preview Platform——编辑器内模拟移动端渲染与 Scalability

Epic Games Documentation发布:约 2026-06（UE 5.8 文档；官方 X 2026-11-02 推广移动工作流时指向）适用版本:UE 5.8
图形渲染移动端渲染

Preview Platform 可在编辑器视口切换目标平台/图形 API，重编译材质以模拟该平台渲染器，并加载对应 Device Profile、默认 Scalability 组与平台 CVar，使视口更接近运行时观感；首次切换需等着色器编译，之后可在已编译级别间切换且不必重启编辑器。视口工具栏 Performance and Scalability → Preview Platform 可选 Android GLES 3.1、Android Vulkan、iOS Metal 等；激活后可单独调该平台 Scalability，Default 可恢复平台运行时默认。文档强调仅作预览，最终必须以真机验证。可配合 Project Settings 各平台 Material Quality 与 Update Preview Shaders。

值得试的点

  • 改移动材质/Scalability 前先切到目标 Preview Platform，确认首轮着色器编译完成后再比画质
  • 在 Preview 激活状态下调 Scalability，用 Default 回到该平台运行时默认，避免污染桌面编辑器质量
  • Material Quality 改完点 Update Preview Shaders；打包前仍在目标 Android/iOS 真机跑通
