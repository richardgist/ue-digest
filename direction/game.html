Unity 新 XR 电子书：面向 Meta VR Glasses 的移植、注视点渲染与用 CLI / Agent 闭环验证

Unity 于 2026-11-06 发布电子书《Build XR with Unity: Meta XR》，面向要新做或把现有应用移植到 Meta VR 设备的开发者。文中介绍 Meta VR Glasses：大约 100 克、以眼动和手部追踪为主要输入，并与 Quest 使用同一套操作系统、商店和 OpenXR，因而现有 Quest 应用可以在其上运行。教程基于 Unity 6.6 与 XR Interaction Toolkit 3.6（或更新），从 Unity Hub 的 VR 模板起步，可在真机、编辑器里的 XR Interaction Simulator，或 Meta XR Simulator 上测试。眼镜侧能力包括：眼动（用于注视点渲染和注视输入，默认视为隐私，需请求权限，并应准备用户拒绝后的回退，例如手部射线）；Quad Views（每只眼睛的周边以低于中心的分辨率绘制）；7.1.4 空间音频（Enhanced Audio Foundation）；以及 5K Infinite Display（每眼 2412×2288 的 micro-OLED，37 PPD，文中对照 Quest 3 的 25 PPD，对比度也更高）。优化章节覆盖基于注视的注视点渲染、Quad Views、Application SpaceWarp、动态分辨率和 Adaptive Performance；并从 Quest 2/3 移植时提醒：固定注视点渲染在 Glasses 上省下的开销更小，应重新评估并做基准测试。效率部分介绍 Unity CLI 与 Unity Pipeline 包：后者把正在运行的编辑器变成本地后台服务，场景和资源库保持热状态。Claude Code、Codex、Cursor、Copilot、Gemini CLI 等能跑 shell 的 agent 可以驱动编辑器；Unity 为 Claude 与 Codex 提供的官方插件会在启动时一条命令装上 29 个 skills。实验性的 Meta XR Operator 让 agent 在运行中的 XR 应用里检查场景、移动头/手柄/手、做 pinch/poke/grab（含 Glasses 的注视+捏合）并截取画面做验证，文中明确不要把它当生产依赖，舒适度、追踪和性能仍要在真机上测。这是厂商指南，本机未按教程完整复现。

    Unreal Fest Tokyo：别只装 Unreal MCP——为项目做 LLM 能用的 UMG / Sequencer 专用工具

    游戏制造商对 Unreal Fest Tokyo 2026（11/3–11/4）Epic Games Japan 铃木孝司演讲的报道。验证环境是 UE 5.8.3，不改引擎，用项目侧代码/插件扩展 Unreal MCP，对象是 UMG 与 Sequencer 工作流；文中写明这是验证项目，不是商用上线数据。要点：MCP 只是操作窗口，项目知识要用 markdown/技能补上；标准 Tool Search 用 list_toolsets / describe_toolset / call_tool 按需装入上下文。AI 说「做不到」不一定缺工具——浮点轨道可用已有的 add_track_to_binding 与 set_property_name_and_path 组合完成。新工具要补齐「创建 / 修改 / 删除」并做闭环测试，否则会出现删不掉的动画行，或删除后同名重建导致崩溃。流程上用 JSON 分镜生成 Sequencer，专用编辑器把细项收进「给 LLM 的指示」栏；相机用继承 CineCamera 的自动构图相机减少反复试位。重新生成 3 个 Sequencer 的报道对照：Sonnet 初测约 17.7 分钟、110 次模型调用；加上可追踪进度的批处理后约 10.8 分钟、55 次；同样调整后 Opus 约 17.7 分钟、73 次。项目整体消耗约 15.6 亿 token（含调研与讲稿整理，且多为缓存读取，不能按普通输入单价估算费用）。UE 5.9 开发分支计划用 MCP 图像格式返回截图。

    Godot Showcase - Sovereign Tower

    Godot 官方于 2026-11-06 访谈 Wild Wits Games 的 Paul Mozet（主程）与 Lisa Garnier（叙事设计/技术美术），介绍已在 Steam 上架（Windows / Linux）的叙事圆桌管理 RPG《Sovereign Tower》。Paul 认为最大工程难点是回溯：每个周期要存早、下午两份，且须记住过往周期状态，同时君主会保留已知信息，再叠加大量叙事变量、任务和一百多个角色。做法是尽量把存储拆细并大量测试，上线后仍在修残留问题。叙事侧则靠削减分支变体来控制字数和本地化成本。动画上 AnimationPlayer 与 Tween 大约各半；当时 UI 节点受布局系统约束，位移动画需要变通，Godot 4.7 引入的 transform offset 让小过渡更容易。简单肖像可由美术直接提交并在 Godot 里改，复杂 UI 再交程序接手；场景系统让美术能自己做视觉打磨。Paul 仍怀念 Unity 可锁定多个文件系统/检视器标签页的能力。全文是开发者自述，没有给出运行时性能数字。

    How SEED renders a world players never stop building

    Klang Games 用 Unity URP 做持久沙盒 MMO《SEED》：客户端只渲染服务器流式状态。建筑拆成约 1m 网格模块，用 BatchRendererGroup + Job/Burst 合批；表面颜色等多写在顶点而非贴图。PC 上用真实玩家存档剖析后发现偏 CPU：大量带 LOD Group 的 Prefab 因动画 cross-fade 没进 GPU Resident Drawer，仍走 SRP Batcher；关掉动画后恢复 hybrid/instanced 合批。移动端主要卡内存，靠 Memory Profiler 差分、按平台 Addressables，以及把经典 LOD 换成 Unity 6.2 Mesh LOD（多级细节收进同一 mesh）。
