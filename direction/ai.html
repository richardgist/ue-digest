    这是一位用户提交、仍处于 open 状态的 Issue,10 月 12 日在 Hacker News 上引发热议。报告称自 Codex CLI 0.157.0 起,打开交互会话就会启动一个常驻的后台守护进程(关掉窗口也不退出),把约 374 MB 的平台包复制到 ~/.codex/packages/app-server-daemon/,并启动每小时检查更新、可自行重启后端的更新进程;守护进程还会沿用第一个启动它的会话的环境变量(如代理、GH_TOKEN 等)。评论里有人在 Windows 上确认,也有人报告旧版本堆积到 2.8 GB。这些是用户报告,OpenAI 官方尚未在该 Issue 中回应,我们也没有自己复现。

Many Agents, One Clone

作者同时开多个 AI 编码代理会话,共用同一个 git 检出,三个月里出了不少事故:有会话中途切走分支,导致另一个会话 push 时只显示 Everything up-to-date、实际什么都没推送;有代理为了“清理”执行 git reset --hard origin/main,丢掉 7 个未提交的文件。他的解法是每个会话单独用一个 git worktree,并明确从 origin/main 切出分支。文章也讲了新坑:git push origin HEAD:main 会把整个分支一起推上去,绕过了 PR 评审。这是个人经验总结,不是对照实验。

Introducing Candle(面向本地开发的进程管理器 1.0)

Candle 是给本地开发用的进程管理器,定位类似 pm2、Foreman,但不面向生产环境,也不依赖 Docker。服务在后台运行,多个终端会话可以共享并查看同一批进程;进程按项目目录隔离,所以不同 git worktree 各有一套独立的进程列表。candle logs 会立即返回,而会持续输出的 candle watch 在被代理调用时会被拦截并提示改用 logs。支持 Mac 和 Linux(原文没提 Windows)。作者明确说 1.0 不处理端口分配,多个 worktree 需要自己用 .env 给每个目录分配不同端口。
