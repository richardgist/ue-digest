值得试的点

  • 若 5.8.4 编辑器冷启动打开 World Partition 地图时，在第 4 帧出现 DXGI_ERROR_DEVICE_HUNG，且面包屑停在 Nanite VSM 的 NodeAndClusterCull、异步队列同时在 LumenScreenProbeGather / UpdateWorldRadianceCaches，可按原文在首次启动就加 -dpcvars=r.Lumen.DiffuseIndirect.AsyncCompute=0，确保第一帧前就关闭 Lumen 漫反射异步计算，再对照 hang 是否消失。作者在改用该参数后连续两次冷启动都干净，但自己也写明次数太少、还不能单独当作充分证明
  • 原文还提到，另有公开报告称 r.RDG.AsyncCompute=0 也能挡住这类 hang。这是启动前关闭异步计算的变通，不是官方合入的修复；5.8.4 仍被列为受影响。不要把它和 11 月 25 日那条“关卡加载后前几帧、先关再开回 AsyncCompute”的报告当成同一帖，但排查时可一并对照

Epic Developer Community Forums发布:2026-11-25适用版本:UE 5.8
图形渲染渲染

作者 @Eel_I_Fukunaka 报告：在项目开启 Substrate 的前提下，若材质的 Front Material 由 Static Switch（或 Static Switch Parameter、Quality Switch、Shading Path Switch）驱动，且其中一路输入经过 Named Reroute 或普通 Reroute，再指向材质函数的第 2 个及以后的 Substrate 输出脚，加载时会打出 LogMaterial: Error: Material information is invalid，Cook 以 ExitCode=25（Error_UnknownCookFailure）失败。编辑器视口里该材质仍能编译并正常显示。复现步骤是：做一个多输出材质函数（输出 0、1 为标量，输出 2 为 Substrate Slab BSDF），把 Named Reroute Declaration 接到输出 2，再把该 reroute 的 Usage 接到 Static Switch 的 B，True 侧接任意 Substrate BSDF，最后把 Switch 接到 Front Material；保存后重新打开编辑器或执行 Cook 即可看到错误。作者定位到 UMaterialExpressionStaticSwitch::IsResultSubstrateMaterial 会跟着 reroute 找到材质函数调用，却检查 reroute 自己的 OutputIndex（0）而不是追踪后的 OutputIndex（2），因而把错误的输出脚当成非 Substrate；同一模式还出现在 StaticSwitchParameter、QualitySwitch、ShadingPathSwitch 以及 GatherSubstrateMaterialInfo 里。SubstrateHorizontalMixing 等节点已经使用追踪后的 OutputIndex，因此不受影响。平台写的是 Windows。发帖时还没有 Epic 答复。

值得试的点

  • 若 5.8 + Substrate 材质在编辑器里看起来正常，但加载日志出现 Material information is invalid、Cook 失败，先检查 Static Switch（及 Quality / Shading Path Switch）的输入是否经过 reroute，且 reroute 是否接到材质函数的非首个 Substrate 输出
  • 按原文的变通：把材质函数的 Substrate 输出直接接到 Switch，不要经过 reroute；或者把该 Substrate 输出改到函数的第一个输出（index 0）
  • 若你维护引擎源码，作者建议在 IsResultSubstrateMaterial / GatherSubstrateMaterialInfo 里改用 GetTracedInput() 之后的 OutputIndex，并同样改 StaticSwitchParameter、QualitySwitch、ShadingPathSwitch。这是作者的补丁建议，不是官方合入的修复

论坛：UE 5.8.4 的 PCG 运行时 GPU 实例会在全局重建渲染状态时丢失，且不会自动再生

Epic Developer Community Forums发布:2026-11-16适用版本:UE 5.8.4
图形渲染渲染

作者 @potrivaev1 报告：在 UE 5.8.4（Linux）上，PCG 以 Generate At Runtime 并在 GPU 上生成的实例只存在于 GPU Scene（UPCGProceduralISMComponent）。一旦发生全局组件渲染状态重建（FGlobalComponentRecreateRenderStateContext，例如用默认选项构造的 FMaterialUpdateContext），这些实例会被清掉，而且 PCG 收不到通知，因而不会再生；相机周围的运行时植被会消失，直到执行 pcg.RuntimeGeneration.Refresh（编辑器菜单 Tools > PCG Framework > Refresh All Runtime Gen Components）。复现是：关卡里放 Landscape 和 PCG Volume（运行时生成、层级网格 32/64/128 m，图为 Generate Landscape Textures → 自定义 HLSL 点生成 → Static Mesh Spawner，在 GPU 上执行），等植被出现后，打开任意材质资源（不必在关卡中使用）并点 Apply，或用 Python 调用 unreal.MaterialEditingLibrary.recompile_material；实例会立刻消失且不再回来。打开 pcg.RuntimeGeneration.EnableDebugging 1 后，重编译之后没有 [RUNTIMEGEN] 日志，说明调度器不知道实例已经没了。作者称 100% 可复现。UPCGProceduralISMComponent::OnRenderStateDirty 已经处理 MarkRenderStateDirty 这条路径（源码注释写明 GPU Scene 里没有显式持久化实例数据），但全局重建路径不会广播 MarkRenderStateDirtyEvent，该处理器不会被调用。作者还观察到冷启动时，每个材质 shader map 加载完成都会触发整次运行时生成重启，根图在前 15–40 秒可执行 10–16 次，并表现为启动阶段植被闪烁。

值得试的点

  • 若 5.8.4 在 Apply / 重编译任意材质后，PCG 运行时生成的植被突然消失且不再长回来，先试 pcg.RuntimeGeneration.Refresh，或菜单 Tools > PCG Framework > Refresh All Runtime Gen Components；原文把它作为已验证的变通
  • 对照时可开 pcg.RuntimeGeneration.EnableDebugging 1，看重编译之后是否完全没有 [RUNTIMEGEN] 日志。这能区分“调度器不知道实例已丢”和普通刷新失败
  • 这是作者在 Linux 上的 100% 复现和源码分析，不是官方合入的修复。冷启动阶段若看到植被反复闪烁，原文也把它归到同一条渲染状态重建路径

UE 5.8 官方说明如何用 Runtime Virtual Texture（RVT）在运行时由 GPU 按需生成纹素，并把大范围着色结果缓存下来，适合带贴花感材质和样条的地形着色。流程是：在内容浏览器创建 RVT 资产，向关卡放入 Runtime Virtual Texture Volume，让材质写入并采样该资产，再把图元或 Landscape 指派给它。每个 Volume 只绑定一份 RVT 资产；场景组件可以写入多份。材质须使用 Virtual Texture 域或 RVT 相关表达式。资产可选多种 Material Type，并对应不同压缩：仅 Base Color（BC1），Base Color/Normal/Roughness/Specular（BC3+BC3），YCoCg Base Color、Normal、Specular（BC3+BC5+BC1）以及带 Mask、World Height（R16_UNORM）、Displacement（BC4）、Mask4（BC3）等变体。文档建议做法线时写入世界空间，以便多个图元混合。Volume 应用 Transform from Bounds / Set Bounds 套住地形或相关组件，并以 Volume 负 Z 方向做正交投影。写入与采样靠 Runtime Virtual Texture Output / Sample / Sample Parameter；也可用 Runtime Virtual Texture Replace、Virtual Texture Feature Switch，以及 View Property 里的 Virtual Texture Output Level / Derivative / Max Level，按 mip 近似做与相机无关的「距离」着色。适合写入的是 Landscape、Landscape Spline、静态网格、ISM 和做贴花散射的植被实例；骨骼网格、可移动或动画网格不合适，因为 RVT 是着色缓存，不会每帧完整更新，写入对象应为 Static。Draw in Main Pass 可选 Never、From Virtual Texture 或 Always：只写入 RVT 的贴花平面在无虚拟纹理支持时应选 Never；地形则应 Always，以便同时写入并采样。仅写入 RVT 的图元应手动关掉碰撞。图元可调 Virtual Texture LOD Bias、Skip Mips、Min Coverage；Landscape 的 Virtual Texture Num LODs 为 0 时每个组件以单四边形写入，对 GPU 最省，需要高频顶点插值时再提高。Volume 还可设置 Streaming Levels 并 Build，生成 Virtual Texture Builder，把低 mip 交给 Streaming Virtual Texture；编辑器默认仍看运行时 RVT，勾选 Use Streaming Low Mips in Editor 才预览流送数据，Build Debug 会给流送 mip 染色。RVT 设置改动后若未重建，关联 SVT 会失效并在 Map Check 中报警。调试可用 stat virtualtexturing、stat virtualtexturememory，以及 r.VT.Flush、r.VT.MaxUploadsPerFrame（编辑器默认 64、游戏默认 8）、r.VT.RVT.TileCountBias、r.VT.PoolSizeScale 等。限制包括：顶点着色器采样没有 GPU feedback；填充 RVT 的材质不能再采样虚拟纹理；普通流送纹理写入 RVT 可能在未完全流入时留下问题；ISM 即使勾了 Use GPU Lod Selection，RVT 也不走 CPU/GPU 实例剔除与 LOD 选择。

  • 只让 Static 的地形、样条、ISM 或植被贴花写入 RVT；骨骼网格和可动画网格不要当写入源
  • 远景在 Volume 上用 Streaming Levels 构建 SVT 低 mip；用 stat virtualtexturing 和 r.VT.MaxUploadsPerFrame（游戏默认 8）限制每帧上传，改完 RVT 设置后重新 Build，避免 SVT 失效

Landscape HLODs are broken in 5.7.2 (Github Release branch)

Epic 开发者论坛发布:2026-01 至 2026-04适用版本:UE 5.7(5.7.2 GitHub release 分支)
图形渲染HLOD渲染

Landscape 材质使用 RVT 时,烘焙 HLOD 得到全黑或灰色贴图,原因是临时 BuildHLODWorld 没复制源世界的 RVT Volume。含复现步骤、根因和 Epic 工程师回复。

值得试的点

  • Nanite+SRVT 的项目可参考帖中配置,不再对 Landscape 做纹理烘焙
  • 能改引擎源码可在 UWorldPartitionHLODSourceActorsFromCell::LoadSourceActors 把源世界的 ARuntimeVirtualTextureVolume 加入 Actor 列表
  • 出现黑色锯齿边可尝试烘焙 Landscape 材质时临时关闭 Nanite
  • 命令行构建 HLOD 别漏 -AllowCommandletRendering

图形渲染移动端渲染
